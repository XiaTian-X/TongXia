# 第三轮真实运行报告

**主题:文档与代码的关系。** 两个工作项(W6 取消行号坐标、W4 把路径归属的
两个缺口摆出来),16 次交接,3 次打回,301 条全绿收尾。

和前两轮一样,`dev` 由本次会话扮演,`tester` 是另一个会话。
两边共用一个工作目录,靠 `PAIR_ROLE=` 区分,执行器是钉住的 `.pair/enforcer.py`。

---

## 一句话:这一轮抓到的问题，主要形状是「绿得没有意义」

3 次打回里,**只有 1 次是红绿发现的**,另外 2 次抓的都是**通过了、但通过得
没有意义**的用例:

| 打回 | 怎么发现的 |
|---|---|
| W6 ①:区间用例声称守「取起始行」却守不住 | 变异(把封闭符号改成取结束行,10 条全绿) |
| W6 ②:直接跑测试文件时新增 10 条一条没跑 | 直接跑一次那个文件(`Ran 12 tests OK`) |
| W4 ①②③:三条红 | **红绿** |
| W4 ④:剩余数断言恒真 | 变异(整段删掉那条实现,301 条全绿) |

前两轮的结论是"两次打回都不是红绿发现的"。这一轮红绿终于抓到了一次
(W4 的三条红),但**比例仍然是少数**,而且那一次抓到的三条里有两条是
用例与脚手架耦合、一条是计数方式错 —— 都不是实现的缺陷。

**红绿在这个项目里的实际角色越来越清楚:它是回合调度的信号,不是发现问题的
手段。** 发现问题的是"把实现改坏,看有没有测试会红"。

---

## 同一个失效形状出现了三次：取样范围比被断言的性质大

这是本轮最值得记的一条,因为三次的表面完全不同:

1. **W6 的区间用例**用 `pair.py:2375-2382@4498de8` 当输入,而 2375 和 2382
   **落在同一个符号里** —— 断言说"应按起始行给建议",可这对数字分不出
   起始还是结束。取样(一个区间)比性质(起止必须跨符号)小。
2. **W4 的剩余数断言**写成 `assertIn("2", r.text)`,而输出表头是
   "12 个孤儿",含 `2`。取样(整份输出)比性质(剩余那一行)大。
3. **同一条的上一版**写的是 `assertIn("5", ...)`,总数 15 含 5 ——
   **一模一样的恒真,换了个数字之后仍然在。我第一次异议时没看出来。**

第 3 条尤其值得记:我在同一条用例上做了两次审查,第一次只报了"计数方式
错"(7 != 10),没发现旁边那句是恒真的。**报出一个真问题会让人以为自己已经
看过这一段了。**

根因是同一个:总数与剩余数天然共用数字(12/2、15/5),而表头按契约必须含
总数 —— 任何"在整份输出里找那个数字"的写法都必然被表头满足。
最终改法是**结构定位**:框出孤儿块 → 排除含总数的表头 → 排除被列出的路径,
剩下的只可能是那一行。它不钉措辞,所以不会把契约没写的东西变成断言。

## W6 刚取消完坐标，自己的用例里留着最后一处 —— 下一个回合就漂了

W6 把全仓 26 处 `文件.py:行号` 迁成 `` `<路径>#<符号>` ``,理由写在契约里:
"行号是硬编码的坐标,被引文件上方插一行,下面每一处就都指向别处"。

**而 W6 自己的用例里留着一处硬编码坐标**,指向 `pair.py` —— dev 的文件。
W4 的实现往 `pair.py` 里加了 `is_orphan` 与两段清单之后:

```
cmd_init.put   2375-2382  ->  2431-2438     位移 56 行
2375           cmd_init.put  ->  merge_entry  完全是另一个函数
```

**W6 完成后的第一个 dev 回合就把它撞红了。**

这不是巧合能解释的:W6 的检查**只扫文档,扫不到测试代码**,所以仓库里
"最后一处会漂的坐标"必然落在检查够不着的地方。最终改法是在用例里用 `ast`
现算坐标,而不是写死。

**教训不是"测试也要被扫",是:一条规则如果只在一半领地上生效,
剩下的那一半会精确地收集所有违例。**

> 写这份报告时又被它抓了一次:上面那处 `pair.py:2375-2382@4498de8`,
> 第一版我按当时的记忆直接写了裸行号,`test_规范文档里没有行号形式的引用`
> 立刻红,并指出它现在落在 `merge_entry`。补上 `@<sha>` 之后才绿 ——
> 这正是历史快照豁免要覆盖的场景,而**判断"这是历史还是现状"的那一步
> 仍然是人做的**,检查只负责逼你做这个判断。

## 开工前的契约审查，这一轮第一次拿到可量化的收益

两个 agent 各自独立交出结论,**九处歧义,两处独立撞上**。人类授权由 dev 代笔
定稿,九处一次性写进契约。

其中**两处按字面实现会产出"通过全部现有测试、但功能是空的"东西**:

- **行内代码豁免**(两边独立发现):契约原文写"代码块与行内代码里的示例不算
  引用",而规定的引用形式 `` `<路径>#<符号>` `` **本身就是行内代码** ——
  照字面实现,整条检查恒真。实测 29 处引用里 **27 处在行内反引号内**。
- **记忆层必然是孤儿**(dev 发现):按原判据实算,当前仓库 4 个孤儿**全部**是
  记忆层,而记忆层被排除在角色/冻结/共享之外**是 `verify-setup` 自己强制的**
  —— 这条警告没有任何一种消除方式。一个结构上不可能清零的警告,
  几次之后就没人看了。

**两处都会通过所有测试、也不会被任何评审的红绿抓到**,要到很多回合之后
才看得出来。这是这道门禁三轮以来第一次给出这种量级的回报。

同时也暴露了它的形状问题:两个角色的开工前结论写**同一个文件名**,
dev 的 `verify-setup` 在后台跑的两分钟里 tester 提交了自己的结论,
dev 没看见就整份覆盖了。已从 git 逐字节还原,没有内容丢失 —— 但那是运气。

## 净回合:16 次交接里有 2 次是空转的 impl

上一轮登记的 P1-8 要求把"推进交付的回合"和"协议开销的回合"分开数。手工算:

| | W6 | W4 |
|---|---|---|
| 交接 | 8 | 8 |
| 其中空转的 impl 回合 | 1 | 1 |

两次都是同一个形状:**打回只动了测试,修完之后实现无事可做**,但协议仍然
要求 dev 走一个完整的 impl 回合才能进评审。两次的提交信息都写着
"本回合无实现改动"。

这让 P1-6(空转的 impl 回合)的样本累计到 **7 个**,分布在三轮里。
它已经不是"再出现两次再说"的阶段了。

**一个反面样本值得记:** W6 的那次空转,最后并不空 —— 迁移把两处文档写陈旧
了(P1-12 的验收有三项没做、定位重框那节提到一条已被移除的绊线),
而那两处在 dev 路径。所以"打回只动测试 ⇒ impl 必然空转"这个推论是错的,
真正的判据只能是"这一回合有没有东西要写"。

## 边界摩擦:5 次，只有 1 次是旧类型

前两轮四次卡顿全部出自"孤儿路径"。这一轮开工前人类把 33 个孤儿划归完毕、
把变异缓存放进 `ignore_paths`,于是:

| 摩擦 | 是不是旧类型 |
|---|---|
| dev 跑全量变异检查刷新缓存指纹 | **不再发生**(已进 `ignore_paths`) |
| 变异点锚在 `if violations:` 紧跟 `lines =`,dev 插一行就失配 | 新 |
| 五步纪律第 3 步(补变异点)落在 tester 路径,dev 提不了 | 新 |
| `handoff` 的异议文件只认一个固定名,第二次异议没处放 | 新 |
| `verify-setup` 的结论文件不分角色,dev 覆盖了 tester 的 | 新 |
| `verify-setup` 在工作区干净时必然 `exit 1`(空提交) | 新 |

**旧根因修掉了,新的四条全是同一个更深的形状:每份产物一个全局固定名、
每条纪律假定只有一个人。** 它们在单人维护时都不是问题。

变异点那次我自己让开了(把孤儿的计算排到 `lines` 之后,并在代码里留注释
说明为什么它不在"正确"位置),没有烧一次往返 —— 但那是运气,
锚点恰好只约束两行的相邻关系。

## 这一轮登记的开放条目

- **12** `verify-setup` 在工作区干净时必然失败(无条件 `git commit`,
  但只 `add` 状态文件与审查结论)。契约一改两边都要重跑校验,先重跑的必撞。
- **13** 开工前校验的报告路径对两个角色是同一个文件名。
- **14** 省掉文件名的裸 `:行号` 坐标不在符号检查的覆盖范围内 ——
  实测 **66 处**,而且旧绊线移除后这部分防护是**净减少**的。
- **15** **「新增一条防护」的五步纪律,没有任何一个角色能独立执行。**
  dev 做 1/4/5,tester 做 2/3,而文档通篇写的是"你"。第 3 步尤其:
  文档自己写着"没补变异点的防护等于没有保障",而写防护的那个人
  改不了那个文件。

第 15 条是本轮最大的一条,因为它不是配置问题 ——
**是一份单人维护时代写下的纪律,切成两个角色之后没人重读过。**

## 三轮下来仍然欠着的

**一次两边都独立的运行。**

这一轮 `dev` 由本会话扮演,而本会话起草了第三轮的 PLAN 与契约、
也在人类授权下代笔定稿了那九处。第一轮作废的理由这一轮同样成立。

"两个都没参与设计的 agent 会以什么频率互相打回" —— **三轮下来零样本**,
仍然是这个项目最大的未知。

值得注意的是,这一轮出现了**两次独立撞上同一个结论**(开工前审查里的
行内代码豁免与 `improvements.md` 口径)。那是三轮以来最接近"独立复现"的
证据,但它发生在**开工前**,不是在结对回合里 —— 两份结论是各自写完才互相
看见的。这恰恰说明:**真正的独立性发生在双方看不见对方草稿的时候。**
