## 打回理由:检查窗口比它要守的那段话短

`tests/conformance/test_docs_consistency.py:572` 写着 `HEAD_LINES = 3`,
注释是"只看开头几行:那句话就在标题里"。**在你写这条的时候那是对的** ——
当时 `PLAN.md` 的假话在第 1 行、`CONTRACT.md` 的在第 1 行。

**是我这一回合把导语写长了。** 实算现在的形状:

```
docs/pair-run/PLAN.md        标题 + 前导引用块 = 7 行   (窗口 3 行)
docs/pair-run/CONTRACT.md    标题 + 前导引用块 = 18 行  (窗口 3 行)
```

契约那 18 行里有 **15 行不在检查范围内**。而那 15 行正是我刚写进去的
"两个角色都可以落笔""不要求对方签字"那一段 —— **最可能长出新错话的地方,
恰好在窗口外面。**

实测:把「除此之外 agent 只读」加到 `PLAN.md` 第 5 行(同一个引用块里),
两条断言**一条都不红**。

## 改法:窗口按结构取,不要按行数

**别扩大成整份文件** —— 我查过,「只读」在这两份文件里合法地出现 6 次:

```
docs/pair-run/PLAN.md:194,195,209,210   引用旧标题(W9/W11 的验收标准)
docs/pair-run/CONTRACT.md:491,492       引用旧标题(W9 那一节的背景)
```

那些是**历史引文**,改掉它们等于篡改记录 —— 和 W6 的 `@<sha>` 豁免是同一个
道理。所以窗口必须有界。

**建议:窗口 = 标题行 + 紧随其后的前导引用块**(从第 2 行起,吃掉所有空行与
以 `>` 开头的行,遇到第一行既不空也不是 `>` 就停)。这样:

- 不管导语写多长都覆盖得住 —— **窗口跟着那段话走,不跟着一个常数走**
- 到正文就停,历史引文不受影响
- 顺带把 `HEAD_LINES = 3` 这个常数消掉:那是"写的时候恰好够用"的数字,
  而这一轮反复在治的正是这一类(枚举、写死的计数、旧设计下的验收标准)

**判据只有一条:把「只读」放进前导引用块的任意一行,那条要红。**
怎么实现你定。
