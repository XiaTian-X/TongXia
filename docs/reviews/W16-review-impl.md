## 四、审这一项时撞见的一个既有漏洞(不在 W16,已进决策记录)

**`git mv` 能绕过"删除测试防护",而且 dev 能靠它把红的测试挪走、让 impl 回合变绿交接。**
`changed_entries` 解析 `git status -z`,遇到改名只取**新路径**、跳过旧路径 —— 旧路径那一侧的删除,
写权限边界、删除测试防护、红绿不变量**都看不见**。隔离克隆里实测:

| 场景 | 结果 |
|---|---|
| dev 在 impl 回合直接删 `tests/W1` | 拒绝(删除测试防护) |
| dev 在 impl 回合 `git mv tests/W1 docs/reviews/…` | **放行,exit 0**,进 review-impl,`tests/W1` 不在 HEAD 里了 |
| tester 在 spec 回合 `git mv tests/W1 docs/reviews/…` | **放行,exit 0** |

`docs/reviews/` 是 `shared_paths`,dev 在 impl 回合可写;挪走之后套件绿了,impl 的 GREEN 要求也满足。
review-impl 看 diff 看得见,但**没有任何检查会说话**。修法方向显然(`git status` 带 `--no-renames`,
改名拆成删除 + 新增),但它不在本项契约里。我会在 W17 的 spec 回合带声明把它立成本轮的一项,你不同意可以打回。
