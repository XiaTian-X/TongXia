# W78 review-test —— 用例改名的声明(`handoff --renamed 旧=新`)

**裁决:打回(changes)。** 只有一处缺口,但它在这一项最要紧的那条性质上:对上了一条改名,别的不再跑的用例是不是照旧算消失。

## 问题

**`tests/conformance/test_v1_test_rename.py:243`(`TestCompletion`)—— 没有"一条对上、另一条照旧消失"的用例。**

- 现有完成类用例里,不再跑的始终只有 `suite.B` 一条:
  - 对上了 → 完成;
  - 对不上(没跑 / 跳过)→ 拒绝。
- 没有一条同时有两条不再跑、只声明了其中一条的情形。
- 探针:把 `matched_renames()` 的返回改成"只要有一条对上就整批清空":
  ```
  return ([] if pairs else list(gone)), pairs
  ```
  在 `.pair/scratch/` 的副本里跑 `test_v1_test_rename`、`test_v1_full_vanished`、`test_v1_rebound_shortcut`,**41 条全绿**。
- 这正是契约「用例改名的声明」和 W61 要防的形状:"一句话带过一大批消失"。规划里也写明"对上了的不算,别的照旧按消失算"。
- ⑱ 与完成时共用这一个函数,所以一条完成时的用例就能钉住两处。

**建议补法(怎么写由你定):**

- 在 `TestCompletion` 里补一条:
  - 声明 B → C,完成时 `suite(A="gone", B="gone", C="green")`;
  - 断言完成被拒、列出 `suite.A`;
  - 最好也断言拒绝文案里不再列 `suite.B`(它已经对上了)。
- 再登记一个变异点,用上面那个探针就行。
- 这次打回只动测试,修正回合按 W17 走捷径回 review-test,不经过 impl。

## 查过、没问题的地方

- **不是变更探测器**:
  - `pairs()` 把 `renamed_tests` 统一成集合,状态存成映射还是对子列表都不影响;
  - 正文两种行是契约原文;
  - 其余只看阶段、提交数、`state.json` 逐字节、全量提交的跑过集合。
- **拒绝类拒得是不是本节**(多数只断言"被拒 + 什么都没变",关键是有没有别的防护替它挡):
  - 格式、一对一、旧名不在基线:都在 spec 回合、`tests/W1` 是红的,不带声明的 spec 交接本身能过(`TestDeclare` 就是对照)。差别只有旗标。
  - 不带 `--test-gap` 的 review-impl:往只追加登记表加一行,让"必须改 tester 路径"让开,并带了不声明照常通过的对照组。和变异 `改名_review_impl_不要求_test_gap` 对得上。
  - 没改 tester 路径:失败用例由人类先提交,本回合只写笔记,带对照组。
  - 讨论回合:dev 在 discuss 带声明。
- **与状态合并后的一对一**:spec 记 B→C,review-impl 再给 A→C 被拒,钉住"在合并后的映射上判"。
- **基线读不出不判**:单独一条对照组。
- **⑱**:修正回合补声明走捷径,对照组不声明进 impl。钉住"内存状态要先更新,⑱ 才看得到本回合的声明"。
- **生命周期**:完成清空在 `TestCompletion`;认领清空用人类提交的旧状态造,因为正常流程里完成就清空了。
- **变异点**:17 个 `改名_` 全抓。两个判为等价的不登记,我同意:
  - 不限 tester:被阶段那道和"改 tester 路径 + 越界"合起来挡住;
  - 格式不查两边相同:被不许链挡住。

## 没覆盖到的(不为它们打回)

- 同一对改名跨两回合重复声明:实现当作已有、不拒,契约没说。
- 分两回合声明时,第二回合正文只写本回合的那条:没断言,影响只在正文。
- 报告读不出(`full_executed` 为 None)时完成那一步不扣除:偏保守,没有用例。
