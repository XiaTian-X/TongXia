# W76 review-test —— 决策条目不能同名

**裁决:通过(approve)。**

## 查过的地方

- **拒绝类用例拒的是不是本节**:重复的那条只换理由、格式合格,所以格式与长度校验不会替本节拒。逐条推了去掉判重之后的结果:
  - 正常交接两条(与 HEAD 同名、同回合两条同名)会放行,而且断言了文案里的重复标题 —— 区分"哪一道拒的";
  - `discuss` 开场、讨论回合 `handoff`:去掉判重后条目合格、讨论入口允许写决策,会放行;
  - `resume` 那条是开放条目 57 的原样:引用 `OLD_REF` 在 HEAD 里正好一条,算"已被推翻"时跳过自己,`推翻:` 校验放行 —— 只有判重能拒它。
- **对照组**守住了"误拒"一侧:ID 同标题不同(抓「只比 ID」)、标题同 ID 不同(抓「只比标题」)、HEAD 已有两条同名时追加不同名(不追溯)、改一个字的推翻者(W71 原行为不变)。
- **复用 `OverturnBase`**:种子、讨论流程与 W71 同一套,没有复制夹具;被拒时断言提交数与 `state.json`,`discuss` 开场那条因提案留在工作区只断言提交数与阶段,和 W71 同一写法。
- **变异点**:`--only 同名_` 5 个全抓。「只比 ID」的缓存抓手是 W71 的用例,W76 的对照组同样会抓(推演过:`W1 — 缓存按租户分键之后还要带上版本号` 与 HEAD 的 `W1` 撞 ID 被误拒)。

## 没覆盖到的

- 判重先于 `推翻:` 校验的先后:同名推翻者两道都拒,外部观察不到,契约只要求被拒。
- 近似标题(全角半角、标点)按契约不做。
