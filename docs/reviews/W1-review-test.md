## 问题:上一次打回修掉的缺陷,没有任何测试守着

`pair.py:947`

```python
item = "%s [%s]" % (item, state["item_type"] or "feature")
```

那个 ` or "feature"` 是上一轮 `review-impl` 打回换来的。**把它去掉,
230 个测试全绿。**

### 复现

把 947 行改回打回前的写法:

```python
item = "%s [%s]" % (item, state["item_type"]) if state["item_type"] else item
```

然后 `python3 tests/conformance/run.py` → 230 个测试 / 全绿。
`test_v1_brief.py` 六条也全过。

### 为什么这一条必须在 W1 里补,不能留到 W2

你在 review-impl 的记录里写了"修完之后我会在下一个 spec 回合补一条用例把它
钉住 —— 现在补不了,评审回合只读"。**"评审回合只读"是对的,但结论下错了:**
补测试的正确时机不是下一个工作项的 spec,而是**把这一项打回到 spec**。

理由是这个项目自己的信条:**一个恒真的测试集比没有测试更危险。**
如果 W1 就这么完成,历史上会留下一条"发现缺陷 → 打回 → 修复 → 通过"的
完整记录,而那个缺陷此刻是完全不设防的。谁下次动 `render_brief` 都可能
把它带回来,而红绿一声不吭。

### 建议的用例形状

需要一个 `item` 有值、`item_type` 为空的状态。`load_state` 会用
`DEFAULT_STATE` 补齐缺失的键,所以直接写一份没有 `item_type` 的
`state.json` 就能造出来(这也正好是你在评审里给的那条 v0 迁移复现路径)。
断言 `- 工作项: W1 [feature]`。

怎么造是你的事,我只要求:**把 947 行改回去,得有测试变红。**

## 我具体查过、认为没问题的

- **没有过拟合。** 六条断言的全是契约逐行规定表里的东西(第 1 行标题、
  第 2 行空行、四个字段的形态与取值、末尾换行)。没有一条断言了私有方法名、
  内部调用次数或中间变量。契约把格式钉到字节级,所以按行断言是**照契约写**,
  不是变更探测器 —— 我重构 `render_brief` 的内部写法时它们不该红,
  改输出格式时它们必须红,现在正是这样。
- **反例覆盖是这一轮最值钱的部分。** 角色配 dev、测试配 RED、工作项配 `(无)`、
  阶段配 idle —— 四个会变的字段各有一条能打死常量实现的用例。我如果返回一份
  写死的头部,至少四条会红。这一点我实测过。
- **`test_工作项全部完成时仍然写`** 覆盖的是契约点名的易漏分支,而且它测的是
  `plan_all_done` 提前 return 那条路径,不是重复第一条。
- **`test_写过简报之后交接不被拒`** 红的原因和其余五条不同(边界豁免,
  不是文件缺失),这条切得准。而且一致性测试的临时仓库**没有**忽略
  `.pair/.last-brief.md`,所以它真实地在测 `PROTOCOL_LOGS` 那条豁免,
  没有被本仓库 `.gitignore` 的改动掩盖 —— 这一点我特地验过。
- **`_lines()` 里的 `endswith("\n")`** 每条都跑,末尾换行不会漏。

## 我没覆盖到的（不是打回理由）

- `review-impl` / `review-test` 两个阶段的字段取值仍然没有单独用例。
  你在两轮记录里都提了这条,我同意它不紧急:阶段字段直接取 `state["phase"]`,
  不存在按取值分支的实现。
- `工作项` 字段没测 bug / cover / refactor 三种类型的形态。同上,
  补完 `item_type` 为空那条之后,类型字段就只剩"原样带出"一种行为了。
