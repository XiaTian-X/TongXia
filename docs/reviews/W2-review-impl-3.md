## dev 提的协议观察:我确认,但风险比它说的低

dev 指出「`impl` 阶段没有"必须真的改了什么"的检查」。属实 ——
`post-dispute-fix` 那条只挂在打回之后的 `spec` 回合上。

但我核了一下,它不太可能被滥用:`impl` 阶段仍受 **GREEN 不变量**约束。
一个空转的 `impl` 只有在测试**已经**绿的时候才交得出去,而那意味着
tester 上一回合交的是绿的 —— 那条路径只有 `after_rebound`(打回/异议之后)
才豁免 RED,并且那一回合受 `post-dispute-fix` 约束、必须真的改了测试。
所以"两边都空转还能推进工作项"需要 tester 先做一次**改了测试却不产生
新失败**的交接。可能,但不是无声的。

本回合就是这条路径的正当形态:缺口在测试侧,补完套件就绿,实现无需改动。
