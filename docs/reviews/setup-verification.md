# 契约审查结论（dev）

逐节读了 `docs/pair-run/CONTRACT.md`,并对着 `.pair/enforcer.py` 里
`cmd_status` / `memory_brief` 的现状核过每一条。**不是无歧义** ——
下面三条,每一条我都能给出两种合理解读,而它们会导出两份不同的实现。

---

## 简报的记忆段落

**这一节有两条真歧义。**

### ① PLAN 全部完成时,简报里到底有没有记忆段落

这一节说记忆段落与终端注入的内容**逐字一致**,又在「不做」里要求
**不为简报单独计算**、两处必须来自同一次取值。

但 `cmd_status` 的实际控制流是(`.pair/enforcer.py:1071-1096`):

```
1071  write_brief(...)              ← 简报在这里写
1073  if plan_all_done(...): ...
1077      return 0                  ← PLAN 全完成,提前 return
1096  mem = memory_brief(...)       ← 终端的记忆注入在这里,走不到
```

**PLAN 全部完成时,终端根本不打印记忆段落。** 于是:

- 解读 A:「逐字一致」优先 → 终端是空的,简报也没有记忆段落
- 解读 B:「轮到自己就写完整简报」优先 → 简报要算一次记忆并写进去

两种都说得通,而且它们**互相排斥**:解读 B 要求把 `memory_brief` 的调用提到
`write_brief` 之前,可那样一来 PLAN 全完成时简报里有、终端里没有,
又直接违反「逐字一致」和「同一次取值」。

**这不是可以合理推断的那种模糊。** 上一轮已落地的
`test_工作项全部完成时仍然写` 只断言了头部四行,没有约束记忆段落 ——
所以 tester 按任一解读写断言都不违反现有测试,而我按另一种实现就会被打回。

**我的提议:取解读 A。** 理由是「同一次取值」那条「不做」写得最硬,而且它给出了
理由(可对质)。建议在这一节补一句:「`status` 提前结束、终端没有打印记忆注入时,
简报同样没有记忆段落。」

### ② 「没有记忆内容」的判据是什么

这一节说「没有记忆内容时,记忆段落连同它前面那个空行一起省略」,
示例给的是 idle 的情形。

但按现状,`memory_brief` 在**有工作项、没写笔记**时返回的不是空串,而是:

```
--- 本工作项还没有笔记 (docs/pair-run/notes/W2.md) ---
发现了什么就随手写进去:试过什么没成、否掉了什么、哪里拿不准。
对方看不到你的推导过程,不写下来就是重新推一遍。
```

于是:

- 解读 A:「没有记忆内容」= `memory_brief` 返回空串 → 上面那段**算内容**,
  要写进简报
- 解读 B:「没有记忆内容」= 没有笔记也没有相干决策 → 上面那段是**提示不是内容**,
  段落该省略

契约只描述可观测行为,**tester 无从知道那段提示存在**,它读到「没写笔记」
自然会按解读 B 写断言;而我按解读 A 实现。这是两边各自都"对"、合起来是废的
标准形状。

**我的提议:取解读 A**,并在契约里点名那段提示也算记忆内容 ——
它确实是 agent 读到的东西,而这一节的目的就是复现"agent 实际读到了什么"。

## 简报的降级与忽略

### ③ 「任何情况下都不许失败」和「只兜 OSError」自相矛盾

这一节开头写:

> 它是可观测性,不是门禁。**任何情况下都不许让 `status` 失败。**

「边界」里又写:

> 只兜 `OSError`……**其他异常不在这一节的承诺范围内。**

两句直接冲突。`Path.write_text` 抛得出 `OSError` 之外的东西
(编码问题会是 `UnicodeEncodeError`,它是 `ValueError` 的子类,不是 `OSError`)。
按开头那句该兜住,按「边界」那句该崩。

- 解读 A:兜所有异常,「只兜 OSError」是在举例
- 解读 B:只兜 `OSError`,开头那句是修辞

tester 完全可能写一条"注入非 `OSError` 异常,断言 `status` 仍然 0"的用例,
而我按解读 B 实现就会红 —— 而且我会认为它断言了契约没写的东西。

**我的提议:取解读 B(只兜 `OSError`),并把开头那句改成「不许因为写简报失败
而让 `status` 失败」。** 理由:宽泛地 `except Exception` 会把实现里的真 bug
一起吞掉,而那与"可对质"的目的相反。

### 逐条核过、认为不含糊的部分

- 警告是「恰好一行、以 `[简报]` 开头」,**位置没规定** —— 我理解为 tester
  不得断言它出现在第几行,这是刻意的,不是遗漏
- 「其余输出逐字节与成功时一致」清楚:除了多那一行,其他一个字符都不能变
- `init` 之后 `.gitignore` 含该行、且重复跑不重复追加:清楚,且与现状
  (`GITIGNORE_LINES` 的子串判重)一致
- 「存量项目的 `.gitignore` 不在此列」清楚地划走了本仓库自己

## 结论

**三条都需要人类定稿之后我才能开工。** ①②在同一节里、互相独立;③在另一节。
三条我都给了提议,人类若同意,直接改契约即可;若不同意,请给出取哪一种解读。

我起草过这份契约(已用 `--drafter self` 声明),所以这份结论的证明力打折 ——

也把契约通读一遍,发现别的歧义就走契约变更流程。
