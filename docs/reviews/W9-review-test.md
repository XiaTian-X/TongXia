## 打回理由:`test_report_那一行跟着事实变` 放行恒为 0 的实现

变异:把 `contract_changes` 的自增改成永不发生。**12 条一条不红。**

根因是分母:

```
正确实现 : 第一轮 '0% (0/1)'   第二轮 '50% (1/2)'
恒为 0   : 第一轮 '0% (0/1)'   第二轮 '0% (0/2)'   <- 分母仍然在变
```

`_fmt_rate` 的分母是**完成项数**,而这条用例本来就要跑两个工作项 ——
**第二个工作项本身就让那一行变了**,和契约有没有变过无关。

**一个额外的诊断,能确认根因就是分母:** 我另外变异了一次,把那一行从
`_fmt_rate(...)` 换成 `"%d 次" % contract_changes`(绝对次数,没有分母)——
12 条仍然全绿(那是合法的另一种实现,契约没规定格式)。但**在那个形状下,
恒为 0 的实现会红**:`0 次` → `0 次`,两轮一模一样。
**所以漏洞不在你的思路,在分母替分子把"变化"演了。**

**改法我不指定**,你怎么写都行,判据只有一条:**把自增改成永不发生,
那条要红。** 两个方向供参考 —— 取那一行里的分子来比,或者断言第二轮
那一行含 `1/`、第一轮不含。别断言措辞,也别钉 `_fmt_rate` 的格式。

## 逐条核过、认为没问题的

- **变异实测 5 打死 1 存活**:豁免整次交接(2 条红)、豁免任何冻结路径
  (`test_旗标不能豁免其他冻结路径` 红)、不校验声明真实性、不要求当场留决策、
  声明不进提交正文 —— 五个各红对应那条,没有误伤。
- **`TestExemptionSkipsAllThreeGates` 的类级 `config = {"scope": [...]}`**
  是这一组的关键:你笔记里记的那个坑(在用例里替换 `'"scope": []'`,
  而 harness 的 `CONFIG` 根本没有这个键,替换是空操作)——
  **那一道判定此前从没被触发过**,是变异把它挖出来的。这条经验比用例本身值钱。
- **`test_带声明但没留决策被拒` 的关键词用中文「决策」**,不用 `"DECISIONS"`
  —— 因为 argparse 的 `unrecognized arguments` 会回显那个路径。
  这是你第二次栽在同一处并把它变成习惯,写在 docstring 里了。
- **`FrozenBase.setUp` 先铺 `docs/DECISIONS.md`**:不铺的话
  `--contract-change docs/DECISIONS.md` 会在**路径真实性**那一道就被拒,
  用例红得不对。你在注释里写明了第一版正是这样。
