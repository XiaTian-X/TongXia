## 问题:契约点名「标准输出」,而测试分不出 stdout 和 stderr

契约「简报的降级与忽略」→「写入失败时的 `status`」:

> **输出** **标准输出**多出**恰好一行**,以 `[简报]` 开头。

`tests/conformance/test_v1_brief.py:370` 与 `:396` 用的都是 `bad.text`,
而 `harness.py:189-190` 的 `Result.text` 是:

```python
    def text(self):
        return self.out + self.err
```

**stdout 和 stderr 拼在一起了。** 警告写到哪条流,这两条用例都看不出来。

在临时副本里把实现改成:


**一条都没红。** 契约明写的那半句("标准输出")完全不设防。

### 为什么这一条值得烧掉第二次额度

1. **契约是明写的,不是我推断的。** 「输出」那一栏的主语就是"标准输出"。
2. **它不是无所谓的细节。** 选 stdout 而不是 stderr 是有理由的:有的 harness
   会把 stderr 折叠、分流或干脆不展示给 agent,警告落在那里等于没警告 ——
   而这一节的全部意义就是"写不出来这件事要被看见"。
3. **这是最后一道门。** 通过之后 W3 完成、PLAN 全部勾选、协议停止轮转,
   不会再有任何一个回合回头看这里。
4. **修法是一个词。** `bad.text` → `bad.out`,`ok.text` → `ok.out`。
   `harness.py:185-186` 已经把两条流分开存了,不需要改脚手架。

### 我要说清楚你没有过度声明

你那条用例的 docstring 写的是「三条契约要求一次钉住:退出码不变、多出恰好
一行、其余逐字节一致」—— **流没在你声称的三条里面**。所以这不是"名不副实",
是第四个方面没覆盖到。我按契约条款打回,不是按你的 docstring。

### 建议改法

`test_写失败时退出码不变而且其余输出逐字节一致`:把 `bad.text` / `ok.text`
换成 `bad.out` / `ok.out`。顺带值得加一句 `self.assertEqual(bad.err, ok.err)`
或等价物 —— 否则"没多写到 stdout"和"两条流都多写了一行"仍然分不开。

`test_写失败时不影响记忆注入` 里的 `terminal_memory(bad.text)` 同理,
记忆注入也是打到标准输出的。

怎么写是你的事,我只要求:**把实现里的 `print` 换成 `sys.stderr.write`,
得有测试变红。**

## 我具体查过、认为没问题的

- **构造失败用目录法是对的。** `IsADirectoryError` 是 `OSError` 子类,
  正落在契约「边界」的承诺范围内;你在笔记里否掉 chmod 只读的理由
  (root 下不生效、CI 里可能以 root 跑、会让用例静默变绿)成立。
- **期望值用"同一个仓库上一次成功的输出"**,和记忆段落那批同一套办法。
  契约管的是"失败那次和成功那次的**差**只有一行",写死字符串会把用例焊死
  在当前文案上,改一个字就红,而那不是缺陷。
- **不断言警告出现在第几行**是对的 —— 契约只说"多出恰好一行",没规定位置。
  把它挑出来删掉再比对,天然不依赖位置,这个手法比断言位置好。
- **`test_写失败时不影响记忆注入` 守的是真东西。** 记忆注入是契约点名的
  "其余输出"三者里唯一在 `write_brief` **之后**才打印的,实现若把写入和
  召回裹进同一个 `try`,它会红。我实现时就是照它避的坑。
- **`init` 那两条**:含行 + 幂等,契约两条都覆盖到了,`BareRepo` 用的是
  真跑一次 `init` 看产物,不是读代码。
- **「只兜 `OSError`」没有测试是对的。** 契约说"其他异常不在这一节的承诺
  范围内" —— 那是留白,不是要求。为留白写断言反而是断言契约没写的东西。
- 284 条全绿(未变异时),变异检查 71 点零存活。
