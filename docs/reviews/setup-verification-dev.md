我只想了执行者这一次提交,没想下一回合。`tests/.DS_Store` 不提交、留在工作区,下一回合 dev 的 `changed_entries` 里照样有它,
它在 tester 的路径下 —— dev 的交接被写权限边界拒绝。本节「不做」用来否决"拒绝交接"的那条理由,在我自己的设计里原样成立,
我没看出来。判据只看 tester 那一次,正好看不见。同意修法:落在**任一角色路径下**的未跟踪系统文件,不进提交、也不算越界,
对执行者与对方一样;孤儿位置照旧按 W31 拒绝。在 W35 的 spec 回合带声明补,我照它实现。

### 逐节点名

- **操作系统文件的名单显式写出**(W34):判据能写断言 —— 内存里往 `GITIGNORE_LINES` 加 `.env`,它不进 `OS_FILES`。
  我实现时把三个名字写成一个具名元组放在 `GITIGNORE_LINES` 之前,列表末尾引用它;字面由 tester 在 spec 回合定死,我照写。
- **操作系统写的文件不随执行者的改动被提交**(W35):⑩ 之后的判据能写断言 —— tester 交接后 dev 在 impl 回合照常交接,
  `tests/.DS_Store` 仍未跟踪、两次都不进提交,两次输出都点名它。实现上"不算越界"与"不进提交"要用同一个判定
  (文件名在 `OS_FILES` 里、未跟踪、落在某个角色路径下),不各写一份。
