## 打回理由:A

契约「裁判副本的同步」要求 `DONE` 重钉时"把新 sha **写进提交正文**"。
拿掉 `.strip()` 之后正文变成两行(你在 review-impl 里贴过实际输出:
sha 行尾断开、右括号单独一行),而 **11 条一条都不红**。

`test_重钉的_sha_进提交正文` 断言的是 `sha[:7] in body` ——
整份正文里含 sha 的前 7 位就算过。一个断成两行、右括号掉下去的记录同样满足它。

**为什么这条值得一次往返:** 这一行是裁判被换掉之后唯一的纸面记录。
W10 存在的全部理由就是"副本悄悄变了而没人知道";记录写成什么样,
在这一项里不是风格问题。

**改法你自己已经写对了**(review-impl 的「未覆盖」一节):判据不是措辞,
是**结构** —— 正文里存在**一行**,同时含 `JUDGE_REL` 与**完整** sha。
按这个写,变异 A 立刻红,而且不碰措辞、不撞规则 4。

## 不要求你做的两条

### B:`if repinned:` 退回真值判断 —— 实际测不了

它只在 `git hash-object` 失败时才有区别,而那是本地 plumbing,
在脚手架里没有干净的注入点(用例跑的是子进程,把 git 弄坏会让整条链一起塌)。

**别为它造一个注入点。** 现状是:实现取不到 sha 也会留痕,这条不变量靠
代码里那段注释和这次评审记录守着 —— 弱,但强行造测试的代价更大。
记在这里,让它活过本工作项。

### D:`and green` 去掉之后 11 条全绿 —— 但它不是缺口

我一开始把它当成"契约写了『全绿就是证据』却没人守"。**核实之后收回。**

`FLOWS` 里 `feature`/`bug`/`cover` 的 `review-test` 期望都是 `GREEN`,
`refactor` 的 `review-impl` 同理;不绿就在红绿不变量那一步 `die`,
根本走不到 `target == "DONE"`。**`green` 在 DONE 处不可能为假** ——
那个 `and green` 是结构性冗余,不是无人看守的条款。

写下来是因为:这类"变异存活但不可达"的东西,不核实就报会变成一次假打回,
而假打回和点头一样失真。

## 逐条核过、认为没问题的

- **`test_副本当裁判时也要拦`** 是这一组里唯一能抓住 `__file__` 恒真实现的
  用例,而 `__file__` 正是本轮真实部署方式下的陷阱。你在笔记里说它是写完
  十条之后才补的 —— 没有它,W10 交付出去的东西在真实用法下是空的。
- **`test_只差一行注释也要拦` / `test_只差一个空白字符也要拦`** 专杀"比注册表"
  与"比 strip 后文本"两类实现。变异 C 证实第二条真的咬得住;第一条对应
  上一轮那次漂移(两边注册表差集为空而文件差 122 行)。
- **`test_重钉发生在_git_add_之前所以进了提交`** 断言的是"DONE 之后工作区
  干净"加"副本进了那次提交",两条合起来才封死"落在 add 之后"那种实现。
  这一条的现实分量比看上去大:`35136c4` 就是它描述的场景在**手工**路径上
  真的发生了一次。
- **`test_副本不存在时放行` 与 `test_DONE_不会凭空造出副本`** 是同一条契约
  ("副本不存在时两条都不触发")的两端,缺任一端都会漏掉一半。
- **`config` 里把 `.agents` 从 `frozen_paths` 挪进 dev 的角色**是对的:
  这一组的前提就是"工作项进行中 pair.py 会变",不挪 `run_to_done` 走不到 DONE。
