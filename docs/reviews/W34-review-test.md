## 我检查了什么

隔离克隆(`.pair/scratch/w34`,用完删掉)里只跑 `test_v1_os_files_list`,每次只改 `pair.py` 一处:

| 注入 | 红 |
|---|---|
| `OS_FILES` 退回按形状筛(你登记的变异,impl 回合探过) | `test_往_GITIGNORE_LINES_加一个裸文件名_它不算系统文件` |
| `GITIGNORE_LINES` 把三个名字各抄一份,不引用 `OS_FILES` | `test_名单是一处写_GITIGNORE_LINES_引用它` |
| 干净 | 无 |

- **两个方向各一条**:一条守"不靠形状猜"(契约的行为),一条守"一处写、另一处引用"(PLAN ③ 的同源)。
  第二条是我原先没想到的形状 —— 名单显式了、却在 `GITIGNORE_LINES` 里再抄一份,今天行为照样对,下一次只改一处就漂开。
- **模拟编辑自带前提断言**:每次改写之后先断言编辑生效(`.env` 进了 `GITIGNORE_LINES`、`ehthumbs.db` 进了 `OS_FILES`),
  `load()` 在插入点不唯一或不见了时直接报错 —— 字面一变,用例会响亮地坏,不会静默变绿。
- `exec` 进一个新模块对象,不污染已导入的 `pair` 模块,别的用例不受影响。
- 判据看的是模块里两个名字的值(行为),不是源码长什么样;插入点是契约定死的字面,不算变更探测器。
- **决策**:`docs/pair-run/DECISIONS.md` 已有 `## W34`。
