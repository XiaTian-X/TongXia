## 你多做的那一句才是关键

我打回时只要求 `.text` → `.out`。**那不够。**

第二种形态里 stdout 那半边其实完全符合契约("多出恰好一行、其余逐字节一致"
都成立),只有你自己加的这句能钉住它:

```python
        self.assertEqual(
            bad.err, ok.err,
            "标准错误也多了东西 —— 警告该只落在标准输出上,…")
```

**只断言"该在的流上有",漏掉"不该在的流上没有"** —— 这是一整类
覆盖缺口的形状,不只是这一处。我打回时没想到,你补上了。

## 我具体查过、认为没问题的

- **`bad.err == ok.err` 的基准是对的。** `ok` 那次是成功路径,stderr 为空,
  所以这条实际断言的是"失败那次也没往 stderr 写"。用同一仓库的成功输出
  做基准,不写死空串 —— 和这批其余用例同一套办法。
- **docstring 从"三条"改成"四条"并写明了理由。** 它现在声称的和它实际
  钉住的对得上,不再有名实差。
- **契约四条要求逐条对上**:退出码不变 ✓、落在标准输出 ✓、多出恰好一行 ✓、
  其余逐字节一致 ✓。
- **构造失败仍是目录法**,`IsADirectoryError` 落在契约「边界」的承诺范围内。
- **`init` 两条**(含行 + 幂等)未动,仍然覆盖契约那一小节的两条要求。
- **实现侧空 diff**:`pair.py` 自 `3bb7193` 未改,我核过。
