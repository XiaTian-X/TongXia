## ① 不带 `--since` 时分母必须照读状态 —— 没有用例能分出来

`tests/conformance/test_v1_report_since.py:190` 的 `test_不带_since_时不出现起点` 只断言不出现起点 sha 与交接数。
变异 `per_done = finished if since else done` → `per_done = finished`,全套 0 红。
**不是等价变异**:测试仓库里状态的完成数与历史里推进到完成的交接数恒等,本仓库实测 **17 对 18**,
那个变异会让本仓库不带 `--since` 的 `--no-decision` / `--contract-change` 分母从 17 变 18 —— 契约写的是
"不带 `--since` 时照旧读状态、输出一个字不变"。
**候选**:造一份两数不等的历史(人类提交一份 `completed_items` 多一项的状态文件,或空提交造一次
`phase=review-test -> idle` 的交接),断言不带 `--since` 时两行分母是状态里的数。

## ② 两行"偏高"判定用区间分母 —— 你笔记"没钉的"第一条

`偏高判定照读状态` 变异 0 红。你当时说"需要构造分子 > 分母/2 的区间,拆开的实现不自然"。
现在实现里判定与比率共用 `per_done`,但只要有人把判定那一行写回 `done`,区间里完成 1 项、带 1 次生效声明时
比率是 `100% (1/1)` 而判定不报"偏高"(因为 `1 > 17/2` 不成立)。
**候选**:`test_no_decision_的分母是区间内的完成数` 那个场景里再断言 `--no-decision` 那一行含"偏高"。
场景现成,只加一句。

## ③ 旁支上的起点会静默统计差集 —— 契约缺口,要不要拒由你定

我在克隆里实测:从 `HEAD~3` 拉旁支、提交一次、拿它当起点 —— 它**不是 HEAD 的祖先**,`report` 退出 0、
报交接 3 次,表头印着那个起点,读的人以为是"它之后"。契约只写"解析不成提交时拒绝"。
**修法一行**(`git merge-base --is-ancestor <sha> HEAD` 不成立就拒),但那是新行为,要 spec 回合带声明补进契约再写用例。
你若判断不做,请在决策里写一句为什么;我已在命令参考里写了"注意"。
