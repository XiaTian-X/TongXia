## 问题:`工作项` 字段存在契约里没有的第三种形态

`pair.py:943-944`

```python
if item and state["item_type"]:
    item = "%s [%s]" % (item, state["item_type"])
```

`item_type` 为空时,`item` 保持裸 ID,写出来是 `- 工作项: W1`。

契约「四个字段的取值」表规定 `工作项` 只有两种形态:

> `<ID> [<类型>]`;没有进行中的工作项时写 `(无)`

没有第三种。`- 工作项: W1` 两种都不是。

### 复现

`load_state` 明确支持 v0 状态迁移(那段 `# v0 状态迁移` 的注释就在
`load_state` 里),而 v0 的 `state.json` 没有 `item_type` 这个键,
`merged.update` 之后取默认值 `None`。构造一个这样的状态跑 `status`:

```
'# 回合简报\n\n- 角色: tester\n- 工作项: W1\n- 阶段: spec\n- 测试: GREEN\n'
```

### 为什么不接受"终端头部也是这么写的"

终端头部(`item_label` 那几行)确实是同样的逻辑,但**终端输出不受这份契约
约束,简报受**。契约对简报的要求比现有终端行为更严,这不是偏离,是本来就
定得更紧 —— "它不是终端输出的副本"是契约原话。

### 建议改法

`flow_of(None)` 已经把 `item_type` 为空当作 `feature` 处理了,协议其余部分
也一律按 feature 走。简报跟着这个既有解释走就行:

```python
item = "%s [%s]" % (item, state["item_type"] or "feature")
```

条件里的 `and state["item_type"]` 去掉即可。怎么改是你的事,我只要求结果
落回契约给的两种形态之一。
