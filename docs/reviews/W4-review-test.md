## 二、存活的 2 个(写进 `--uncovered`)

### ① `is_orphan` 不排除 `ignore_paths` —— 10 条全绿

把 `is_orphan` 里这一句去掉:

```python
    if matches_any(path, cfg["ignore_paths"]):
        return False
```

`test_v1_paths` 10 条**一条都不红**。而它产出的输出是自相矛盾的:

```
  [警告] 4 个孤儿:不属于任何角色,也不在共享/冻结/ignore_paths/记忆层里。
      build/缓存.json                      ← 说没人能写
  [警告] 1 个文件不受边界保护:命中 ignore_paths,任何角色、任何阶段都能写。
      build/缓存.json                      ← 说人人都能写
```

同一个文件同时出现在两段警告里,一段说"两个 agent 都写不了",另一段说
"任何角色任何阶段都能写";而且孤儿表头**自己写着**"也不在 ignore_paths 里",
下面却列着一个在 ignore_paths 里的文件。

`TestIgnorePathsListing` 只断言那个文件出现在"不受边界保护"那一段,
没有断言它**不在**孤儿清单里,所以抓不到。

**补法一行:** 在那条用例里加
`self.assertNotIn("build/缓存.json", 孤儿那一段)`,或者更简单 ——
断言 `build/缓存.json` 在整份输出里只出现一次。

### ② `ignore_paths` 清单的截断没有用例

契约「`ignore_paths` 的覆盖清单」写着"**同样超过 10 个只列前 10 行**,
并补一行还剩多少个(口径与上一节相同)"。把这一段的 `limit` 调成 10000
(等于不截断),10 条同样全绿 —— 用例只造了 1 个 `ignore_paths` 文件。

孤儿那一侧有 `TestOrphanTruncation` 专门守截断,`ignore_paths` 这一侧没有。
契约明说"同样的截断规则",两侧的覆盖却不对称。

## 三、为什么这两条我没有打回

**因为它们是"缺用例",不是"用例说谎",而第三次打回会撞死锁闸。**

我前两次打回的都是同一个种类:断言**声称**守着某条契约,实际守不住
(区间用例起止落在同一符号;剩余数断言被表头满足)。那种东西必须打回 ——
它比没有用例更坏,因为它让人以为那条契约已经有防护了。

这两条不是。现有的 10 条用例每一条都是真的,没有一条恒真;它们只是
没有覆盖到契约的这两句。契约也没有"每条条款都要有独立用例"的要求。

而 `DEADLOCK_LIMIT = 3`:第三次 `handoff changes` 会停转、要求把分歧交给
人类裁决。**这里没有分歧** —— 前两次打回你都受理了,改法也都对。
拿一个双方不会有争议的补充去触发死锁闸,是把这个闸用歪了:
它守的是"两个 agent 谈不拢",不是"还能再补两条用例"。

所以走 `--uncovered`,并且写进决策记录 —— 笔记随工作项作废,
`--uncovered` 只在提交正文里,而这两条值得活过 W4。

## 四、逐条读过、认为没问题的

- **`TestOrphanTruncation` 单独拆一个类**是对的:它需要"孤儿只有用例自己
  造的",而 `init` 铺的那 3 个入口文件会占掉截断名额。把它们划给 dev
  比在断言里做减法干净 —— 后者会让用例依赖一条契约没写的排序承诺。
- **剩余数那段用结构定位、不钉措辞**:框出孤儿块 → 排除含总数的表头 →
  排除被列出的路径。我把"还有 %d 个没列出"换成别的说法它照样绿,这是对的。
- **`test_记忆层不算孤儿` 的前提断言挑对了词。** 你笔记里记的那次教训
  (第一版用 `assertIn("AGENTS.md")` 当前提,而 `verify-setup` 本来就会
  提到它,前提恒真)—— 换成 `assertIn("孤儿")` 之后前提才真正成立。
  三条负向断言现在都有真前提。
- **`test_未被跟踪的文件不算孤儿`** 我没找到办法变异掉它:
  `tracked_files` 走的是 `git ls-files`,要让未跟踪文件进清单得换一个数据源,
  那已经不是"拆掉一条防护"而是重写。判据本身是对的。
- **副产物挪到 `build/缓存.json`** 避开了脚手架 `TEST_CMD` 那条
  "每个测试文件要有同名实现文件",干净。
