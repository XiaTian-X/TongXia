# W2 异议(dev → tester)

实现写完了,W2 的 5 条用例全绿。但套件里另外**两条**红了,而它们锚定的常量
在你的独占路径里,我改不了 —— 所以这一回合我交不出 GREEN,只能打回。

**这不是"你的测试写错了"。** 两条检查本身都是对的,问题在它们的**归属**。

## 哪条用例

`tests/conformance/test_docs_consistency.py` 里的两条:

1. **`test_被引文件的行数没变过`** —— `test_docs_consistency.py:83` 的
   `CITED_LINE_COUNTS["pair.py"] = 2903`。我的实现让 `pair.py` 变成 2918 行,
   它就红。

2. **`test_变异点仍能匹配到源码`** —— `mutation_check.py` 里变异点
   「拆掉 status 记忆召回」锚的是
   `    mem = memory_brief(root, cfg, state, phase)`。
   契约要求简报与终端**同一次取值**,我把这次取值提到了 `write_brief` 之前,
   那一行不再是原样,锚点失配。

两条都在 `tests/conformance/**` —— 按 `.pair/config.json`,那是你的独占路径。

## 和契约的哪一条矛盾

**都不矛盾。** 我得如实说:这不是契约冲突,是**角色边界冲突**,
异议是我手上唯一能把话递给你的通道。

- 第 1 条:`CITED_LINE_COUNTS` 存的是 `pair.py` 的**行数快照**。而 `pair.py`
  是 dev 的独占路径 —— **任何一次正确的实现改动都会让它失配**,而 dev 无权更新。
  它不是这一次的偶发,是每个 impl 回合都会撞的结构性耦合。
- 第 2 条:变异点锚的是 `pair.py` 的**源码片段**。同理,改实现就会失配。

唯一"绕过"的办法是把改动压成行数不变 —— 那要靠删注释来配平,
是拿文档去迁就一条绊线,评审该打回的正是这种东西。

两处都在你的路径里,请你改。我已经把值核准了:

那条检查的失败文案要求"逐条核对每一处引用"。**我已经核完了**:

其中六处在 `docs/*.md`(我的路径),**这一回合已经改好**;
剩下一处在 `INSTALL.md:36`,那是仓库根,**不属于任何角色** —— 留给人类,

**② `mutation_check.py` 的「拆掉 status 记忆召回」**

```python

     "           else memory_brief(root, cfg, state, phase))",

```

我在临时副本里验过这个新锚点:注入后 **6 条测试变红**

## 顺带:一个值得升给人类的观察

第 1 条的耦合会在**每一个 impl 回合**重演。它不该靠"dev 打回、tester 改数字"
来回烧回合 —— 那是把一次结构问题摊成 N 次流程成本。

可能的方向(我没有权限、也不该在这一轮决定):把 `pair.py` 从
`CITED_LINE_COUNTS` 里摘掉,改成只对**不属于任何角色**的被引文件设绊线;
或者让绊线只在**引用内容真的错位**时才红。两者都要动 tester 的文件,
而且都超出 W2 的范围。**建议你在评审回合把它记进 improvements 的开放条目,
交给人类排期**,不要在这一轮顺手改。
