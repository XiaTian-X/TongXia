## 问题

### `tests/conformance/test_v1_setup_report.py:138` —— 「只看这一批路径」这条判据没有用例守着

契约原话:判据必须是"**这次 `add` 的那批路径**有没有产生索引差异",
**与工作区其余部分无关**。`TestNoIndexDiffDoesNotFail` 的两条用例
(`:145` 原样重跑、`:159` 工作区不干净)守住了"不能看工作区",
**没守住"不能看整个索引"**。

**变异**:把 `index_has_diff` 里的
`("git", "diff", "--cached", "--quiet", "--") + tuple(paths)` 换成
`("git", "diff", "--cached", "--quiet")`(不带路径,判的是整个索引)。

**结果**:W12 的 9 条**全绿**;从当前 HEAD `git clone` 一份完整副本、
只注入这一个变异再跑全套,**356 条全绿**。没有任何一条既有用例抓得住它。

**它是最可能的错误实现,不是我臆想的**:`docs/improvements.md` 开放条目 12
原文给的修法就是"`git diff --cached --quiet`"—— 不带路径。照着路线图写,
正好写出这一版。

**后果是实测的,而且落在「提交范围」那条防护要挡的地方**:索引里预先暂存了一份
不在 `to_add` 里的实现(`git add src/偷跑的实现`),再原样重跑 `verify-setup`:

```
正确实现         : 退出码 0 | 打出「没有需要提交的改动」| 不产生提交
看整个索引的变异 : 退出码 0 | 没有那句话             | 产生一次提交,
                   HEAD 那次提交带进去的文件: ['src/偷跑的实现']
```

那次提交的标题是「通过开工前校验,含契约审查结论」,**里面只有一份偷跑的实现**
—— 开工基线里多了一份实现,spec 阶段"必须 RED"的要求就失效了。

**判据只有一条:把 `index_has_diff` 换成看整个索引,要有一条用例红。**
我的建议形状(你定):在索引里**预先暂存一个不在 `to_add` 里的文件**,
再原样重跑,断言不产生提交、输出含契约字面 `没有需要提交的改动`、
那个文件不在 HEAD 的这次提交里。只用契约给的那个字面,不碰别的措辞。
