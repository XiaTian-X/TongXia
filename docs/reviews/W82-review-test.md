- **拒绝类拒的是不是本节**:
  - 每条拒绝都断言"被拒 + 提交数与 `state.json` 不变",带标记的几条再断言文案原样含标记。

- **范围的边界两侧都有**:
  - 子小节、标题行被拒;未被引用的同级小节、子小节之后的同级小节放行。

- **写法**:契约表每一种一条。全角字符用 `chr(0x...)` 拼,不会因为写文件时被转换而悄悄失去区分力。
  - 英文那条断言原样出现在文案里,同时管住"原文按位置取"。
- **代码豁免**:
  - 两种围栏各一条。`~~~` 那条是必要的:反引号围栏的两行自己就能配成一对行内代码,只有它能看出围栏是不是单独抹掉的。
  - 单、双反引号各一条。
  - "单开双关"与"落单"两条,管住 N 开恰好 N 关、关不上的当字面字符。
  - review-impl 补的"两段各一个落单反引号"管住不跨空行,只有它抓得到 `跨空行配对`。我提出的这条行为有了用例,同意。
- **HTML 注释照算**有一条拒绝用例,变异点 `HTML_注释先抹掉` 被抓。
- **类型**:bug 被拒、cover 与 refactor 放行。"拦了 cover"是等价变异(外层 `item_type != "cover"` 已跳过),不登记,我同意。
- **文案数量**:5 处全列且没有"另有",6 处恰好列 5 处且"另有 1 处"。哪 5 条不断言,不是变更探测器。

  - 按 W73 的切法只数提到该小节的 `[警告]`/`[失败]`,并断言 `setup_verified` 为真,所以"判失败"会红。
