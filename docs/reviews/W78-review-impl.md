## 查过的地方

- 纸面校验 `rename_declarations()`:紧跟 `test_gap_refusal` 之后、抓改动之前,被拒什么都不落盘。
  - 阶段:spec,或带 `--test-gap` 的 review-impl。这两个都是 tester 的阶段,所以 dev 在这一道就被拒,没有单独的角色判定(见下"等价变异")。
  - 格式:用 `partition("=")`,两边去空白后都不能为空,也不能相同。
  - 一对一:在**合并后**的映射上判。同一个旧名换新名、新名重复、键与值相交(链)都拒;同一对重复声明当作已有,契约没说,不拒可以接受。
  - 旧名在全量基线里:`load_executed` 读不出时不判,和 W61 读不出基线时的处理一致。
- 讨论回合:`discuss_handoff` 那一支单独拒 `--renamed`,和 W77 的 `--test-gap` 同形。
- "本回合改了 tester 路径":放在 `--test-gap` 那段"必须补了用例"之后,删除和只追加文件都算。
  - 通过后先把合并后的映射写进内存里的 `state`,⑱ 才能看到本回合刚补的声明。
  - 落盘只在交接成功时。
- ⑱ `last_full_new_failures`:不再跑的集合先过 `matched_renames()`。原锚点行 `gone = vanished_tests(...)` 原样保留,扣除另起一行。
- 完成时:用同一个 `matched_renames()`,先扣除再判拒绝。
  - 新名要在那一次报告的"跑过"集合里,跳过的不算。
  - 对上了的写正文 `改名(对上了): 旧 → 新`。
  - `DONE` 清空 `renamed_tests`,认领也清空。
  - `full_executed` 为 None 时一条都不扣,对不上就照旧按消失算,偏保守,可以接受。
- 正文:本回合每条声明一行 `改名(声明): 旧 → 新`(U+2192,两边各一个空格)。
- W61 的拒绝文案补了 `--renamed` 的用法;argparse 用 `action="append"`。
- 状态与清单:`DEFAULT_STATE` 加了 `renamed_tests: {}`;`ENFORCEMENTS` 加了 `test-rename`(不是交接不变量,README 的 18 不动)。
- 文档:protocol-spec(状态表、选项、正文格式、完成时全量)、command-reference、architecture、troubleshooting、rules.md 第 8 节都跟上了,开放条目 56 标 ✅,措辞与契约一致。
- 没有针对用例输入的特判。

## 变异点

登记 17 个(`改名_` 前缀),`--only 改名_` **全被抓到**:

| 类别 | 变异点 |
| --- | --- |
| 契约列的 | 完成时不扣除对上了的、不要求新名在跑、捷径(⑱)不扣除、不查一旧对多新、不查多旧对一新与链、不查链、不查旧名在基线、不限阶段、review-impl 不要求 `--test-gap`、认领时不清空 |
| 加的 | 完成时不清空、不要求改了 tester 路径、讨论回合不拒、格式不查空、正文不写声明行、正文不写对上了、拒绝文案不提 `--renamed` |

### 两个等价变异,没登记

- **拆掉"只限 tester"**:dev 能带声明进来的阶段已经被阶段那一道拒了。即使绕过它,dev 也得改 tester 路径才过得了"必须改动了 tester 路径",而那本身就越界。几道合起来,dev 永远过不去。
- **格式不查"两边相同"**:`B=B` 合并进映射后键与值相交,"不许链"那一道照样拒。

两道 dev 都留着作纵深防护,不登记,免得变异检查里留两条永远抓不到的。

## 没覆盖到的

- 同一对改名在两个回合各声明一次。契约没说;实现当作已有、不拒。
- "声明校验在跑测试之前"的先后:只断言被拒与状态不变。
- 报告读不出(`full_executed` 为 None)时完成那一步的行为:实现偏保守,没有用例。
