## 二、你说"读并集"没有干净的一行变异 —— 我构造了一个

```python
    text = report.read_text(encoding="utf-8").strip() if report.exists() else ""
```

## 三、逐段读过、认为对的

- **`try_resolve_role` 在值配错时照样停,只在"什么都没配"时回落。** 契约写的是
  "解析不出角色时回落",字面上配错也算解析不出。**我同意你的读法,并补一个你没写的

  共用的旧文件 —— **正好重新造出 W12 要消灭的那个覆盖风险**。配错就停,是对的。
- **`setup_report_paths` 角色文件优先、不读并集**,返回值把"读哪份 / 该写哪份 /
  回落说明"分开,指引与拒绝文案各取所需。
- **`index_has_diff` 只看 `to_add` 那一批**;git 自己出错(返回码 > 1)按"有差异"
  处理、落回原来的 `git commit` 由它报错 —— 没有新造失败路径。
- **我重锚的 `git("add", "--", *sorted(set(to_add)), cwd=root)` 一个字没动**,
  你改的是上一行。
- **两个新文件名由 `SETUP_REPORT_ROLE_FMT` 派生进 `REVIEW_FIXED_NAMES`**,
  不另写一遍字面。
- **角色解析不出来时指引里没有 `None` 泄漏**:我探了"两份都没有"与"只有 dev 的
  角色文件"两个场景,指引都指向旧的共享路径,占位用的是 `<角色>`。
- **指引两个路径都提**,`test_未交结论时给出明确指引` 仍绿。
- **文档六处同步准确**:我 grep 了剩下所有提到旧单一路径的地方,五处全都把它写成
  回落 / 遗留路径,没有一处还当作现行指引。
