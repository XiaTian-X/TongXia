# W16 review-test(dev 审 tester 的测试)

裁决: **changes**。一处:契约验收标准 ② 里的"改名被拒",用例守的不是本节,实现在一种改名下根本不拒。

## 问题:`test_改名被拒` 被越界判定替本节拒了,改名进共享路径时放行

`tests/conformance/test_v1_review_append.py:98` 把登记表 `git mv` 成 `checks/改了名.txt`。
**拒它的是越界**:评审回合 `checks/` 不可写,新路径本来就过不了。docstring 写的"改名在 HEAD 那一侧就是一次删除"
在现在的实现下不成立 —— `changed_entries` 解析 `git status -z` 时**改名只取新路径**
(你在 review-impl 撞见并记进 `DECISIONS.md` 的那个既有漏洞),旧路径那一侧的删除本节根本看不见。

实测(隔离克隆,W16 实现原样):review-impl 里 `git mv checks/mutations.txt docs/reviews/W1-挪走的登记表.md`,
tester approve —— **退出码 0、进 review-test、登记表不在 HEAD 里了**。只追加的登记表被整个挪走,没有任何检查说话。
这正是契约 ②"删除整个文件、改名,都有删除行,都拒绝"要防的,而且是你那条用例 docstring 声称守住的。

和你 spec 回合自己抓到的 `test_删掉整个文件被拒` 同一个形状:**被另一道检查替本节挡了**。那一条你加了
`--allow-deletion`;这一条要换改名的目标,让能拒它的只剩本节。

**候选形状**:改名的目标换成 `shared_paths` 下的路径(评审回合本来可写),断言被拒、阶段不变、登记表仍在 HEAD
(`git_paths` 整路径)。

## 修法,以及为什么建议把你立的那一项并进来

**一个旗标**:`changed_entries` 的 `git status` 加 `--no-renames`,改名拆成删除 + 新增,本节的"有删除行"自然接住。
隔离克隆里验过:

- 上面那个改名进共享路径的场景:**退出码 1、阶段停在 review-impl、登记表仍在 HEAD**;
- **全套 409 条全绿、0 条红** —— 没有既有用例依赖"改名只取新路径"。

**这正是你在 `## W16 — git mv 能绕过删除测试防护` 里写的修法方向**,你打算在 W17 的 spec 回合把它立成单独一项。
**建议这次打回的 spec 回合带 `--contract-change` 把它并进 W16**:本节验收标准 ② 本来就要求改名被拒,
这不是扩范围,是兑现本节;分开做的话 W16 要么带着一条没兑现的验收标准 DONE,要么先打一个只管本节的补丁、
下一项再推倒重来。

**我没验的**:`--no-renames` 是否也堵住了你那条"dev 在 impl 挪走红测试"的路径。按机理应该会(旧路径变成 `D`,
删除测试防护认它),但我没跑。并进来的话那条也该有用例。
