# 第五轮真实运行报告

**主题:把测量工具修准。** 四个工作项(W12 开工前结论按角色分、W13 契约变了校验作废、
W14 声明只在生效时留痕与 `report` 分开净回合、W15 开工前校验的提交只带它自己的文件),
**30 次交接、4 次打回、397 条全绿、126 个变异点全部被抓到收尾**。

**角色和前四轮反过来了**:`tester` 由本会话扮演,`dev` 是另一个会话,共用一个工作目录,
靠 `PAIR_ROLE=` 区分。第五轮的规划与契约是本会话在换角色之前起草的 —— 这一点对下面
所有"独立"的说法都要打折,最后一节细说。

这一轮的目的是给第六轮铺路:第六轮要做一次**两边都没参与设计的独立运行**,
而拿一个会给出错误诊断的仪器去做一次性实验,样本是废的。

## 一句话:打回靠变异,契约缺陷靠开工前审查,红绿只贡献了一次

|---|---|
| **变异**(把实现改坏,看有没有测试会红) | 3(W12、W14、W15 的 review-test) |
| **红绿**(dev 落地实现时一条既有用例变红) | 1(W13 的异议) |

五轮累计:17 次打回,红绿贡献 2 次。

**更大的一块发生在工作项开始之前**。三次开工前的契约审查一共挑出 **24 处缺陷,
全部在认领之前修掉**:

| 审查 | 谁做的 | 挑出 | 采纳 |
|---|---|---|---|
| 第五轮三节的冷审 | 一个没有任何上下文的 agent(`--drafter other`) | 19 | 18 |
| W15 新增一节的独立审查 | tester(那一节是 dev 代笔的) | 3 | 3 |
| 认领 W14 前重跑 `verify-setup` 的审查 | tester(那一节是 tester 起草的) | 2 | 2(带声明改契约) |

W15 那三处里有一处是**"已验证 · 全套 357 条全绿"本身是真的,但全套里没有那种输入**:
契约给的一行修法在"暂存后又删掉的文件"上 `exit 1`,而状态位已经写进工作区。
**"已验证"只覆盖了快乐路径** —— 这句话这一轮之后要当成一条审查判据用。

## 这一轮的形状(第四轮的延续):判据比它声称守的性质更窄

第四轮报告的标题是"判据比它声称守的性质更窄或更宽",发作五次。这一轮又是七次,
而且分出了三种可复用的变体:

**① 只守了双向要求的一侧。** 契约写"在它实际生效时才写进",是条件句,两个方向都要钉。
- W14:五个旗标都写了"不生效时不写",只有 `--basis` 漏了"生效时要写" —— 改成从不写,全套 0 红。
- W14:"不在完成那一次时不留痕"的场景没写笔记,笔记长度先把条件否掉了,分不出实现看没看"完成"。
- W12:守住了"不能看工作区",漏了同一句里的"只看这次 add 的那批" —— 看整个索引,全套 356 条全绿。

**② 断言本身恒真。**
- W12 的三处 `assertNotIn("偷跑的实现", <ls-files / ls-tree 的输出>)`:不带 `-z` 时中文路径被转义,
  子串永远找不到。**两个角色都踩过,而且都把病因认错成"查索引还是查 HEAD"。**
  W15 把判法改成 `-z` 整路径相等,并让测试工具在不带 `-z` 时直接报错。
- W14 的 `assertIn("0% (0/2)", report)`:同一份报告里另一行恰好也是 `0% (0/2)`。
  这一条是交接前自己在今天的代码上跑出"本该红却是绿"才发现的。

**③ 测试数据的形状替实现挡掉了一类输入。**(dev 在 W15 决策里总结的)
W15 把判据侧的转义坑修得很彻底,但被测代码里同一个 `-z` 没有任何用例经过 ——
进入 `git commit --` 的路径全是 ASCII,唯一的中文名 `草稿.md` 恰恰是不进提交的那个。
**可复用的判据:实现里每一处为某类输入做的特殊处理(`-z`、`strip`、转义),
都要问测试数据里有没有一条输入会让那处处理起作用。**

**以及一个 W13 的变体:用"今天的全套"判"落地之后的全套"。** tester 在 W13 的 spec 里
写"全套 375 条、红 10 条,没有别的用例被带红",那个数是真的,但副本里只实现了一半。
`claim` 那一半落地,一条既有用例(dev 校验、tester 认领、期望放行)就和新契约冲突了 ——
dev 以异议交接指出。**从 W14 起 tester 改了做法:交接前在隔离副本里写一个完整的参考实现、
跑全套,再说"没有别的用例被带红"。** W14(393 条)、W15(396 条)两次都这样做了。

## 两个结构问题,根子是同一个:测试只在 spec 回合可写

**① 变异点连续三次欠到下一个工作项(W12、W13、W14)。**
新代码的形状由 dev 定,锚点要到 impl 落地才知道;而 `mutation_check.py` 在 tester 的独占路径下,
tester 在一个工作项里能写 `tests/` 的只有 spec 回合 —— 那时代码还不存在。于是每次都是:
dev 在笔记里点名锚点 → tester 在 review-impl 隔离复现 → 写进 `DECISIONS.md` 欠着 →
下一个工作项的 spec 回合登记。W14 那一笔提前还清,只是因为恰好有一次打回把回合退回了 spec。

**② 只涉及测试的打回,必然制造一个空转的 impl 回合。**
第五轮 7 个 impl 回合里 **3 个是空转的,而且三个全是这一类**(W13、W14、W15 的第二个 impl 回合):
review-test 打回 → tester 在 spec 补测试 → dev 的 impl 回合无事可做、一行代码不改 →
tester 的 review-impl 也只能确认"没有可实现的东西是对的"。**一次只涉及测试的打回,
实际花掉三个回合,其中两个是纯仪式。** W14 加的空转判定行会把它们如实计成协议开销,
但分不出"为什么空" —— 这一类和"实现方混一个回合"在 `report` 里同色。

两件事都登记进了路线图开放条目 18、19。

## 新检查在引入它的那个工作项里管不到自己(又两次)

第四轮记过这条推论("同一个工作项里不能既加旗标又用旗标"),这一轮它换了两种形状:

- **W13 自己的 DONE 仍按旧口径判。** 执行那次交接的裁判副本里还没有 `settled`,
  tester 在 review-impl 写下的决策在那一次交接里不算"本回合新追加",dev 只能当场再补一条。
- **W14 自己的 impl 回合没有判定行。** 执行交接的还是 W13 那份裁判副本,于是 W14 的第二个
  impl 回合落进了「未判定的 impl 回合」。**W15 的第二个 impl 回合是协议史上第一行真正写进
  提交正文的 `空转判定: 是`。**

**W13 的门禁在真实仓库里拦下了两次认领**,都是它该拦的:认领 W14 时状态里没有 tester 那一份
校验记录(存量升级的形状),认领 W15 时契约在上次校验之后被改过(W14 的契约改动)。
两次都是重读、在结论后面补记、重跑之后放行。

## 本会话(tester)这一轮的错

按时间:

1. **W12:守住了一侧**("不能看工作区"),漏了"只看这批路径"。dev 用变异打回。
2. **W12:写了两条恒真的断言**,docstring 里还在教别人"查 HEAD 的树" —— 那句话本身就是
   把病因认错了。到审 W15 契约时才自己发现。
3. **W13:只实现了一半就说"没有别的用例被带红"。** dev 以异议交接指出。
4. **W13:唯一能写 `tests/` 的回合里漏登记了 8 个变异点。** dev 提醒。
5. **W14:`--basis` 只守一侧、"不在完成那一次"分不出条件。** dev 用变异打回。
6. **W14:`0% (0/2)` 恒真** —— 交接前自己抓到的。
7. **W15:守住了"判据别被转义骗",没守"实现别被转义骗"。** dev 在 impl 回合就探出来了。

七条里五条是 dev 发现的。其中**三次打回与一次异议,全部带着可以直接照写的形状** ——
打回的三次都附了"正确实现绿、只有这个变异红"的候选用例,异议那次写明了"应该改成什么"。
打回不是一句"覆盖不足"。(第五条是一句提醒,不是打回。)

**一个协议给这一轮带来的收益值得记下:** 每一次打回之后,那条"口头结论"都变成了
`MUTATIONS` 里的一个常设检查(`依据从不写`、`晋升闸读旗标时不看完成`、`提交路径不带 -z`……)。
dev 在 W14 的 review-test 里说"比补两条用例本身更值" —— 下一次谁再把那一行改坏,
不需要任何人记得这一轮发生过什么。

## 五轮下来仍然欠着的

**一次两边都独立的运行。**

这一轮离独立更近了一点,但仍然不是:
- 第五轮的规划与契约由本会话起草,本会话随后扮演 tester —— 照契约写断言的正是起草人。
  `--drafter self` 声明了三次,证明力打折。
- 反过来,**W15 那一节是 dev 代笔的,tester 做了一次真正的 `other` 审查,挑出三处缺陷全部被采纳**;
  冷审那一次也是真正的 `other`。两次 `other` 审查挑出 22 处,自审挑出 2 处。
  样本很小,但方向和第四轮报告里"八次自审、结论开头都写着证明力打折"是一致的。

**人类这一轮裁决了零次冲突。** 唯一的人类介入是授权 dev 代笔立项 W15。

第六轮就是那次独立运行。仪器现在是:开工前校验按角色、契约改了就作废;
`report` 分开净回合与开销、说出覆盖面;声明只在生效时计数;开工基线不会夹带别人暂存的实现。
