## 唯一的打回:测试没有覆盖契约条款里的每一类

W3 被 dev 打回,两个错误实现对整套 slugify 用例 0 条红:

- **组合符只认 `Mn`**。契约定义是 `unicodedata.category` 以 `M` 开头,而用例里的四个组合符全是 `Mn`。
  只认 `Mn` 的实现把 `Mc`、`Me` 丢掉 —— 一个印地语词(U+0939 U+093F U+0902 U+0926 U+0940)在那个版本下只剩两个码位,**元音符号整个没了、字被改了**。
  W4 提函数时写成 `== "Mn"` 正是最顺手的错,而 W4 只靠这套测试保护。
- **`casefold()` 代替 `lower()`**。用例里的字母两种小写结果相同。按契约 `Straße` 应保留 `ß`,casefold 会得 `strasse`。
  **第十三轮 W3 被打回的是同一个缺口**,两轮之间没有任何沟通 —— 样板契约没能引导人写出能区分这两者的测试。

tester 补完后在笔记里写下一条教训:"按类别写的条款,每一类都要挑一个能把错误读法区分开的样本"。
这与第十六轮 W32 的决策("契约里用来说明一条规则的例子,必须能区分这条规则")是同一个道理,这次在测试一侧自己长出来。
