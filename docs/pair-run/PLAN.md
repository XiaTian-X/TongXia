# 项目规划（冻结 — agent 只读）

> 由人类维护。工作项完成时由脚本勾选,那是脚本的权限,不是 agent 的。

## 目标

**第三轮:文档与代码的关系。** 前两轮(W1-W3)把 `status` 的回合简报做完了,
但那三个工作项真正暴露出来的东西不在简报里 —— **四次卡顿全部出在
"哪份文件归谁、什么时候能写、文档怎么指代码"上**,一次都不是简报本身的问题。

来源:`docs/improvements.md` 的 P0-4、P0-7、P1-12,它们在路线图里被编成
同一组,因为三条都不依赖任何设计决定,纯粹是缺陷修复,而且**在它们落地
之前,后面每一轮都会继续踩同样的坑**。

证据在 `docs/dogfood-run-2.md` 与 `docs/pair-run/DECISIONS.md` 的四条
W2/W3 条目里。

### 顺序是硬依赖:**W6 必须最先**

`pair.py` 现有 7 处行号引用分布在 `cmd_init` / `cmd_handoff` /
`cmd_whose_turn` / `cmd_report` / `cmd_verify_setup` 里。**W4 要改
`verify-setup`,一动就让其中至少一处失配** —— 而那正是 W6 要消灭的东西。
先做 W6,W4 的漂移成本直接归零;反过来做,每改一次 `pair.py` 就要付一次
往返。所以工作项按下面的顺序排列,不是编号顺序。

### 开工前人类要做两件事

1. **重跑 `verify-setup`。** 契约改过,前一轮的审查结论没有覆盖新内容。
2. **划归孤儿路径**(改 `.pair/config.json` 的 `roles`)。这是 **W6 的前置
   条件**:它要迁移的引用里有几处在 `INSTALL.md` 与 `README.md`,
   而那两份现在不属于任何角色,dev 改不了 —— 前两轮已经为同类问题卡过两次。
   建议把仓库根的说明文档与 `examples/` 划给 dev。
   顺带把 `tests/conformance/mutation-cache.json` 加进 `ignore_paths`(见下)。

**注意 W4 只负责让缺口可见,不负责修好它。** 划归是"谁能写什么"的决定,
按契约「不做」那条,脚本不碰。

### 原 W5(`artifact_paths`)已取消

开工前复查发现**它要的功能已经存在**:`ignore_paths` 的 `continue`
(`pair.py` 的写权限边界循环里)落在角色与阶段判断**之前**,所以它
**已经同时豁免了角色与阶段** —— 正是 `artifact_paths` 提议的核心。
新增配置键相对它的安全增量约等于零(留痕防不住任何东西,而副产物的改动
本来就在 `git diff` 里可见)。

**剩下的真缺口只有可见性**,已并进 W4 的第二个清单。把副产物划进
`ignore_paths` 是一次 config 改动,人类做,不是工作项。

将来 `discuss` 阶段落地时会真需要一个新路径类别(提案目录),但那时需要的
不是"副产物",而且 `shared_paths` 有一个隐藏约束(见 improvements 的 P0-5),
到时候单独设计。

## 工作项

- [x] **W2** [feature] — 记忆段落入简报,非自己回合时不写不清空
  - 验收标准:有笔记或相干决策时,简报里的记忆段落与终端所见**逐字一致**
    (不含终端上那两条 `=` 分隔线与标题);没有时整段连同它前面那个空行
    一起省略,而头部四行仍在;不是自己回合时跑 `status`,既不创建该文件、
    也不改动已有内容
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的记忆段落

- [x] **W3** [feature] — 写不成时不阻断,以及新项目里被忽略
  - 验收标准:写入抛 `OSError` 时 `status` 退出码不变、其余输出不受影响,
    标准输出出现一行以 `[简报]` 开头的警告;全新项目跑完 `init` 后,
    该项目的 `.gitignore` 里含 `.pair/.last-brief.md`
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的降级与忽略

- [ ] **W6** [feature] — 文档里的代码引用改成符号形式
  - 验收标准:规范性文档里 `` `<文件>#<符号>` `` 的符号在目标文件里不存在
    时,一致性检查失败并指出文档、文件与符号;`` `<文件>:<行号>` `` 形式
    被拒,并指出应改成哪个符号(该行号所在的封闭符号);**代码块与行内代码
    里的示例不算引用**;形如 `` `<文件>:<行号>@<sha>` `` 的**历史快照豁免**
    (运行报告与"已解决"留档记的是当时的状态,改写它等于篡改历史);
    仓库里所有行号形式的引用迁移完毕 —— **由检查全绿本身证明,不数具体
    数字**(开工时实测 27 处,但那是快照,期间增删都会让写死的数字失效);
    `CITED_LINE_COUNTS` 绊线连同它在 `docs/contributing.md` 的说明一并移除
  - 对应契约:`docs/pair-run/CONTRACT.md` → 文档里的代码引用

- [ ] **W4** [feature] — 把边界的两个缺口摆出来,并在撞上时说清楚
  - 验收标准:三条。①**孤儿清单** —— 被 git 跟踪、且不落在任何角色/共享/
    冻结/`ignore_paths` 里的文件,`verify-setup` 打印首行含"孤儿"与总数、
    随后逐行列出的警告,**超过 10 个只列前 10 行**并补剩余计数,退出码不受
    影响,未被跟踪的文件不算;②**`ignore_paths` 覆盖清单** —— 同一次
    `verify-setup` 另打印一段,首行含"不受边界保护"与总数,同样的截断规则;
    ③**越界文案** —— `handoff` 因写权限边界拒绝时,若越界文件是孤儿,
    文案要指出它不属于任何角色、需要人类划归
  - 对应契约:`docs/pair-run/CONTRACT.md` → 路径归属的可见性
