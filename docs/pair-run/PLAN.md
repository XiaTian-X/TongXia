# 项目规划（冻结 — agent 只读）

> 由人类维护。工作项完成时由脚本勾选,那是脚本的权限,不是 agent 的。

## 目标

**第三轮:文档与代码的关系。** 前两轮(W1-W3)把 `status` 的回合简报做完了,
但那三个工作项真正暴露出来的东西不在简报里 —— **四次卡顿全部出在
"哪份文件归谁、什么时候能写、文档怎么指代码"上**,一次都不是简报本身的问题。

来源:`docs/improvements.md` 的 P0-4、P0-7、P1-12,它们在路线图里被编成
同一组,因为三条都不依赖任何设计决定,纯粹是缺陷修复,而且**在它们落地
之前,后面每一轮都会继续踩同样的坑**。

证据在 `docs/dogfood-run-2.md` 与 `docs/pair-run/DECISIONS.md` 的四条
W2/W3 条目里。

### 开工前人类要做两件事

1. **重跑 `verify-setup`。** 契约新增了三节,前一轮的审查结论没有覆盖它们。
2. **划归孤儿路径**(改 `.pair/config.json` 的 `roles`)。这是 **W6 的前置
   条件**:它要迁移的 27 处引用里有几处在 `INSTALL.md` 与 `README.md`,
   而那两份现在不属于任何角色,dev 改不了 —— 前两轮已经为同类问题卡过两次。
   建议把仓库根的说明文档与 `examples/` 划给 dev,`.pair/config.json` 的
   `artifact_paths` 先留空(W5 落地后再填)。

**注意 W4 只负责让缺口可见,不负责修好它。** 划归是"谁能写什么"的决定,
按契约「不做」那条,脚本不碰。

## 工作项

- [x] **W2** [feature] — 记忆段落入简报,非自己回合时不写不清空
  - 验收标准:有笔记或相干决策时,简报里的记忆段落与终端所见**逐字一致**
    (不含终端上那两条 `=` 分隔线与标题);没有时整段连同它前面那个空行
    一起省略,而头部四行仍在;不是自己回合时跑 `status`,既不创建该文件、
    也不改动已有内容
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的记忆段落

- [x] **W3** [feature] — 写不成时不阻断,以及新项目里被忽略
  - 验收标准:写入抛 `OSError` 时 `status` 退出码不变、其余输出不受影响,
    标准输出出现一行以 `[简报]` 开头的警告;全新项目跑完 `init` 后,
    该项目的 `.gitignore` 里含 `.pair/.last-brief.md`
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的降级与忽略

- [ ] **W4** [feature] — `verify-setup` 检出孤儿路径
  - 验收标准:被 git 跟踪、且不落在任何角色/共享/冻结/`ignore_paths`/
    `artifact_paths` 里的文件,`verify-setup` 打印一段警告 —— 首行含"孤儿"
    与总数,随后逐行列出路径;**超过 10 个只列前 10 行**并补一行剩余计数;
    退出码不受影响;未被跟踪的文件不算孤儿
  - 对应契约:`docs/pair-run/CONTRACT.md` → 开工前的路径覆盖面检查

- [ ] **W5** [feature] — `artifact_paths`:副产物豁免角色与阶段
  - 验收标准:`artifact_paths` 下的改动在任何角色、任何阶段(**含只读评审
    回合**)都能交接;与角色路径**重叠时以 `artifact_paths` 为准**;本次交接
    含此类改动时提交正文出现一行以 `副产物:` 开头、后接路径清单,
    且**不需要 agent 显式声明**;`verify-setup` 打印它覆盖了哪些被跟踪文件
  - 对应契约:`docs/pair-run/CONTRACT.md` → 副产物路径

- [ ] **W6** [feature] — 文档里的代码引用改成符号形式
  - 验收标准:规范性文档里 `` `<文件>#<符号>` `` 的符号在目标文件里不存在
    时,一致性检查失败并指出文档、文件与符号;`` `<文件>:<行号>` `` 形式
    被拒,并指出应改成哪个符号(该行号所在的封闭符号);**代码块与行内代码
    里的示例不算引用**;仓库现有 27 处引用全部迁移完毕
  - 对应契约:`docs/pair-run/CONTRACT.md` → 文档里的代码引用
