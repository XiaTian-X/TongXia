# 项目规划（冻结 — agent 只读）

> 由人类维护。工作项完成时由脚本勾选,那是脚本的权限,不是 agent 的。

## 目标

**第四轮:文档改动的授权与留痕。** 前三轮每一轮开工,人类都要手抄一次
PLAN 与契约 —— 而它给的授权是"定方向",不是"当打字员"。这一轮把它反过来:
agent 可以落笔,但必须留下**谁改的、为什么改、依据是什么**。

来源:`docs/improvements.md` 的 P1-15 与 P1-9(弱版本)。路线图把 P1-9 原本
排在第七轮,复查后前移 —— 它的顾虑(合谋改契约)本来靠 discuss 的双方签字,
而 P1-3 里已有等价的轻量流程,**弱版本不依赖 discuss**。代价写在契约里。

**同时清掉第三轮的欠账。** W4 走完流程被勾选了,但它的验收标准有三条没有
测试守着(两条是 dev 在终审里用变异发现的,一条是 tester 事后逐条对照
补出来的);另有五条落在 `pair.py` 的防护至今没有变异点。
**"工作项勾选"不等于"验收标准都被测住"** —— 这是三轮里第二次
(W3 同源),所以这一轮先把它清干净再往前走。

### 开工前人类要做的事(顺序有意义)

1. **先只把 `PLAN.md` 与 `CONTRACT.md` 从 `frozen_paths` 移出,不划归。**
   跑一次 `verify-setup`:上一轮刚做的 W4 会把它们报成**孤儿** ——
   这是对 W4 的一次真实验证,而且只有在"移出但还没划归"这一刻才看得到。
2. **再把这两份划归某个角色。** 划归之后它们就不是孤儿了,
   两件事不能同时成立 —— 所以必须分两步,不能一次做完。
3. **重跑 `verify-setup`** —— 契约新增了「术语」一节、两节新规格,
   前一轮的审查结论没有覆盖新内容。

**划归的写法有个坑,实测过:**

| 写法 | 结果 |
|---|---|
| `docs/pair-run/**` | 命中 `notes_dir` 与 `decisions_file` → `verify-setup` **直接失败** |
| `docs/pair-run/PLAN.md`、`docs/pair-run/CONTRACT.md`(逐份写) | 安全 |

`verify-setup` 强制记忆层不能落进任何角色路径(落进去就变成单方私有的),
而最省事的目录通配正好把 `notes/` 与 `DECISIONS.md` 一起圈进去。**逐份写。**

### 本轮的一条纪律:每条新增的拒绝分支都要有变异证明

W8 与 W9 各自新增一条拒绝分支。第三轮的教训是**同一个失效形状出现了三次**
——断言的取样范围比被断言的性质大,于是"通过了"什么都不说明
(区间用例起止落在同一符号;剩余数断言被表头里的总数满足,而且换了个数字
之后仍然恒真)。

所以本轮验收时,每条新增的拒绝分支都要给出"**把它拆掉会红**"的证据,
而不只是"带了参数能过、不带会拒"。这也正是五步纪律的第 3 步 ——
见下面 W8 要顺带修的那件事。

### 第三轮的问题里，本轮**不做**的三条(写明理由，免得下轮重新发现)

**开放条目 13(开工前校验的报告路径不分角色)—— 不做。** 它上一轮真的造成过
一次覆盖(dev 把 tester 的结论整份盖掉,靠 git 还原)。但实测改动面是
**`pair.py` 6 处 + 文档 7 处 + 测试 33 处**,跨两个角色,单独就是一个工作项;
本轮已经三项。**本轮的临时办法**:人类在第一条消息里规定,**第二个跑
`verify-setup` 的一方必须先读那份文件、追加而不是覆盖**。这是一条散文规则,
这个项目一向不信任它 —— 所以它只是临时办法,真正的修法排下一轮。

**开放条目 12(`verify-setup` 在工作区干净时必然 `exit 1`)—— 不做。**
它只在"报告没改动却重跑一次"时发作,而开工前每一方都会写自己的结论、
工作区不干净。上一轮我是为了确认才重跑才撞上的。绕开成本≈0,单独修要一个
工作项。和 13 一起排下一轮(同一个函数)。

**开放条目 14(66 处省掉文件名的裸 `:行号`)—— 不做。** 它是一次机械迁移,
和本轮"授权与留痕"的主题无关;而且 W8 落地之后,**改那 66 处本身就要带
`--doc-reason`**,顺序上更适合放在 W8 之后。

## 工作项

- [x] **W2** [feature] — 记忆段落入简报,非自己回合时不写不清空
  - 验收标准:有笔记或相干决策时,简报里的记忆段落与终端所见**逐字一致**
    (不含终端上那两条 `=` 分隔线与标题);没有时整段连同它前面那个空行
    一起省略,而头部四行仍在;不是自己回合时跑 `status`,既不创建该文件、
    也不改动已有内容
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的记忆段落

- [x] **W3** [feature] — 写不成时不阻断,以及新项目里被忽略
  - 验收标准:写入抛 `OSError` 时 `status` 退出码不变、其余输出不受影响,
    标准输出出现一行以 `[简报]` 开头的警告;全新项目跑完 `init` 后,
    该项目的 `.gitignore` 里含 `.pair/.last-brief.md`
  - 对应契约:`docs/pair-run/CONTRACT.md` → 简报的降级与忽略

- [x] **W6** [feature] — 文档里的代码引用改成符号形式
  - 验收标准:规范性文档里 `` `<路径>#<符号>` `` 的符号在目标文件里不存在
    时,一致性检查失败并指出文档、文件与符号;**符号在该文件里重名时必须写成
    `<外层>.<内层>`**,裸写重名符号一样失败并列出候选;`` `<路径>:<行号>` ``
    与区间 `` `<路径>:<行号>-<行号>` `` 两种旧形式都被拒,并指出应改成哪个
    符号(起始行所在的封闭符号,嵌套取最内层);**不算引用的只有两类** ——
    ``` 围栏代码块里的内容,以及目标 `.py` 文件在仓库里不存在(行内代码
    **算**引用,那正是规定形式);形如 `` `<路径>:<行号>@<sha>` `` 的
    **历史快照豁免**(运行报告与"已解决"留档记的是当时的状态,改写它等于
    篡改历史),且不校验该 sha 在不在本地;文档范围取现有一致性检查的
    `NORMATIVE` 全集,**含 `improvements.md`**;仓库里所有行号形式的引用
    迁移完毕 —— **由检查全绿本身证明,不数具体数字**(处数是快照,期间增删
    都会让写死的数字失效);`CITED_LINE_COUNTS` 绊线连同它在
    `docs/contributing.md` 的说明一并移除
  - 对应契约:`docs/pair-run/CONTRACT.md` → 文档里的代码引用

- [x] **W4** [feature] — 把边界的两个缺口摆出来,并在撞上时说清楚
  - 验收标准:三条。①**孤儿清单** —— 被 git 跟踪、且不落在角色/共享/
    冻结/`ignore_paths`/**记忆层(`notes_dir` 与 `decisions_file`)** 里的
    文件,`verify-setup` 打印首行含"孤儿"与总数、随后逐行列出的警告,
    **超过 10 个只列前 10 行**并补**剩余**计数,退出码不受影响,未被跟踪的
    文件不算(记忆层必须排除:它被 `verify-setup` 自己强制挡在前四类之外,
    不排除就是一条无法消除的常驻警告);②**`ignore_paths` 覆盖清单** ——
    同一次 `verify-setup` 另打印一段,首行含"不受边界保护"与总数,同样的
    截断规则,**两段先后顺序不作规定**;③**越界文案** —— `handoff` 因写权限
    边界拒绝时,若越界文件是孤儿(判据与①逐字相同),文案要指出它不属于任何
    角色、需要人类划归,**并且末尾那句"请撤销这些改动后重试"要跟着改成分
    情况的说法**;越界项里没有孤儿时末尾维持原样
  - 对应契约:`docs/pair-run/CONTRACT.md` → 路径归属的可见性

  - 对应契约:`docs/pair-run/CONTRACT.md` → 路径归属的可见性

- [ ] **W8** [feature] — 文档改动要带理由,路线图的改写要有依据
