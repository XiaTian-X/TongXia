# 项目规划（改动要带 `--contract-change` 并当场留决策）

> 方向由人类定。**两个角色都可以落笔**,但改它的那次交接要带
> `--contract-change "<指向一份真实产物的路径>"`,并在 `DECISIONS.md` 里
> 当场追加一条 —— 不是放行,是强制留痕。工作项完成时由脚本勾选,
> 那一次写入不算 agent 的改动。

## 目标

**第六轮:先修第五轮暴露的五处协议缺口,再做独立运行实验。**

第五轮把测量仪器修准了(W12–W15),真实运行报告 `docs/dogfood-run-5.md` 与路线图
开放条目 18–22 记下了它同时暴露的五处缺口。**这五处都会污染下一次独立运行的样本**:

| 缺口 | 第五轮的实测 | 对实验的影响 |
|---|---|---|
| 新代码的变异点只能欠账(18) | W12、W13、W14 连续三次欠到下一项 | 欠账期间那几个分支没有常设检查 |
| 只涉及测试的打回制造仪式回合(19) | 7 个 impl 回合里 3 个空转,全是这一类 | `report` 的协议开销被结构性抬高 |
| dev 的"校验不作数"提示常驻(20) | dev 这一轮**每一次** `status` 都打这句 | 永远在的提示教人忽略它 |
| 评审记录没有追加式保护(21) | W14、W15 各被整份改写一次 | 已进提交记录的评审证据可被无声改写 |
| `report` 没有起点(22) | 未判定 25、历史声明照旧计数 | 实验的数只能靠人手工减 |

**独立运行实验挪到第七轮。** 人类在第五轮收尾时裁决"开始修复"(2026-09)。

### 顺序:越早落地、对后面几项越有用的排越前

新检查只从**下一个**工作项起生效(裁判副本在 `DONE` 才重钉)。所以:

- **W16(条目 18)第一**:它落地之后,W17–W20 的新锚点可以在 review-impl 当场登记,
  不再欠到下一项。W16 自己的锚点仍然欠一次(它的 review-impl 由旧裁判判)。
- **W17(条目 19)第二**:之后几项若有只涉及测试的打回,少走两个仪式回合。
- **W18(条目 21)**、**W19(条目 20)**、**W20(条目 22)** 互不依赖。W19 排在 W20 前,
  让 W20 的认领成为 claim 看两个角色的第一个真实样本。

### 开工前

1. **两个角色都重跑 `verify-setup`** —— 契约新增五节。W19 落地之前这仍只对 tester 强制,
   但 dev 在第五轮从没重跑过,正是条目 20。
2. **契约由 dev 代笔**(人类授权),所以 tester 的审查是 `--drafter other`,dev 自审是 `self`。
   第五轮 W15 那一节的教训:代笔人写的"已验证"只覆盖了快乐路径,**五处缺陷里三处是 tester
   开工前挑出来的**。这一轮每节的"已验证"都写明验了什么、没验什么。
