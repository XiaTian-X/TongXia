### 用例怎么造的,实现时要知道的

- 沿用 W61 的假全量(`test_v1_full_vanished.VanishBase`,直接导入):`suite/` 下文件名是用例名,内容 `green`/`red`/`skip`/`gone`;用例 ID 是 `suite.<名>`。
  "改名"由人类提交 `suite/` 的变化来造;tester 那一回合另改 `tests/W1`。另配了 `proposal_paths`(讨论回合那条要用),所以 `RenameBase` 自己搭假全量、不调 `VanishBase.setUp`。
- 状态里的 `renamed_tests`:用例按"映射"读 —— 是 dict 就取 `items()`,是列表就按二元组读,统一成 `{(旧, 新)}`;没有这个键或为空都是空集合。
- 正文两种行逐字断言:`改名(声明): 旧 → 新`、`改名(对上了): 旧 → 新`(ASCII 括号与冒号,箭头 U+2192,两边各一个空格)。一条声明一行。
- 拒绝类断言提交数与 `state.json` 不变,不断言措辞。"格式不对""一对一"两组在同一个 spec 回合里逐个试(被拒什么都不改)。
- **"本回合没改 tester 路径"**:失败用例由人类先提交,tester 本回合只写笔记;同一回合不带声明的交接照常放行 —— 证明拒它的只有这一条。
- **⑱ 要算上本回合的声明。** 修正回合就是 tester 补声明的那一回合:W17 捷径判 ⑱ 时,只看状态里已记的会漏掉这一回合刚声明的,捷径不走。
  我的参考实现第一版就栽在这里(`TestShortcut` 那条红),改成校验通过后先把合并后的映射放进内存里的状态,再走 ⑱。
- **"认领时清空"单独造**:正常完成就清空了,所以由人类在空闲时直接提交一份带 `renamed_tests` 的状态(dict),再认领。
- 完成成功那条同时断言基线更新为 `suite.A`、`suite.C`(W61 原有行为,改名对上之后照常写基线)。

### 参考实现与探针

`.pair/scratch/` 里写过参考实现(已删),21 条全绿,`test_v1_full_vanished`、`test_v1_rebound_shortcut`、`test_v1_test_gap` 照旧全绿。
探针 20 个,18 个被抓:契约列的七个(完成时不扣除、不要求新名在跑、⑱ 不扣除、不查一对一 —— 拆成一旧对多新 / 多旧对一新 / 链三个、不查旧名在基线、
认领时不清空,"不限阶段"见下),加完成时不清空、不要求改 tester 路径、讨论回合不拒、格式不查空、正文不写两种行、W61 文案不提 `--renamed`、只在 review-impl 却不要求 `--test-gap`。

- **"不限阶段"第一版没抓到**:review-impl 不带 `--test-gap` 那条,tester 什么都没改,拒它的是"本回合必须改动了 tester 路径"。改成往只追加的登记表(`checks/mutations.txt`)里加一行 ——
  不带旗标也合法、也算改了 tester 路径,于是能拒它的只剩阶段那一道;同一回合不带声明照常通过作对照。改完之后两种拆法都被抓。
- **两个没抓到、我判为等价的**:
  - "不限 tester":dev 只要带了声明,就得改 tester 路径才过得了"本回合必须改动了 tester 路径",而 dev 改 tester 路径本来就越界 —— 两道合起来 dev 永远过不去,拆掉角色这一道观察不到。
    用例仍断言 dev 在 impl、review-test 带被拒。
  - "格式不查两边相同":`B=B` 合并进映射后键与值相交,"不许链"那一道照样拒。

### 没写用例的

- "声明时的校验在跑测试之前"的先后(只断言被拒与状态不变)。
- 变异点等实现落地后在 review-impl 登记。

## impl(dev)

`pair.py` 里按 `cmd_handoff` 的顺序:

1. **纸面校验** `rename_declarations()`,紧跟 `test_gap_refusal` 之后(转移表查完、抓改动之前):阶段(spec,或带 `--test-gap` 的 review-impl;dev 落在这一道)、
   格式(`partition("=")`,两边去空白后非空且不等)、一对一(在合并后的映射上判:同一个旧名换新名、新名重复、键与值相交都拒;同一对重复声明当作已有)、
   旧名在全量基线里(`load_executed` 读不出不判)。返回本回合的对子与合并后的映射。讨论回合那一支也调一次,和 `--test-gap` 同样。
2. **改了 tester 路径** 在 `--test-gap` 那段"必须补了用例"之后:含删除、含只追加文件(你在 review-impl 那条正是靠登记表那一行)。
   通过后**先把合并后的映射放进内存里的状态** —— 你笔记里说的 ⑱ 要算本回合的声明;状态只在交接成功时落盘,被拒什么都不留。
3. **⑱** `last_full_new_failures`:不再跑的集合先过 `matched_renames()`(新名按那一次报告的跑过集合判)。原来那一行 `gone = vanished_tests(...)` 是变异锚点,原样留着,扣除另起一行。
4. **完成时** 同一个 `matched_renames()`,扣完再判拒绝;对上了的写正文 `改名(对上了):`,状态清空。认领时也清空。
5. 正文:本回合每条声明一行 `改名(声明): 旧 → 新`;W61 拒绝文案补 `--renamed` 的用法;argparse `action="append"`。

`DEFAULT_STATE` 加 `renamed_tests: {}`(protocol-spec §8 表跟上);`ENFORCEMENTS` 加 `test-rename`(不是交接不变量,README 的 18 不动)。
