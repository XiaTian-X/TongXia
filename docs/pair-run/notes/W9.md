## 一、交出之前:参考实现 + 七个错误实现

参考实现下 **12 条全绿**。改错七次:

| 注入的错误实现 | 红的用例 |
|---|---|
| 旗标豁免**任何**冻结路径 | 旗标不能豁免其他冻结路径 |

## 二、三个我自己踩的坑，都是变异或参考实现逼出来的

**① 一条恒真的关键词。** `test_带声明但没留决策被拒` 原来用 `"DECISIONS"`
当关键词 —— 而 `--contract-change` 还不存在,argparse 的
`unrecognized arguments: … docs/DECISIONS.md` **回显了那个路径**,当场绿。
换成中文 `"决策"`(argparse 造不出中文)才红。这是第二次栽在同一处,
现在我的习惯是:**凡是关键词可能出现在命令行参数里的,一律换掉。**

**② `scope` 那一道判定从来没被开过。** 第一版是在用例里改
`.pair/config.json`,把 `'"scope": []'` 替换掉 —— 而 harness 的 `CONFIG`
**根本没有 `scope` 这个键**,`json.dumps` 里没有那个子串,替换是空操作。
用例一直在空 `scope` 下跑,那一道判定完全没被触发。
**是变异「豁免只跳冻结和越界」一条都不红,才把它暴露出来的。**
改成类级 `config = {"scope": [...]}`,现在那个变异会红。

**③ `report` 那条原来只断言"这一行存在"。** 一个恒为 0、或者写死常数的
实现照样能过,而这一节的目的是"频率异常时收紧",不动的数字没有用处。
改成跑两个工作项(一个不改契约、一个改),断言**那一行前后不同** ——
不碰措辞、不碰 `_fmt_rate` 的格式。

## 三、⚠️ W9 与既有强制的交互：同一次契约变更要留**两条**决策

实测。带 `--contract-change` 在 spec 回合改了契约并留了一条 `## W2 — …`,
走到 `DONE` 那次交接**又被拦了**:

```
拒绝交接 —— docs/CONTRACT.md 在这个工作项期间被改过,
但 docs/DECISIONS.md 里没有对应记录。
```

根因:既有那条(`contract-change-note`)算的是
`mine = [e for e in fresh if e[0] == item]`,而 `fresh` 是
`new_decision_entries` —— **按偏移量算"这一次交接里新追加的"**。
spec 回合那条早就进了 HEAD,到 DONE 时不算"新的"。

于是同一次契约变更要留两条 id 相同的决策:一条在改动那一刻,一条在完成时。

**我没有把它写成断言。** 契约写的是两条"并存、互不替代",所以照字面这是
规定行为;但它长得像冗余,而把可疑行为焊进用例正是 `cover` 那套纪律点名要
避免的事。我只在 `TestReportShowsContractChanges` 的脚手架里满足了它,
并在那里写明"这是交互不是规格"。**请你或人类判一下**:
是接受两条,还是让既有那条认"本工作项内已有同 id 决策"。后者要改契约。

## 一、那条判据改成「让分母不变」

你给的诊断(换成 `"%d 次"` 之后恒为 0 会红)直接指出了根因:**分母替分子
演了"变化"**。所以新判据不去解析那一行,而是**让两次观测的分母逐字相同**:

1. 完整跑掉 W1(不改契约)→ `done == 1`,记下那一行;
2. 认领 W2、**只做一次带声明的交接**(W2 不完成)→ `done` 仍然是 1;
3. 分母没动过,那一行还变了,就只能是分子变的。

外加一条前提断言(`completed_items == ["W1"]`),否则"分母不变"这个前提
自己就没人守。

两个方向都验过:

- 把 `contract_changes += 1` 换成 `pass` → **红**(这是打回要的)
- 把那一行换成 `"%d 次" % contract_changes`(没有分母的合法写法)→ **仍绿**
  (不钉 `_fmt_rate` 的格式)
