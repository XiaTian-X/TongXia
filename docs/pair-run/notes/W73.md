# W73 笔记 —— 契约形状检查

## spec(tester)

用例在 `tests/conformance/test_v1_contract_shape.py`,36 条,写完时 21 红 15 绿。绿的是对照组与守"不查"的:有代码块 / 波浪线围栏 / 填了数据行的表不警告、
子小节里的代码块与围栏里的 `#` 行不截断、关键词只在代码块里或大写也算、依据待核实与已完成工作项引用的不查、不加配置照样通过、严格模式下合格契约照样通过、
漂移在函数名存在于 `src/` 或 `tests/` 时不警告、feature 项不查漂移、抽不到标识符不查。

契约不用补。读法写在开工前审查的补记里。

### 用例怎么造的,实现时要知道的

- 每条用例以人类身份提交自造的 PLAN 与契约,另写一份 dev 的审查结论(`docs/reviews/setup-verification-dev.md`,点到每个被引用的小节),以 dev 跑 `verify-setup --drafter other`。
- **按条断言**:stdout 里"脚本能查的都通过了"之前那一段按 `\n  [警告] ` / `\n  [失败] ` 切开,提到小节名(`部件构造`)的那几条就是这一节的结论。
  所以三条检查要走既有的 `warn()` / `bad()` 出口,一条检查一次调用;小节名要原样出现在文案里。
- 只造"只有一条检查会触发"的小节:有关键词没形状 → 只能是形状那条;有形状没关键词 → 返回或错误;两样都有 → 只可能是漂移。只有散文的两条都触发,只断言至少一条。
- 断言的文案词:工作项 ID(`W1`、两个工作项引用同一节时 `W1` 与 `W2` 在**同一条**里)、非严格模式下形状那条含 `strict_contract` 与 `阻断`、
  漂移那条含抽到的标识符(`make_widget`、`GadgetFactory`)与工作项 ID(`C1`)且**不含** `阻断`、非布尔值失败含 `strict_contract`、`true`、`false`。
- 严格模式下失败的那条要出现在 `[失败]` 里、退出码非零;漂移在严格模式下仍在 `[警告]` 里、`[失败]` 里没有提到这一节的。
- 原样复制的模板:在一个 Python 布局的空仓库里跑 `init`,把它铺出来的 `docs/PLAN.md`、`docs/CONTRACT.md` 原样提交到 harness 仓库,断言 `<小节名>` 有警告且含 `W1`。
- 契约模板补「不做」:`init` 铺出来的契约里 `**不做**` 出现在 `**边界情况**` 之后。
- 漂移查的是**已跟踪**文件:用例放进 `src/` / `tests/` / `docs/` 的文件随 PLAN 一起提交。契约本身就含着那个函数名 —— 漂移不能把 `docs/` 算进去,否则永远查不出。
  `tests/probe.py` 放了个同名的 `src/probe.py`,因为 harness 的测试命令要求两边同名。
- 我在 `.pair/scratch/` 里写过一份参考实现(已删),36 条全绿;按契约列的八个变异点加我自己的十一个探针,19 个都被抓到。

### 没写用例的

- 小节标题本身算不算正文、关键词按整词还是子串、代码块里的 HTML 注释、`strict_contract: null`、混着 feature 与 cover 引用同一节时漂移那条列哪些工作项 —— 见开工前审查的读法。
- 变异点等实现落地后在 review-impl 登记(锚点要是 `pair.py` 里的真字面)。

## impl(dev)

- 小节全文另写了 `contract_sections_full`:找标题时把围栏内容换成**等长**空白(`_blank_fenced_blocks` 换成等量换行,偏移会错位,不能拿它的位置去切原文),切的是原文。
  标题行本身不在正文里,子小节的标题行在。
- 形状、关键词、标识符都在去掉 HTML 注释之后做;表格只在围栏外找。分隔行 = 只由 `|-: ` 组成、含 `|` 与 `-`,且上一行含 `|`;数据行到第一行不含 `|` 为止。
- 三条检查在逐项循环之后按小节各跑一次(`shaped_refs` 收集可断言小节的引用者),所以同一节只报一次;漂移的工作项列表只列 cover/refactor/bug 那几个。
- 漂移的名字匹配用 ASCII 的前后断言而不是 `\b`:`\b` 在中文紧挨着名字时不成立("调用make_widget")。去掉的名字含常见内置调用,理由见开工前审查补记。
- 本仓库自己的契约:本轮新节有表格,过;`understand 模式`、`决策的推翻` 这类旧节只有散文,会被报 —— 但它们只被已完成工作项引用,不查。以后立项写契约要带表或代码块。
- 变异锚点留给 review-impl:`if ok:` 收集那行、`strict = cfg.get("strict_contract") is True`、`if "|" not in row:`、`_HTML_COMMENT_RE.sub`、`drift = [i for i, t in users if t in DRIFT_TYPES]` 等都是单次出现的字面。
