# W7 — spec 回合的笔记

`cover`,全程绿。三条测试缺口 + 变异点从 71 补到 **80**,全套 316 条绿,
`mutation_check` **80/80 全部被抓到**。

## 一、三条缺口都用变异证过，不是"看着像守住了"

| 注入的错误实现 | 红的用例 |
|---|---|
| `is_orphan` 去掉 `ignore_paths` 排除 | **只有**新写的「命中 ignore_paths 的文件不算孤儿」 |
| ignore 清单首行不给总数 | 「首行含不受保护的文件总数」+ 截断那条(它靠首行的总数定位块) |
| `PATH_LISTING_LIMIT` 调成 10000 | **两侧截断用例都红** —— 正说明 `ignore_paths` 这侧原来没人守 |
| 只列前十但补的是**总数**而不是剩余数 | 两侧截断用例都红 |

第三条那次"两侧都红"是这一项最直接的证据:同一个变异,孤儿那侧本来就红
(`TestOrphanTruncation` 守着),`ignore_paths` 这侧原来是绿的。

## 二、判据都照 W4 那条决策写的，没有一条用 assertIn 扫整份输出

- **孤儿/ignore 互斥**:判据是"整份输出里只出现**一次**",不是"在某一段里"。
  原来的 `TestIgnorePathsListing` 只断言它出现在"不受边界保护"那段,
  **没断言它不在孤儿清单里** —— 所以拆掉排除那一句,10 条一条都不红
- **截断的剩余数**:结构定位(块内既不含总数、也不是被列出路径的那一行),
  不数名字前缀、不断言措辞、更不 `assertIn("2")` ——
  首行"12 个文件"里就含 `2`,那是恒真的。这条坑 W4 时栽过一次,原样照抄它的解法

## 三、超出验收标准的部分：W10 的四个变异点

PLAN 的 ④ 只列了五个(W3 两个 + W4 三个)。我另加了 **W10 的四个**:

```
拆掉裁判副本的逐字节比对   -> test_副本当裁判时也要拦
裁判副本改成 strip 后比    -> test_只差一个空白字符也要拦
裁判正本改用 __file__      -> test_副本当裁判时也要拦
拆掉重钉后 sha 的 strip    -> test_写进正文的值不带换行
```

**理由**:W10 的 spec 回合我补不了它们(锚点是 `pair.py` 的字面源码,
那时实现还不存在,写死锚点就是断言实现细节、撞规则 4),当时的提议就是
"归进 W7"。W7 是这一轮唯一一个既归 tester、又在 W10 之后、名字就叫
"补变异点"的工作项。**不在这里补,就是把缺口再推给下一轮** ——
而"每一轮都推给下一轮"正是 W4 那条决策要治的病。

**如果你判它是超范围,打回,我拆掉。** 我不认为验收标准里的"五个"是上限,
但那是我的解读,不是契约写的。

## 四、这九个点不会重蹈"临时脚本变死代码"

你在 W10 记的那条(临时变异脚本在实现变化后安静全绿)对登记在册的变异点
不成立:`test_变异点仍能匹配到源码` 强制 `count(old) == 1`,锚点一失配
立刻红。**这正是"把探查搬进 `MUTATIONS`"的价值**,也是我把 W10 那四个
搬进来的第二个理由。

## 五、否掉的

- **给"孤儿/ignore 互斥"写成"断言它不在孤儿块里"** —— 要先定位块边界,
  而块的先后顺序契约明写"不作规定"。数出现次数不依赖顺序
- **`ignore_paths` 用 `"build/**"`** —— 改用 `"build"`(不含通配符,
  走目录前缀语义),和仓库现有配置风格一致,也少一层 glob 转义的可能出错点
- **把越界文案的逐行标注也做成变异点** —— 我只做了末尾那句分情况的 tail。
  逐行那句和 tail 同真同假的时候多,两个变异点会有一个是冗余的;
  tail 是契约点名要改的那句("请撤销这些改动后重试"),取它

## 行为来源

这一项断言的三条行为,契约「路径归属的可见性」都逐字写了,所以契约是主依据;
但我没有只读契约就下断言,每一条都对着实现和实际输出核过。

**读了什么**:`is_orphan`(四类排除,`ignore_paths` 那句在第二位)、
`render_path_listing`(`lines = [head] + paths[:limit]`,超限再补一行剩余数)、
`cmd_verify_setup` 里并排的两个 `warn(render_path_listing(...))` 块 ——
孤儿那段的表头逐字写着"也不在共享/冻结/ignore_paths/记忆层里",
而 `ignore_paths` 那段的表头写着"任何角色、任何阶段都能写"。两段语义相反,
这就是第一条用例要守的东西。

**跑了什么、看到什么**:在临时仓库里造 `build/缓存.json` 并入库,
跑 `verify-setup --drafter other`,数它在整份输出里出现几次 —— 现状是 **1 次**。
截断那条造 12 个 `build/产物NN.json`,输出里被列出的是 **10 个**,
另有一行含 **2**。

**四个变异证明这些数字不是巧合**:去掉 `is_orphan` 的 `ignore_paths` 排除 →
那个文件出现 **2 次**;首行去掉 `%d` → 首行不含数字;`PATH_LISTING_LIMIT`
调成 10000 → 列出 12 个;剩余数改成打印总数 → 那一行消失在判据外。
每个变异都只让该红的红。

## 我冻结了哪些可疑行为

**没有把可疑的产品行为焊进测试** —— 三条断言逐条对过契约,措辞、顺序、
`PATH_LISTING_LIMIT` 的具体值我都没有断言(顺序契约明写"不作规定")。
但有两件事必须说清楚,因为它们是我**在写的过程中差点焊进去的**:

**① 我险些照抄一个弱判据,然后把它对称地复制到新的一侧。**
孤儿那侧原有的剩余数断言是 `any("2" in l for l in rest)` —— **子串比**。
一个把剩余数算成 `len(paths) + 8` 的错误实现会打出"还有 20 个",
而 `"2" in "20"` 为真,**它照样绿**。我第一版就是原样复制了这个写法。
改成取整数集合再比(`re.findall(r"\d+")` → `assertIn(2, nums)`),
并且**两侧一起改** —— 只改新的一侧,就是上一个工作项里 dev 挑出我的
"改了一半的规矩"。新增变异点「剩余数打成总数」守这条,实测:
打印 20 时两侧都红,打印总数时两侧都红。

**② `len(listed) == 10` 把契约里的 10 固化成了可观测量。**
这是有意的:契约逐字写了"超过 10 个时只列前 10 行"。但要说清楚代价 ——
将来若改成可配置,这两条用例会红,而那时**红得对**(契约变了,
断言就该跟着变),不是误伤。记在这里免得有人把它当脆弱断言删掉。

**其余逐条对过契约,没有别的。** `ignore_paths` 与孤儿两段的先后顺序、
两段的具体措辞、`build/` 这个目录名 —— 一条都没进断言。
