# W51 — tester 的 spec 回合

## 用例 `test_v1_make_demo_git_fail.py` 7 条,今天红 4 条

假 git:PATH 最前一个 sh 脚本,第一个不以 `-` 开头的参数等于要失败的那一步时往 stderr 打一句固定文字、退 128,其余转给真 git
(`shutil.which` 起测前找好)。固定文字里不含 init / add / commit,免得替"点名是哪一步"作答。

- 红:`commit`、`init`、`add` 各自失败时 —— 退出码非 0、没有 `Traceback`、假 git 的原话在输出里、点名这一步(三条);
  `commit` 失败时给出 `user.email` 与 `commit.gpgsign` 两个原因(一条)。
- 绿(守着):假 git 什么都不拦时照常生成(前提,防转发坏了让"失败"白白成立);失败后目标目录与已复制的样板留着;
  `init` 失败时不点名 `commit`。

**"点名"按 ASCII 词边界判**,`commit.gpgsign`、`-` 相连的不算 —— 修好之后输出里一定有 `commit.gpgsign`,按子串找 `commit` 会被它满足。
中文紧挨着英文算边界(字符类写死 ASCII,`\w` 会把汉字也算进去)。

## 参考实现(scratchpad,不提交)

`git_step(target, args)`:捕获输出,失败时 stderr 打"git <步> 失败(退出码 N)。git 的原话:…",`commit` 再加两个原因,说目标目录留着,
返回假;`main` 里三步各自 `return 1`。全套 628 OK。

探针(各只红该红的):
- 不论哪步都打"git init/add/commit 之一失败" → 只红 `init 失败时不说是 commit`;
- 失败时 `rmtree` → 只红"目标目录留着";
- 不给原因 → 只红"两个原因";
- 不转述 git 的 stderr → 四条"点名+原话"全红。

# W51 — dev 的 impl 回合

- 新函数 `git_step(target, args)`:捕获 git 的输出,失败时往 stderr 打"git <步> 失败(退出码 N)。git 的原话:…",`commit` 再给两条最常见原因,
  最后说目标目录留着没删、修好之后删掉再重跑;返回假,`main` 里 `return 1`。`init` 失败就不再跑 `ensure_identity`。
- `init` 与 `add` 不给原因 —— 它们失败多半是目录或磁盘的问题,猜原因不如给 git 原话;这也让"init 失败时不说是 commit"那条天然成立
  (原因文字里只有 `commit.gpgsign`,带点,按你的词边界不算点名)。
- 身份那条原因除了 `--global`,还给了 `GIT_AUTHOR_*`/`GIT_COMMITTER_*` 环境变量的出路 —— 不想改全局配置的人有路走。
  签名那条写的是"或者只在这个目录里关掉",是给用户的选项,不是脚本替人关(与"不强关签名"不矛盾)。
- `tracked_demo_files` 与 `ensure_identity` 里的 git 调用没动(前者问不了 git 有回退,后者本来就容错)。路线图第 4 条标 ✅。
- 全套 628 绿;手工用假 git 让 commit 失败跑过一遍,输出没有堆栈、退出码 1。
