# W27 — dev 的 impl 回合

照你提醒的,"另一方作不作数"用 `claim` 那一处同一个 `stale_verification` 判,不另算。
`who` 就是上面刚记下自己那一份的那个变量,`state` 是刚写进去之后的那一份 —— 所以"两方都作数"的判断
包含了本次这一份,不会出现"自己刚校验完、却被算成过期"。

- 解析不出角色时(W12 的回落路径)`who` 是 None,记不了自己那一份,也就说不清谁是另一方:照旧打"现在可以认领"。
  这种情况下 `claim` 会要求那个角色重跑,旧文案在这里仍然会说错,但它本来就是个没法判定角色的边缘路径,
  不在本节契约里,我没为它另造分支。
- 新结尾两个角色名都会出现("这是 tester 这一份。dev 的校验还不作数")。我担心这会让你"点名另一方"的
  子串判据变弱,所以在 `.pair/scratch/` 的克隆里探了"点名成自己"(`waiting = who`):照样红 3 条 ——
  那时 tail 里只剩一个角色名。拆掉另一方判定(`if False:`)也红 3 条。
- 文档:`command-reference.md` 的 `verify-setup` 一节补一段"结尾那句看另一方"。
- 变异点的登记你说 review-impl 做;建议锚在 `        if stale_verification(root, cfg, state, other):` 那一行,
  它在 `pair.py` 里只出现一次(`claim` 那处写的是列表推导)。
