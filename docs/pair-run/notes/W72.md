### 用例依赖的口径

- 开场:`discuss --understand --proposal <提案> "<为什么>"`;`state["discuss"]` 里 `mode == "understand"`、`speeches == 1`,`item` 为 None;
  正文第一行以 `understand=open role=tester` 开头。idle 不带 `--understand` 的拒绝文案要含 `--understand`。`discuss_limit = 0` 时照样能进。
- 讨论回合:`speeches` 变成 2,正文第一行以 `understand=reply role=dev` 开头。
- `resume`:`resume "<结论>" --no-draft "<理由>"`(结论在前,旗标在后)。只有两次发言、本回合没追加提案 → 拒,状态与提交数不变;
  放行后 `phase == "idle"`、`discuss` 为 None、`discussed` 为空、轮到 tester,正文第一行以 `understand=resume role=tester` 开头,`--no-draft` 时正文含 `未产出草案(已声明): <理由>`。
- 合规草案(a):正文含提案路径与最后一个 diff 块的哈希(`sha256` 前 16 位,与 W68 `block_hash` 同),输出含 `ratify`;之后人类 `ratify` 把契约新节与 `[cover]` 项落地。
- 草案的拒绝用例逐条只违反一项:缺 tester 签字;tester 签了第一块之后又追加了第二块;diff 多碰了一份 `docs/其他.md`;契约只加了一行「补充」没加 `## ` 小节(PLAN 的 cover 引用 `W1`);
  `依据: 人类定稿`;`考古观察@deadbeef0123`;PLAN 除了 cover 还加了一个 `[feature]`;契约加了两节、cover 只引用了一节。
- 草案的小节写法:`## <标题>` 下一行空行,再 `- 依据: 考古观察@<完整 sha>`;cover 项三行,`对应契约:` 后是 `` `docs/CONTRACT.md` → <标题> ``。
- `status`:dev 在开场之后(自己第一次发言之前)跑 `status`,输出含"独立"。
- `report`:走完一次 understand(`--no-draft` 收尾)之后,"讨论"那一行是 0。

## impl(dev)

- `cmd_discuss` 多一个 `understand` 分支:只换进入条件(idle)、跳过额度、状态加 `mode`/`speeches`、第一行 `understand=open`。其余(提案、开场陈述、散文、决策校验)走原来那段代码,没有复制。
- 额度那段整体缩进到 `if not understand:` 下面,而不是把条件并成 `if not understand and used >= …`。并成一行会撞掉既有变异点「讨论_每项一次不查」的锚点。缩进之后锚点仍是原文的子串,而且只出现一次。
- 草案检查放在 `understand_draft_problem`,按顺序查:签字齐 → 只碰 PLAN/契约 → 有新增小节 → 每节有考古观察且 sha 真实 → 只加 cover → 每节有 cover 引用。新增行按 `+++ ` 头切段(`_diff_added`)。
  局部变量叫 `last` 不叫 `block`:`    block = blocks[-1]` 是 ratify 那个变异点的锚,重名会撞成两处。
- `--no-draft` 用在普通讨论上会被拒(契约没写)。不拒的话,一个本来没有意义的旗标会被默默吞掉。
- 签字只查齐不齐,不查是谁的回合提交的。resume 时 tester 的签字还在工作区,要随这次提交一起进;溯源交给之后的 `ratify`。
- 探针(项目内 `.pair/scratch/`,已删)15 个全被抓:契约列的九个,加上不查别的文件、不查新增小节、不查考古观察、额度照算、speeches 不加、签字看第一块。

## impl 第二回合(dev,按 review-impl 打回)
