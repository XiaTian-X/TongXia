# W62 — tester 的 spec 回合(cover;`run.py` 的实现与用例都由我写,dev 在 review-test 评审)

## 带声明改的契约(开工前审查 ⑲)

`FAIL:` / `ERROR:` 行两种形态都认(3.11+ 括号里是完整 ID,3.10- 只有 `模块.类`),subTest 只取第一对括号。理由见 W62 决策。

## `run.py` 改了什么

- `FAIL_LINE` 与 `failed_ids(outputs)`:各分片输出里红着的用例 ID(两种形态)。
- `junit_xml(ids, failed)`:收集到的每个用例一个 `testcase`,`classname` = ID 去掉最后一段、`name` = 最后一段,红的带 `<failure/>`;属性值用 `quoteattr` 转义。
- `run(ids, jobs, junit=None)`:跑完、在打印汇总之前写报告(目录不在就建);`--junit-xml 路径` 传进去。不给参数时一行代码路径都不变。
- 文件头的用法里加一行。

## 行为来源

- `unittest -q` 的失败头:3.14 本机实测 `FAIL: test_x (mod.Cls.test_x)`、subTest `… (i=1)`;3.10- 的形态取自 `mutation_check.py` 里 `FAIL_RE` 上方的注释与它的 `_ids`(第十几轮为缓存写的,同一个问题)。
- `pair.py` 的读法(`junit_failures`、`read_report`)是 W58 落地的,用例直接调它们,不另写一份读法。

## 我冻结了哪些可疑行为

- **`-q` 看不到跳过,收集到的都写成跑过**:契约原话。启用 W61 之后,本仓库里一条 `skipTest` 的用例在报告里是"跑过且绿"—— 它变成跳过时 W61 看不见。
  本仓库会 skip 的(问不了 git、Windows/root)在本机日常运行里都不 skip,所以今天不影响基线;记在这里,将来要拿跳过信息得改分片方式(契约「不做」)。
- **某个分片整体崩溃时报告与退出码对不上**:崩溃的分片没有 `FAIL` 行,报告里它的用例都是绿的、退出码非 0 —— 交给 W58 的 ⑰ 降级。契约原话,不另处理。
- **`setUpClass` 之类的 `ERROR:` 行**(括号里是 `模块.类`、方法名是 `setUpClass`)会拼出一个不存在的 ID `模块.类.setUpClass`,而那个类的用例在报告里是绿的。
  它不在收集到的用例里,所以不写进报告 —— 报告"无红"、退出码非 0,同样交给 ⑰。本仓库没有 `setUpClass`。

## 用例 `test_v1_run_junit.py` 10 条,全绿(cover)

解析五条(3.11+、3.10-、ERROR、subTest 参数、不在行首不算);端到端两条(小模块的报告被 `junit_failures` 读出、ID 与 `--list` 一致;报告目录不在也能写);
临时目录里一份 `run.py` 跑有红有绿的模块三条(红 / error / subTest 带 failure、绿的不带、退出码非 0;`read_report` 不降级;不给参数不写文件、汇总行格式照旧)。
探针:只认 3.11+ 形态 → 解析的三条红。全套 750 OK。
