# W20 — dev 的 impl 回合

你在 spec 回合补的"分母跟着起点走"与"树对象也拒"我同意,照着实现。

## 怎么实现的

- `_handoff_log(root, since=None)`:有起点时 `git log --reverse <sha>..HEAD`。
- 起点用 `rev-parse --verify -q <rev>^{commit}` 解析;解析不出 → `die`,文案点名那个起点。
  **`^{commit}` 不能省**:`check=False` 会把"`<tree>..HEAD` 报错"吞成"区间为空",静默报一张全零的表。
- 区间里的完成数 `finished`:正文里有 `phase=<阶段> -> idle ` 的交接(只在表头计入的那批里数)。
- `per_done = finished if since else done`,两条声明比率与它们的偏高判定都用它。
- 表头加一行"起点:<sha 前 12 位>(只作用于从提交里数的行;……照读状态)"。
- 文档:`command-reference` 的 `report` 一节补 `--since`(含下面那条"旁支"的注意)、路线图 22 标 ✅。

自己跑的:**全套 460 全绿**。

## 探针:9 个里 7 个抓住,2 个存活

| 拆掉 | 红 |
|---|---|
| 忽略 `--since` / 区间不生效 | 各 9 |
| 不限定为提交 | **只有**树对象那条 |

| 分母照读状态 | 5 |

| 表头不写起点 | **只有**交接与认领那条 |
| **偏高判定照读状态** | **0** —— 你笔记"没钉的"第一条已声明 |
| **不带 `--since` 时分母也用区间完成数** | **0** |

**第二个存活不是等价变异。** 测试仓库里"状态里的完成数"与"历史里推进到完成的交接数"永远相等,所以测不出来;
**本仓库这两个数不相等**:状态里 17,历史里 18(实测)。那个变异会让不带 `--since` 的 `report` 在本仓库上
从 `17` 变成 `18` —— 契约写的是"不带 `--since` 时照旧读状态、输出一个字不变"。
**候选**:人类提交一份 `completed_items` 比历史里多或少一项的状态文件(或用 `old_impl_commit` 那种空提交造一次
"推进到完成"的交接),断言不带 `--since` 时两条比率的分母是状态里的数。

## 契约外的一处,实测成立:旁支上的起点会静默统计差集

我在开工前的补记里提过,这次在克隆里跑实了:从 `HEAD~3` 拉一条旁支、提交一次,拿那个提交当 `--since` ——
**它不是 HEAD 的祖先,`report` 照样退出 0、报交接 3 次**,读的人以为是"那个提交之后",实际是两条分支的差集。
契约只写了"解析不成提交时拒绝",所以**我没有实现拒绝**(那是没有用例的新行为),只在命令参考里写了注意。
修法一行:`git merge-base --is-ancestor <sha> HEAD` 不成立就拒。要不要做由你判断 —— 要做就是 spec 回合带声明补一句。
