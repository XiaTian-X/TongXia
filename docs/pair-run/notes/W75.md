# W75 笔记 —— review-impl 的测试缺口

## spec(tester)

用例在 `tests/conformance/test_v1_test_gap.py`,17 条,写完时 8 红 9 绿。绿的九条全是拒绝类:现在 argparse 不认 `--test-gap`、直接以退出码 2 拒绝,
所以它们此刻的绿不说明什么 —— 区分力靠参考实现与探针证明(见下)。

契约不用补。读法写在开工前审查的补记里。

### 用例怎么造的,实现时要知道的

- 布局照 `test_v1_review_append`:tester 拥有 `tests` 与 `checks`,`checks/mutations.txt` 是 tester 的 `review_append_paths`(已在 HEAD 里)。
- **红用例 = 新增 `tests/W1-缺口`**(harness 的测试命令要求 `src/` 有同名文件,没有就红);**绿用例 = 改已有 `tests/W1` 的内容**(布局不变)。
- 被拒时一律断言提交数与 `.pair/state.json` 逐字节不变。断言的文案词只有两个:套件绿时 `changes --test-gap` 被拒含 `approve --test-gap`;refactor 被拒含 `[cover]`;
  另外改写登记表已有行被拒含 `追加`(既有的只追加文案)。
- **几条拒绝用例特意把"别的防护"让开**,否则拒它的不是本节:
  - dev 在 review-test 带旗标那条,dev 同时改了 `tests/W1` —— 不改的话"必须补了用例"那一道替"只限 tester"挡了,拆掉角色限制照样绿(探针证实过,已改);
  - 只删测试那条带 `--allow-deletion`,免得删除测试防护先拒;
  - 改写登记表那条同时补了真用例,免得"必须补了用例"先拒。
- 提交正文断言含 `测试缺口:` 与说明原文;全流程那条在 review-test 那一刻读 `changes_count == 1`,DONE 之后不依赖。
- 简报只断言 review-impl 的 `status` 输出里有 `--test-gap`,不断言措辞。

### 参考实现与探针

`.pair/scratch/` 里写过一份参考实现(已删),17 条全绿。探针 11 个,10 个被抓:契约列的七个(不限 review-impl、不限有 review-test 的流程、`changes --test-gap` 不要求 RED、
不要求动测试、只追加文件算作补用例、带旗标不放开 tester 路径、空说明放行),加不限 tester、删除算补用例、正文不写 `测试缺口:`。
没抓到的那个是我的探针写弱了(只删了简报里 `changes` 后面的 `--test-gap`,同一行的 `approve --test-gap` 还在),不是用例的缺口。

### 没写用例的

- `affected_test_cmd` 配了时新用例会不会被选中(harness 不配它,契约没说)。
- 删除测试要 `--allow-deletion`、评审证据、异议落纸、死锁闸照旧:契约写"其余检查不变",既有用例守着,不另写。
- 变异点等实现落地后在 review-impl 登记。
