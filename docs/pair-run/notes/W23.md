# W23 — tester 的 spec 回合

## 用例 `test_v1_scratch.py` 6 条,今天红 5 条

- `init` 写的 `.gitignore` 含 `.pair/scratch/`;本仓库 `.gitignore` 也有(④)。
- 评审回合、impl 回合在 `.pair/scratch/` 写副本与探针脚本,`handoff` 放行、不进提交。
  **harness 的 `.gitignore` 是手写两行**,所以先以人类身份把 `PAIR.GITIGNORE_LINES` 原样追加提交 ——
  手加 `.pair/scratch/` 就与实现无关了。
- `verify-setup` 的"未提交的代码改动"只列角色路径:默认布局下 `.pair/scratch/` 不是角色路径,那条恒绿。
  改用 Go 的 glob 布局(`**/*.go` 命中副本里的源码),并配一条对照组(仓库里真的源码照样被列出,今天绿)。

**更正我开工前补记里的一句**:`test_gitignore_跟得上_GITIGNORE_LINES` 比的是**样板项目**的 `.gitignore`,
不是本仓库的 —— ④ 不是自动被守的,所以单独加了一条。你加进 `GITIGNORE_LINES` 之后,样板项目的 `.gitignore`
也要跟上,否则那条既有用例会红。

## 参考实现与探针

`GITIGNORE_LINES` 加 `".pair/scratch/"`、本仓库与样板 `.gitignore` 各加一行:全套 489 OK。
去掉 `GITIGNORE_LINES` 那一行 → 4 条红(init、两条 handoff、verify-setup);本仓库那条是数据检查,不随变异。

## 没钉的

- 文档(`references/rules.md` 的示范、条目 26 的两句):契约写明不写成用例。
- 测试命令会不会扫进 `.pair/scratch/` 里的副本测试:pytest 默认不进点目录、`go test ./...` 跳过点目录、
  unittest discover 只进包;但 harness 的 Go 假测试命令是 `glob('**/*_test.go')`,会扫进去 —— 真实项目的
  自定义测试命令同理。值得在 `rules.md` 里提一句"副本里的测试文件可能被自定义测试命令扫到",不写成用例。
