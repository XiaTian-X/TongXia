# W56 — tester 的 spec 回合

## 口径(契约交给 tester 定)

- 字段 = 行首的 `**名字**`。标准五项 背景 / 决策 / 理由 / 代价 / 被否掉的方案,**名字恰好相等**才算有:`代价与已知边界`、`理由与取舍`、
  `理由:填模板的……` 这类变体都算缺那一项(契约要求变体也点名)。`相关`、`已知不足` 之类附加字段不管。
- "否掉的方案"与"被否掉的方案"同算一项 —— 全体条目都写前者,是一处统一的命名差:偏差说明里说一次(用例要求出现不带"被"字的"否掉的方案"),不逐条点名。
- 偏差说明 = 第一个 `## ADR-` 之前的部分。每条有偏差的 ADR,编号要在那里**逐个**出现;"ADR-009 到 ADR-019"不算点名中间几条;`ADR-0100` 不算点名 `ADR-010`。
- 按这个口径实扫 14 条:ADR-006、009、010、012–019、021 缺"否掉的方案";ADR-020 缺"理由""代价""否掉的方案";ADR-022 缺"理由"。

## 用例(`test_docs_consistency.py` 末尾两个类,12 条,今天红 2 条)

- 红:有偏差的 ADR 都在偏差说明里被点名;偏差说明讲了"否掉的方案"这处统一命名差。
- 绿(守着):口径在真实数据上挑得出偏差(ADR-020 / 022 / 006 / 001 四格钉死,防口径坏成恒绿);
  **ADR-001 到 ADR-024 原文不许改**:各节去掉结尾分隔线与空白后拼接的 sha256 钉住 —— 把变体名改成标准名也能让第一条绿,那正是契约不许的修法。
  不用 `git show` 比对,因为 CI 是浅克隆。结尾分隔线不算原文:以后追加 ADR-025 时前一节多一条 `---` 不会误红(实测)。
- 绿(口径八格):五项齐全不用登记;新加一条缺字段又没登记 → 红;登记了不红;变体名算缺;加粗不在行首不算;两种"否掉的方案"同算;区间不算逐个点名;编号整段匹配。
