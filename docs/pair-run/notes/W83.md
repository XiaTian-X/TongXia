### 用例怎么造的,实现时要知道的

- **被拦的项**:全用人类提交的 PLAN 与契约造,不碰判定代码。
  - 待澄清:feature 项小节正文里有 `[待澄清: …]`。
  - `依据`:写成 `已有文档 docs/api.md §3(待核实)`。
  - refactor:不写 `保护测试`。
  - 类型非法:PLAN 写 `[chore]`。
- **断言的关键词取自 `claim` 拒绝文案的头一行**:`待澄清`、`依据`、`保护`、`非法`,外加工作项 ID。
  - 补记里写的是"标记原文"与"保护测试",写用例时发现这两样不在头一行里(头一行只说"还有 N 处待澄清的标记"、"必须声明保护它的测试")。
    契约要的是头一行,所以照头一行改了关键词,以这里为准。
  - 每一行都断言不含"拒绝认领"(去掉前缀),以 `stop ` 开头,`strip` 之后无换行。
  - 两项被拦时断言半角 `;` 在行里。
  - 项的顺序、理由之外的措辞不断言。
- **类型非法**的拒绝不在 `check_item_preconditions` 里,而在 `cmd_claim` 里那句 `die`。契约说"与 `claim` 用同一份判定",怎么共用由你定;用例只看那一行里有 `非法` 与 ID。
- **只读**:每次 `whose-turn` 前后比提交数、`state.json` 文本、`git status --porcelain`,三样都不能变。
- **副本**:
  - 测试仓库里把 `.pair/enforcer.py` 写成 `pair.py` 加一行注释,以人类身份提交。断言理由里有"重钉"与"人类"。
  - 进行中那条先钉一致的副本、认领,再给正本加注释。
- **进行中**:认领 W1 之后人类改 PLAN 与契约,让 W1、W2 都被拦,断言照旧 `turn tester`;推到 impl 再拦,断言 `turn dev`。
- **idle 归 dev**:门禁打开,只有 tester 跑过 `verify-setup`,然后只改 PLAN(不改契约,tester 那份仍作数)。
  - 唯一的 refactor 项写了保护测试 → `turn dev`(对照);没写 → `stop`。
- **现有 stop 在前**:门禁打开、谁都没校验、唯一的项被拦 → 那一行含 `verify-setup` 且不含 `W1`。
- **文档**:只断言 `command-reference.md` §6.6(到下一个 `## ` 为止)里出现"认领"与"重钉"。
  - `protocol-spec`、`troubleshooting`、开放条目 62 不写断言,review-impl 时人工看。

### 参考实现与探针

在 `.pair/scratch/` 的副本里写了参考实现。做法是在 `cmd_whose_turn` 最后那句 `print("turn …")` 之前插一段,只在 `phase == "idle"` 时判:

- 先判副本(`judge_in_sync`)。
- 再遍历 `parse_plan`,跳过已完成项。类型不在 `ITEM_TYPES` 时自己拼一句"非法",否则调 `check_item_preconditions`。
- 一旦有一项放行就照旧;全被拦时取每条理由的头一行,去前缀与行尾冒号,`;` 连接。

24 条全绿。15 个探针全抓:

| 探针 | 抓到它的用例(之一) |
|---|---|
| 不判 | `test_refactor_没声明保护测试` |
| 进行中也判 | `test_进行中副本不一致_照旧轮到当前阶段的归属` |
| 进行中也判(只判认领、副本仍限 idle) | `test_进行中其余项和当前项都被拦_…`、`test_进行中到了_impl_照旧轮到_dev` |
| 已完成项也算 | `test_已完成项能认领_未完成项被拦_停下` |

## impl(dev)

- **类型合法并进了 `check_item_preconditions`**:原来在 `cmd_claim` 里单独 `die`,现在是函数里的第一条、返回同样的文案,`cmd_claim` 照旧 `die(refusal)`。
  契约要求与 `claim` 用同一份判定,这是最直接的办法;`claim` 对类型非法的行为与文案不变(`test_positive`、`test_v1_flows` 照旧全绿)。
  docstring 补了一句:`whose-turn` 也调它,所以它只能读、不能提交。
- **`idle_claim_blocked(root, cfg)`**(紧跟 `cmd_whose_turn`):先判 `judge_in_sync`,再对 `_plan_blocks` 里未完成的项逐个调 `check_item_preconditions`,遇到第一个放行的就返回 None。
  全被拦时拼 `<ID>:<头一行>`,去 `CLAIM_REFUSED_PREFIX`(`拒绝认领 —— `)与行尾半角、全角冒号,`;` 连接。没有未完成项返回 None(交给现有逻辑)。
- **判点**:`cmd_whose_turn` 篡改检查之后、`print("turn …")` 之前,只在 `phase == "idle"`。输出 `print("stop %s" % …)`,字面以 `stop ` 开头。
- 不进 `ENFORCEMENTS`。
- 文档:`command-reference.md` §6.6 四种改六种并分条说明;`protocol-spec.md` §3.3"idle 时轮到谁"后补一段;`troubleshooting.md` 新节;开放条目 62 标 ✅。
