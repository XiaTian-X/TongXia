# W1 笔记(tester)

## 为什么一次交了六条,而不是一条

否掉了"只写一条正常路径用例"的写法。头部四个字段**全都能被写死**:
只测一次 spec/tester/GREEN,一份返回常量的实现就能通过,而评审时才发现
就得整轮返工。所以每个会变的字段都配了一条反例 —— 角色配 dev、
测试配 RED、工作项配 `(无)`、阶段配 idle。六条是同一个头部的一组,
不是六件事。

## 这六条不是同一种红

五条红在"文件不存在"。`test_写过简报之后交接不被拒` 红的原因不同:
简报落在 `.pair/` 下,而 `.pair` 是冻结路径,写出来的第一份简报会被
边界检查判越界。**所以这一项至少要动两处**,不是"写个文件"就完事。

契约把这条单独列出来并且提了 `.pair/.last-full-test.log` 上真实踩过一次,
我照它钉了一条。怎么解决没写进契约,那是实现的事。

## 我拿不准的地方

契约说"文件末尾以一个换行符结束",我只断言了 `endswith("\n")`,
**没有**断言"结尾不是两个换行"。因为"没有记忆内容时整段连同前面那个空行
一起省略"是 W2 的验收标准,在 W1 里抢先把整份文件的字节钉死,会让 W2
的用例无事可做,也容易变成过拟合。如果评审认为这属于 W1,说一声,
我下一轮补。

## 这一轮没覆盖的

- `review-impl` / `review-test` 两个阶段的字段取值没单独测(阶段字段的
  取值面只测了 idle / spec / impl)
- `工作项` 字段只测了 `[feature]` 和 `(无)`,没测 bug / cover / refactor
  的形态
- 记忆段落整段 —— 那是 W2

# W1 笔记(dev)

## 回答上面那条"拿不准"

**你的判断是对的,不用补。** 我这一轮只写了头部,文件结尾天然就是一个
换行,`endswith("\n")` 已经把它钉住了。在 W1 里断言"结尾不是两个换行"
会提前锁死 W2 的形状 —— 而记忆段落到底怎么接在头部后面,正是 W2 要定的事。

## 那条"两处"其实是一处,但代价在别的地方

边界那条只需要把 `.pair/.last-brief.md` 加进 `PROTOCOL_LOGS`(边界检查
对协议自己写的文件的豁免名单),一行。但它带来一个你从测试里看不到的后果:

**`handoff` 用的是 `git add -A`,所以简报会被每次交接提交进去。**
`.last-test.log` 没这个问题是因为它在 `.gitignore` 里 —— 而 `.gitignore`
在仓库根,不在你我任何一方的可写路径下,**我们俩都改不了它**。

W3 的验收标准是"全新项目跑完 init 后 `.gitignore` 含这个文件",那管的是
`GITIGNORE_LINES`(给新项目用的),管不到本仓库。所以本仓库这轮结对期间,
每次交接的提交里都会多出一份变动的简报。不影响判定,但是噪音。

**这属于人类要处理的事**,我已经在下面记了。不打算在 W1 里绕开它 ——
绕开就得动 `.gitignore`,那是越界。

## 我没做什么

没有实现记忆段落。契约把整份文件都写明了,但 PLAN 把它切成三项,
W1 只要头部。多写等于替 W2 把活干了,而且 W2 的用例会无事可做。

## 留给人类的一件事

把 `.pair/.last-brief.md` 加进本仓库根的 `.gitignore`。
理由见上,我们俩谁都碰不了那个文件。

# W1 笔记(dev,第二回合)

## 打回的那条成立,我复现了

`item` 有值而 `item_type` 为空时,`render_brief` 写出裸 `- 工作项: W1`。
构造 `dict(DEFAULT_STATE, item="W1", item_type=None)` 直接跑出来:

    '# 回合简报\n\n- 角色: tester\n- 工作项: W1\n- 阶段: spec\n- 测试: GREEN\n'

契约只给了 `<ID> [<类型>]` 和 `(无)` 两种,这是第三种。改成
`state["item_type"] or "feature"`。

## 那句"终端头部也是这么写的"确实不是理由

我这段逻辑是照着 `item_label` 那几行抄的,所以缺陷也一起抄过来了。
评审的反驳成立:**终端输出不受这份契约约束,简报受。**"它不是终端输出的
副本"是契约原话,那句话同时意味着"也不许拿终端行为当挡箭牌"。

抄现有代码时把现有缺陷一起抄走,这是我这一轮真正的教训 —— 不是这一处
写错了,是我没有对着契约逐条核,而是对着旁边那段代码核的。

## 顺带发现:终端头部有同一个缺陷,但我不动它

`cmd_status` 打印的 `item_label` 也会写出裸 ID。它不归这份契约管,
改它属于契约外的顺手修 —— 那是评审该打回的东西。**记在这里,交给人类
决定要不要单开一个工作项。**

## 我没做什么

仍然没实现记忆段落(W2)、没做 `OSError` 降级(W3)、没动
`GITIGNORE_LINES`(W3)。评审确认了这个切分是对的,继续保持。
