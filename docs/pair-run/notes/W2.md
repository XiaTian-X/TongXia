## 给 dev 的三件事

### 1. 那两条现在绿的用例,是在等你的实现

`test_简报不含终端的分隔线与标题` 和
`test_没有记忆内容时整段连同前面的空行一起省略` 现在绿,只是因为简报里
还没有记忆段落。它们守的是**实现做过头**的两种形态:

- 把终端那段连 `=` 分隔线和标题一起抄进简报(契约点名这三行不写进去)
- 无条件写那个空行 / 记忆段落(idle 时该整段省略,连空行一起)

你实现完再跑一次,它们才真正开始起作用。**别把"现在是绿的"读成"已经满足了"。**

### 2. 有一处契约要求,我**故意没有**写测试

契约:「**`status` 提前结束时**(PLAN 全部完成)终端没有打印记忆注入,
简报同样没有记忆段落。」

W2 的验收标准里没有这一情形,规则 5 要求一回合只提一组紧密相关的用例,
所以我没写。**代价:这一点没有任何测试守着。**

它对你是个真实的坑:`write_brief` 在 `plan_all_done` 提前 return **之前**,
`memory_brief` 在**之后**。要让简报带上记忆段落,最直接的改法是把
`memory_brief` 提到前面 —— 那样 PLAN 全完成时简报里有、终端里没有,
**违反契约但不会红**。W1 的 `test_工作项全部完成时仍然写` 只断言头部,
拦不住它。

我会在 review-impl 回合按「同一次取值」核对这一点。先说在前面,免得你
按"测试全绿"交出来、我再打回,白烧一个回合。

### 3. 期望值用的是终端输出,不是写死的字符串

每条比对都是「终端注入了什么 → 简报里就该是什么」。这不是图省事:
契约的「不做」要求两处来自**同一次取值**,而写死期望值恰恰测不出
"两处各算一遍" —— 只要两次算法一样,结果也一样,写死值照过。
"两处必须逐字相同"是那条要求唯一可观测的形态。

所以**别为了让测试好过而在简报侧单独算一次**,那会同时违反契约的「不做」。

## 否掉的方案

- **写死每条用例的期望记忆段落文本** —— 理由同上,测不出两处各算一遍。
- **直接断言「不为简报单独计算」** —— 它是实现约束,不是可观测行为,
  规则 4 下我不能断言。只能靠 review-impl 读代码核对。
- **重复写「不是自己回合时不写/不清空」** —— W1 的 `TestBriefHeader`
  已有两条覆盖(验收标准第三块),规则 5 下不重复。
