## 这一回合带声明改了契约一处(开工前审查的 ④)

契约原文只说 `verify-setup` 那一侧"拒绝,不提交",**没说拒绝在哪一步**。`cmd_verify_setup` 的顺序是
结论检查 → 起草人声明 → 写 `setup_verified` → `save_state` → 提交;新检查插在写状态之后就是 W12、W15
两次治过的"状态对、退出码错",而且这回状态位留在工作区、下一次交接判它篡改。补写明**拒绝发生在写状态之前**,
可断言"拒绝后状态文件不变、HEAD 不变"。PLAN 加 ③′,决策 `## W18 — verify-setup 那一侧的拒绝必须早于写状态`。

## 用例:`tests/conformance/test_v1_review_immutable.py`,10 条

- **拒绝**(4 条):评审回合改写已提交的评审记录(文案要给出本回合该写的文件名)、删掉整份、改名、
  **dev 在 impl 回合改写**(不分角色不分阶段)
- **放行**(4 条):纯追加、新建文件、`ignore_paths` 豁免、子目录与非 `.md` 不管
- **`verify-setup` 一侧**(2 条):改写已提交的结论被拒**且状态文件与 HEAD 都没动**;往结论末尾追加照旧放行

## 判据的取舍

- **拒绝文案只断言三样**:那份文件的路径、本回合该写的文件名、"不要撤销"与"告诉人类"。
  契约写的是"如果这份改动不是你做的",PLAN 写的是"如果不是你改的" —— 两处措辞不同,取都有的部分。
- **`verify-setup` 那条同时断言状态文件逐字不变、HEAD 不变** —— 这是 ④ 那处修改的可观测形式。
- **追加那条用的是"往结论末尾补记"**:W13 起 tester 每次重跑都这么做,这条用例守的是这个既有用法不被打断。

# W18 — dev 的 impl 回合

你在 spec 回合带声明补的"拒绝必须早于写状态"我同意,照着实现。

## 怎么实现的

- **`review_rewrite_violation(root, cfg, path)`**:顶层评审 `.md` → 不在 `ignore_paths`/协议日志 →
  已在 HEAD → 有删除行,四条都过就返回拒绝理由。
- **`review_rewrite_hint(cfg, state, phase)`**:拒绝时补一句"本回合该写的是 `<review_file_for 算的那个>`"
  与"不是你做的就别撤销、别改名,告诉人类"。
- **`handoff`**:写权限边界那段循环之后**另起一个循环**逐条判(既有锚点 `if violations:` 那两行没碰)。
- **`verify-setup`**:判那份结论,**在 `state["setup_verified"] = True` 与 `save_state` 之前** `die`。
- **你提醒的那一处我照做了**:`blob_sha(...) is None` 与 `not has_rewrite(...)`,故意跟 W16 的两个锚点
  (`if not blob_sha(root, path):`、`if has_rewrite(root, path):`)岔开字面,免得它们各匹配两处。
  理由写进了函数 docstring,免得下一个人"顺手改整齐"。
- 文档:`protocol-spec` 不变量表第 6 行补一句(新检查挂在写权限边界这道上,不新增不变量,
  `HANDOFF_INVARIANTS` 与它的顺序一致性用例都不用动)、`references/rules.md` 评审一节一段、
  `troubleshooting` 新增一条、路线图 21 标 ✅。

自己跑的:**全套 434 全绿**。

## 探针

| 拆掉 | 红 |
|---|---|
| 检查从不触发(第一条 `return None` 恒真) | 四条拒绝 + `verify-setup` 那条 |
| 不看顶层范围 | **42 条** —— 范围一放开,笔记/决策等共享路径的正常改写全被拒 |
| 不豁免 `ignore_paths` | **只有** `test_ignore_paths_豁免` |
| 不看删除行 | 12 条(纯追加的正常用法全被拒) |
| `handoff` 一侧不判 | 四条拒绝 |
| `verify-setup` 一侧不判 | **只有** `verify-setup` 那条 |
| **真的把拒绝挪到 `save_state` 之后** | **只有** `verify-setup` 那条 ✅ |
| 不看"已在 HEAD 里" | **0 —— 等价变异**,与你 PLAN ⑥ 的判断一致,不登记 |

**我第一次探"拒绝挪到写状态之后"探错了**:把它挪到 `state["setup_verified"] = True` **之后**、
`save_state` 之前,那是内存里的赋值,磁盘没动,当然 0 红。挪到 `save_state` 之后才是你那条用例守的东西 ——
重探之后**只有它红**。记在这里:这类"顺序"变异,锚点要挪过真正落盘的那一行。

## 一条判据比它声称守的性质宽(不打回,留给你判断)

`test_评审回合改写已提交的评审记录被拒_文案给出该写的文件名` 里
`self.assertIn("W1-review-impl.md", r.text)` **恒成立**:被改写的那份文件本身就叫
`docs/reviews/W1-review-impl.md`,而拒绝清单必然把这个路径打出来 —— 我把 `review_rewrite_hint`
里"本回合该写的是 …"整句删掉,**全套 0 红**。

**候选形状**:让"被改写的文件"与"本回合该写的文件"不同名 —— 在 review-impl 里先打回一次
(`changes_count` 变 1),此时简报算出的是 `W1-review-impl-2.md`,再去改写 `W1-review-impl.md`,
断言文案里出现 `-2`。那时删掉那句就会红。我 review-test 会带这个形状打回,除非你先补。

## 锚点:请在 review-impl 当场登记

| 名字建议 | old | new |
|---|---|---|
| 评审记录改写检查不看顶层范围 | `    if not _review_top_level(cfg, path):` | `    if False:` |
| 评审记录改写检查不豁免 ignore | `    if matches_any(path, cfg["ignore_paths"]) or path in PROTOCOL_LOGS:` | `    if False:` |
| 评审记录改写检查不看删除行 | `    if not has_rewrite(root, path):` | `    if False:` |
| handoff 不判评审记录改写 | `        rewrite = review_rewrite_violation(root, cfg, path)` | `        rewrite = None` |
| verify-setup 不判结论改写 | `    rewrite = review_rewrite_violation(root, cfg, report_rel)` | `    rewrite = None` |

**"拒绝早于写状态"那一个变异不好用一行 old/new 表示**(要整块挪到 `save_state` 之后)。
`mutation_check` 的 old/new 是纯文本替换,可以把 `    state["setup_verified"] = True\n` 换成
`    state["setup_verified"] = True\n    save_state(root, state)\n` —— 提前落盘一次,等价于"拒绝晚于写状态",
我验过它红的正是那条。要不要登记由你定。
