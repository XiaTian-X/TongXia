## 这一回合带声明改了契约(`--contract-change`)

**① 判定行只对 impl 回合。** 原句"`handoff` 在检出'本回合没有任何改动落在执行者
那个角色的路径下'时写一行"没限定阶段。评审回合按构造只读,每一次都满足这个条件 ——
照字面实现,所有评审都会被算成协议开销,和同一节表格里的"空转的 **impl** 回合"
自相矛盾。

**② 每次 impl 交接都写判定行(是/否),没有判定行的不猜。** 只在空转时写,
`report` 就分不出"这回合没空转"和"那时还没有这一行"。W14 之前的所有提交、
任何从旧版本升级上来的项目,空转都会被计成 0 —— **指标在"好看"的方向上静默少计**,
正是这一节开头点名要消灭的那种指标。于是加了第三行 `未判定的 impl 回合`,只报覆盖面。

**不变量不动**:`推进交付的回合` + `协议开销的回合` = 交接提交。未判定的那些
按"交接提交数减去开销"的定义落在推进交付一侧,第三行把它们的数目说出来。

这是我自己起草、又由我在 spec 回合改的 —— 按 W9 两个角色都能落笔,但**你不同意

## 怎么实现的

- **五行声明各按"有没有检查读到它"来写**,判据一律用 `handoff` 开头抓的那批改动
  (`entries`),不用提交内容:
  - `--allow-deletion` ← `deleted` 非空(删测试防护读它)
  - `--doc-reason` ← `touched_docs` 非空(文档理由强制读它)
  - `--basis` ← 路线图在规范性文档里、且 `has_rewrite`(依据强制读它)
  - `--contract-change` ← `changed_named_frozen` 非空(冻结豁免与当场留决策读它)
  - `--no-decision` ← 新函数 `no_decision_is_read`:晋升闸的条件**去掉旗标那一项**。
    你约束的那一行(晋升闸,锚点「拆掉完成时的晋升 gate」)一个字没动,在它旁边另算。
    **必须紧跟在 `check_memory` 之后调用** —— 完成交接会在后面把 `item` 置空,
    晚一步就读不到笔记与 `settled` 了。
- **判定行** `空转判定: 是/否`,前缀是常量 `IDLE_JUDGMENT`,`handoff` 写、`report` 读
  同一个常量。只在 `phase == "impl" and not is_dispute` 时写;空转 = 执行者角色路径下
  没有改动、且没有带生效 `--contract-change` 的承重文件改动。
- **`report`**:删掉「每工作项回合数」一行与它在 `HEALTH` 里的键(`avg_rounds` 只有
  那两处用,打回率偏低的提示不依赖它);三行新计数只在表头计入的提交里数,
  两数之和因此恒等于「交接提交」。三个都不设健康区间。
