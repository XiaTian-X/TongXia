## 这一回合带声明改了契约(`--contract-change`)

**① 判定行只对 impl 回合。** 原句"`handoff` 在检出'本回合没有任何改动落在执行者
那个角色的路径下'时写一行"没限定阶段。评审回合按构造只读,每一次都满足这个条件 ——
照字面实现,所有评审都会被算成协议开销,和同一节表格里的"空转的 **impl** 回合"
自相矛盾。

**② 每次 impl 交接都写判定行(是/否),没有判定行的不猜。** 只在空转时写,
`report` 就分不出"这回合没空转"和"那时还没有这一行"。W14 之前的所有提交、
任何从旧版本升级上来的项目,空转都会被计成 0 —— **指标在"好看"的方向上静默少计**,
正是这一节开头点名要消灭的那种指标。于是加了第三行 `未判定的 impl 回合`,只报覆盖面。

**不变量不动**:`推进交付的回合` + `协议开销的回合` = 交接提交。未判定的那些
按"交接提交数减去开销"的定义落在推进交付一侧,第三行把它们的数目说出来。

这是我自己起草、又由我在 spec 回合改的 —— 按 W9 两个角色都能落笔,但**你不同意
可以打回**。决策记录在 `## W14 — …`。

## 判据的取舍

- **判定行的字面契约没给,我一次都不碰**,只通过 `report` 的三个计数观察它。
- **"旧提交"用一次空提交模拟**,正文照 `role=dev phase=impl -> review-impl item=W9 …`
  的既有形状写、没有判定行。`report` 读的就是这个。
- **行值我用 `标签\s*:?\s*(\d+)` 取第一个数**,不管你写 `1` 还是 `1 次`。
- **"只在空转时写"那种错误实现专门有一条打它**:同一个仓库里一个没空转的新 impl 交接、
  一个空转的、一个旧的 —— 那种实现会报"未判定 2",这里要 1。
