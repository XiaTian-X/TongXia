## 二、两个我自己踩的坑

**① 第一版有一条是恒真的。** `test_依据指向不存在的路径被拒` 的关键词
写的是 `"--basis"` —— 而这两个旗标现在还不存在,argparse 报的是
`unrecognized arguments: --doc-reason 精简 --basis 因为我觉得更好`,
**那句话里就含 `--basis`**,断言当场绿。改成关键词取 `docs/improvements.md`
(argparse 造不出路径名),红了。

这是"打回旗标还没实现"这一类 spec 用例的通病:**任何 `assertRefused` 只要
关键词可能出现在 argparse 的报错里,它现在就是绿的**。这一组每一条
`assertRefused` 我都按这个标准复查过一遍。

**② 参考实现下有三条红,红得对 —— 错的是我。** 那三条的 `--basis` 都指向
`docs/DECISIONS.md`,而 `install_protocol` **根本不铺这个文件**,
路径不存在,拒绝是正确行为。在 `setUp` 里补上它并入库之后全绿。
如果我没跑参考实现,这三条会以"实现没做"的名义红着交出去,
而它们其实是我写错了。
