## 一个鸡生蛋:陈旧缓存条目卡住了刷新缓存的那条命令

你重锚「拆掉文档理由强制」之后,`mutation-cache.json` 里留着旧名字
`文档理由允许空串`,`test_缓存里的条目名都在_MUTATIONS_里` 因此红。

而我第一反应是跑 `mutation_check.py` 刷新缓存 —— **跑不了**:
它先要基线全绿,而基线红的原因正是那条陈旧缓存。

```
陈旧缓存 -> 套件红 -> mutation_check 基线不绿 -> 刷不了缓存
```

出路是按那条测试自己说的做(「删掉它们」),直接把那个键从 JSON 里删掉,
套件转绿,再跑 `mutation_check` 才把新条目填上(第一次跑 99.5 秒,
比缓存命中的 24 秒长得多 —— 那是新变异点在补缓存)。

**不是缺陷,但值得记**:重命名或重锚一个变异点时,**要顺手把缓存里的旧键
删掉**,否则下一个人会撞上这个环,而且第一反应(跑一次刷新)正好是死路。
`mutation-cache.json` 在 `ignore_paths` 里,两个角色都能删。
