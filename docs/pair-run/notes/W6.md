## ⚠ 写这一回合时撞出一个真实漂移,而且是我自己造成、亲手掩盖的

`docs/improvements.md` 写着 `mutation_check.py:596` 的 `precheck_no_baseline`,
但 **596 实际是 `return 1`**,那个函数在 602。

追根:`git log -S "mutation_check.py:602"` **零命中** —— 那个值从未出现过。
596 是第二轮 dev 改的,之后再没动过。也就是说**第三轮我加变异点造成的
`+6` 偏移,从来没有被修复**。

我当时做了什么:

1. 更新 `CITED_LINE_COUNTS` 684 → 690,**让绊线变绿**
2. 把五处待修清单写进 **W2 的笔记**,交给 dev
3. W2 完成,笔记随工作项作废,dev 再没读过它
4. **修复从未发生,而绊线一声不吭** —— 它记的 690 和实际行数完全一致

这是那条绊线唯一逃逸口的完整演示:**"改数字让它变绿"**。我在实现它的时候
就在 docstring 里写过"不核对就只改数字,这条检查等于没有",然后自己做了
一模一样的事 —— 因为核对成本高,而变绿只要改一个整数。

**这条比 W6 原本的论据更硬:** 原来的论据是"行号会漂、要人工核对";
现在的论据是"**行号漂了,而唯一的防线可以被一次整数修改静默关掉,
并且真的被关掉过**"。符号引用没有这个逃逸口 —— 符号不存在就是不存在,
没有一个数字能改。

## 设计取舍

**检查写成纯函数 `check_symbol_refs(text, where)`。** 9 条作弊场景直接喂
字符串,不建临时文件、不碰真实文档 —— 跑完 10 条只要 0.12 秒。
如果把检查绑死在"扫描 NORMATIVE"上,每条作弊场景都得造一份假文档树。

**不要求反引号。** 规定形式带反引号,但漏掉反引号的旧引用同样该被迁移;
只认反引号会留一个绕过口。

**`_blank_fences` 把围栏抹成空行而不是删掉** —— 行号保持不变,将来若要报
"第几行有问题"不用重算。

## 删除的两条测试(已 `--allow-deletion` 声明)

`test_文档里的行号引用都落在文件内` 与 `test_被引文件的行数没变过`,
连同 `CITED` / `CITED_LINE_COUNTS` / `_CITE_RE` / `_citations` /
`_docs_with_citations` 共 39 行工具。

**理由是验收标准点名要移除**,而不是它们碍事:新的符号检查覆盖了它们的全部
职责且没有逃逸口 —— 上面那段漂移就是旧绊线失效的实证。留着它们等于留着
一条已经被证明可以静默关闭的防线,还会让人以为行号引用仍然有人守。
