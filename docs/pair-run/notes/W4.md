# W4 笔记

## 这一回合交了什么

新增 `tests/conformance/test_v1_paths.py`,9 条:**8 红 1 绿**。

单独建文件而不是塞进 `test_v1_setup.py` / `test_boundaries.py`:三条验收
(孤儿清单、`ignore_paths` 清单、越界文案)同属**一个契约小节**,拆到两个
文件会让"这一节由谁守着"变模糊 —— 而 W6 刚证明过,文档与代码的对应关系
一旦模糊,漂了都没人知道。

那 1 条绿是 `test_越界项里没有孤儿时末尾维持原样`:它守的是**现有行为不被
改坏**(越界项全是有主文件时,末尾仍该是"请撤销"),实现前绿是对的,
它是上一条的对照,防止把文案改成无条件的。

## 一个发现:新项目开箱即带孤儿

默认装出来的 harness 仓库就有 3 个孤儿:`.gitignore`、`AGENTS.md`、
`CLAUDE.md` —— **全是 `init` 自己铺的入口文件**。

契约背景写的是"存量项目接入时必然有大量孤儿",实测**新项目也一样**:
`init` 铺了一堆入口文件,而它给的默认 `roles` 只有 `tests` / `src`,
两者对不上。这不是边角场景,是每个新接入项目的开箱状态。

对 W4 没影响(它只要求检出并打印),但它说明**这条警告会在每个项目上出现**
—— 值得考虑让 `init` 顺手把自己铺的文件划进某个角色,那是另一笔账。

## 差点又写出恒真的用例,而且是刚被打回之后

三条负向断言(未跟踪文件不算孤儿 / 记忆层不算孤儿 / 孤儿只是警告不阻断)
第一版**全是恒真的** —— 功能没实现时输出里什么都没有,`assertNotIn` 自然过。

按上一轮学到的加了前提断言,但**第一版前提用的是 `assertIn("AGENTS.md")`
—— 它也没起作用**:`verify-setup` 本来就会因为"入口文件含协议激活段落"
那条检查提到 `AGENTS.md`,前提恒真,等于没加。实测输出里它出现 1 次。

换成 `assertIn("孤儿")`(只可能出现在新清单里)之后,三条才真正变红。
**前提断言必须挑一个只有目标功能才会产生的词** —— 挑一个"碰巧也会出现"的,
和没加一样。

## 给 dev

- **截断那条要的是剩余数,不是总数。** 用例造 12 个新孤儿,加上开箱那 3 个
  共 15 个,断言输出里有 `5`(15 − 10)。
- **越界文案有两条对照用例**,别把末尾改成无条件的:有孤儿时不能再说
  "请撤销这些改动后重试",没孤儿时必须仍然是它。
- `ignore_paths` 那条用了单独的 `config`,因为默认是空的。

变异点「拆掉写权限边界」锚的是 `if violations:` **紧跟** `lines =`。
我原本把 `orphaned = [...]` 写在 `lines` 之前(它逻辑上该在那儿:先算出

而 `MUTATIONS` 在 `mutation_check.py` —— **tester 的路径,我改不了。**

**我没有把它写进异议,自己改了实现。** 锚点是正当约束,代价只是语句顺序,
不值得为它烧一次往返。但值得记下来:这已经是本轮第四次"dev 改自己的文件、
失配出现在 tester 路径里"。前三次分别是行号绊线、孤儿路径、变异缓存指纹。
**这一次我能自己让开,是运气** —— 锚点恰好只约束两行的相邻关系。

代码里留了注释说明为什么孤儿的计算排在 `lines` 之后,否则下一个人会顺手
把它挪回"正确"位置,再红一次。

## 开箱孤儿是 3 个,不是 0 个 —— 这影响了你那条截断用例

你笔记里记的"新项目开箱即带 3 个孤儿"我复现了,而且它正是
`test_超过十个只列前十并说明还剩多少` 红的原因:那 3 个按字节序
(`.gitignore` < `AGENTS.md` < `CLAUDE.md` < `孤儿…`)**排在最前面,占掉
3 个名额**,所以匹配 `孤儿0`/`孤儿1` 前缀的只有 7 行。

契约没有规定清单的顺序,我按 `git ls-files` 的顺序列(也就是字节序),
没有另外排序 —— 换任何顺序都是给契约加一条它没写的承诺。

## 异议受理:三条都是我的用例问题,不是实现问题

### ① 我在 W6 的用例里留了最后一处硬编码坐标

`test_区间形式也被拒且按起始行给建议` 把 `pair.py:2375-2390` 写死当输入。
W4 的实现让 `cmd_init.put` 从 2375-2382 挪到 **2431-2438**,2375 现在落在
`merge_entry` —— 我核过,dev 说的准确。

**这是 W6 最讽刺的一处**:那个工作项把全仓 26 处文档坐标全部取消,而它
**自己的用例**里留着一处指向 dev 文件的硬编码坐标,W6 完成后第一个 impl
回合就漂了。

**根因是 W6 的检查只扫文档(`NORMATIVE`),扫不到测试代码。** 这是一个
真实的残留缺口,不在 W6 的验收标准里 —— 值得单独立项,和开放条目 14
(66 处裸坐标)同类。

改法采纳 dev 的:用 `ast` 在用例里现算 `put` 的起止行,取
`end_lineno + 1` 作为结束行(落在 `cmd_init` 内、`put` 外)。
起止跨符号的性质一个字没弱,而 `pair.py` 怎么改都不会再漂。

### ② dev 给的改法我**没有**采纳,换了一种

它建议 `assertIn("孤儿06.md")` + `assertNotIn("孤儿07.md")`,并说这样
"同时钉住了截断在第 10 行和顺序是字节序"。

**但契约没有规定清单内部的顺序。** 断言字节序就是断言契约没写的东西
(规则 4)—— 而 dev 自己在同一段里也写了"顺序不是这一节要保护的性质"。
它给的方案和它自己的判断矛盾。

我的改法:**把 `init` 铺的那 3 个入口文件划给 dev**,孤儿就只剩用例自己
造的 12 个,于是可以数"被列出的孤儿有几个 == 10",既不按名字前缀数行,
也不假设谁排在前面。为此把截断那条拆成独立的 `TestOrphanTruncation` ——
其余用例反过来**需要**开箱孤儿存在(它们的前提断言靠它)。

### ③ 副产物挪出 `tests/`,采纳

脚手架的 `TEST_CMD` 要求每个测试文件都有同名实现文件,写在 `tests/` 下会让
基线变红、`verify-setup` 拒绝 —— 而那与被测功能无关。改成 `build/缓存.json`。
