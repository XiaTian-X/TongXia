# W4 笔记

## 这一回合交了什么

新增 `tests/conformance/test_v1_paths.py`,9 条:**8 红 1 绿**。

单独建文件而不是塞进 `test_v1_setup.py` / `test_boundaries.py`:三条验收
(孤儿清单、`ignore_paths` 清单、越界文案)同属**一个契约小节**,拆到两个
文件会让"这一节由谁守着"变模糊 —— 而 W6 刚证明过,文档与代码的对应关系
一旦模糊,漂了都没人知道。

那 1 条绿是 `test_越界项里没有孤儿时末尾维持原样`:它守的是**现有行为不被
改坏**(越界项全是有主文件时,末尾仍该是"请撤销"),实现前绿是对的,
它是上一条的对照,防止把文案改成无条件的。

## 一个发现:新项目开箱即带孤儿

默认装出来的 harness 仓库就有 3 个孤儿:`.gitignore`、`AGENTS.md`、
`CLAUDE.md` —— **全是 `init` 自己铺的入口文件**。

契约背景写的是"存量项目接入时必然有大量孤儿",实测**新项目也一样**:
`init` 铺了一堆入口文件,而它给的默认 `roles` 只有 `tests` / `src`,
两者对不上。这不是边角场景,是每个新接入项目的开箱状态。

对 W4 没影响(它只要求检出并打印),但它说明**这条警告会在每个项目上出现**
—— 值得考虑让 `init` 顺手把自己铺的文件划进某个角色,那是另一笔账。

## 差点又写出恒真的用例,而且是刚被打回之后

三条负向断言(未跟踪文件不算孤儿 / 记忆层不算孤儿 / 孤儿只是警告不阻断)
第一版**全是恒真的** —— 功能没实现时输出里什么都没有,`assertNotIn` 自然过。

按上一轮学到的加了前提断言,但**第一版前提用的是 `assertIn("AGENTS.md")`
—— 它也没起作用**:`verify-setup` 本来就会因为"入口文件含协议激活段落"
那条检查提到 `AGENTS.md`,前提恒真,等于没加。实测输出里它出现 1 次。

换成 `assertIn("孤儿")`(只可能出现在新清单里)之后,三条才真正变红。
**前提断言必须挑一个只有目标功能才会产生的词** —— 挑一个"碰巧也会出现"的,
和没加一样。

## 给 dev

- **截断那条要的是剩余数,不是总数。** 用例造 12 个新孤儿,加上开箱那 3 个
  共 15 个,断言输出里有 `5`(15 − 10)。
- **越界文案有两条对照用例**,别把末尾改成无条件的:有孤儿时不能再说
  "请撤销这些改动后重试",没孤儿时必须仍然是它。
- `ignore_paths` 那条用了单独的 `config`,因为默认是空的。
