## 判据的取舍

- **场景用 `checks/` 不用 `tests/`。** harness 的测试命令要求 `tests/` 下每个文件在 `src/` 下有同名文件,
  在 `tests/` 下放登记表会让套件本身变红,分不清是谁拒的。
- **拒绝文案只断言"追加"和文件路径。** 契约写"评审回合只能往它追加,不能改或删已有行",PLAN 写"只能追加",
  两处字面不同 —— 取两者都含的词。
- **"新建被拒"那条改了配置再提交**(人类提交),让名下路径指向一个 HEAD 里没有的文件。
- **路径按精确文件测**,不钉通配语义(审查里记过:契约没说是 `matches_any` 还是精确路径)。

## 请你不要动的既有锚点

**追加路径请另行判定**(例如在写权限边界的循环里,对评审阶段执行者名下的路径单独判),不改那两行。

# W16 — dev 的 impl 回合

## 怎么实现的

- **`review_append_paths(cfg, phase)`** 紧挨着 `writable_paths`:只在评审阶段、只取阶段执行者名下的。
  **你点名的「拆掉评审只读」那两行一个字没动** —— 这批路径不进 `allowed`。
- **`append_only_violation(root, path)`**:不在 HEAD 里 → 拒("新建不算追加");`has_rewrite` 有删除行 →
  拒("评审回合只能往它追加,不能改或删已有行");否则放行。
- **写权限边界的循环里**,冻结判定之后、越界判定之前:命中只追加路径就单独判、判完 `continue`。
  那一段的四个既有锚点都是单行,插入位置没有切断任何一个(第六轮立项时 W18 的原型切断过一次,这次核了)。
- **`writable_display(cfg, phase)`**:`status` 的"可写路径"与简报的"只能写"共用,只追加的路径后面标"(只追加)"。
- 文档:`protocol-spec` 配置表加一行、§4.1 补一句判定;`INSTALL.md` 加一小节"评审回合要往测试侧登记东西"
  (含"只追加不等于无害、对方要看 diff");路线图条目 18 标 ✅。

自己跑的:**全套 409 全绿**、`mutation_check` **126/126**(既有锚点都没被碰坏)。
