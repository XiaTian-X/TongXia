## 这一回合交了什么

`tests/conformance/test_v1_review_append.py`,12 条:

- **放行**:评审回合往名下文件末尾追加;**往中间插入也放行**(契约写死"判据不许写成中间插入被拒")
- **拒绝**:改已有行(文案提到"追加"与那份文件)、删掉整个文件、改名、**名下路径不在 HEAD 里时新建**、
  没配置的测试文件照旧越界
- **不配这个键时不变**:评审回合往那份文件追加照旧被拒
- **不并进 `shared_paths`**:impl 回合不能写自己名下的追加路径;idle 时 `status` 不列它;
  **只放开阶段执行者名下的**(review-test 里 dev 能追加自己名下的、不能追加 tester 名下的)
- **`status` 在评审阶段标出"只追加"**

## 判据的取舍

- **场景用 `checks/` 不用 `tests/`。** harness 的测试命令要求 `tests/` 下每个文件在 `src/` 下有同名文件,
  在 `tests/` 下放登记表会让套件本身变红,分不清是谁拒的。
- **拒绝文案只断言"追加"和文件路径。** 契约写"评审回合只能往它追加,不能改或删已有行",PLAN 写"只能追加",
  两处字面不同 —— 取两者都含的词。
- **"新建被拒"那条改了配置再提交**(人类提交),让名下路径指向一个 HEAD 里没有的文件。
- **路径按精确文件测**,不钉通配语义(审查里记过:契约没说是 `matches_any` 还是精确路径)。

## 请你不要动的既有锚点

「拆掉评审只读」锚在 `writable_paths` 里 review / idle 返回 `shared` 那两行 —— 最顺手的实现正好改那里。
**追加路径请另行判定**(例如在写权限边界的循环里,对评审阶段执行者名下的路径单独判),不改那两行。
非改不可就打回,我按「三节共同」重锚。

## 变异点

形状由你定,你交实现时点名锚点。**本节自己的锚点仍然欠一次**(契约「边界」写明:W16 的 review-impl
由旧裁判判,那时追加还不生效),我在 W17 的 spec 回合登记。契约点名要有用例红的两个方向:
去掉"只追加"的判定、去掉"HEAD 里要存在"的判定。

## 两半都在隔离副本里实现过,再说话

参考实现:写权限边界的循环里,评审阶段执行者名下的路径单独判(不在 HEAD 里 → 拒;有删除行 → 拒;
否则放行),`status` 的可写路径后面补"(只追加)"。**没动「拆掉评审只读」那两行。** 结果:

- **全套 409 条 OK** —— 没有别的既有用例被带红。
- 四个变异**各只被一条**用例抓住:去掉"只追加"判定 → 改已有行那条(以及下面说的删文件那条);
  去掉"HEAD 里要存在" → 新建那条;不看执行者 → 执行者名下那条;不分阶段 → impl 回合那条。
- 今天的代码上红 **5 条**,原因都核过:追加与中间插入被当成越界拒绝、review-test 里 dev 追加自己名下的
  被拒、`status` 不列这份文件、改已有行的拒绝文案里没有"追加"。

**参考实现又挖出我自己一条用例的毛病**:`test_删掉整个文件被拒` 第一版在"去掉只追加判定"下**照样绿** ——
`checks/` 在 tester 角色路径下,删掉它先被既有的"删除测试防护"拒了,拒绝原因根本不是本节。
加上 `--allow-deletion` 之后,能拒这次删除的只剩本节,那个变异下它红了。**又一次"判据比它声称守的性质更宽"**,
这次是被另一道检查替它挡了。
