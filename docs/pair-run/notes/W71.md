## spec(tester)

用例在 `tests/conformance/test_v1_decision_overturn.py`,27 条,写完时 23 红 4 绿。绿的四条是对照组与守"不做"的:
注入预算的对照(没推翻时最早那条被挤掉)、字段解析的对照(tester 主体阶段照常按 `影响路径` 召回)、讨论回合追加合规普通条目照旧放行、晋升闸照样把被推翻的算作本工作项的决策。

**契约补了一段「补充」(㉓)**:判"已被推翻"时不算这条新条目自己。原文"文件里任一条目的 `推翻:`"照字面包括正在写的这条 —— 那样正面用例
`test_resume_时推翻放行…` 会红。本回合**其他**新条目的 `推翻:` 算(`TestSameTurnDoubleOverturn`)。

### 用例怎么造的,实现时要知道的

- 推翻走真的 discuss:spec 里 tester 开场,dev 讨论回合发言,tester resume 时往决策文件追加带 `推翻:` 的条目。`resume` 的提交要带上决策文件(它本来就是散文路径)。
- 注入只看 `status` 输出里 `--- 相关决策` 之后那一块;旧条目在不在,看它**理由里独有的词**,不看标题(新条目的 `推翻:` 行就带着旧标题)。
- 只测注入的用例直接往工作区写决策文件再跑 `status`(不经过 resume 的校验)。推翻者与当前阶段无关(ID 不是当前工作项、`影响路径` 是 `docs/无关/…`)。
- 字段解析那条:被推翻的标题里含 `src/W1`。`推翻:` 被当成 `影响路径` 的续行时,`src/W1` 进了路径,impl 阶段(dev 主体)就会召回推翻者 —— 现在就是这样红的。
- 引用写法放行两种:`` `## W1 — 缓存按租户分键` ``(前导井号加反引号)、`W1 - 缓存按租户分键`(半角连字符)。
- 拒绝文案的断言词:
  - 错的入口:正常交接要有 `discuss` 与 `resume`;`discuss` 开场与讨论回合的 `handoff` 要有 `resume`。
  - 引用对不上:标题不符的那条要出现引用里写错的标题 `缓存按租户分片`;ID 不符要出现 `W2`;引用本回合新写的,要出现 `本回合先写的结论`。
  - 重复推翻:要出现**已推翻它的那条**的标题 `早先已推翻租户分键`。
  - 讨论回合改写已有条目:`追加`;不构成条目:`不构成`;缺字段:`已否决`。
  - 正常交接的追加式文案:保留 `追加式`、`伪造共识`,补上 `discuss`、`resume`、`推翻`。
  - 条目格式提示:要含 `- 推翻:`(提示里那一行示例)。
- 被拒时一律断言:提交数不变、`.pair/state.json` 逐字节不变(讨论回合那几条)或阶段不变(开场那两条,提案文件会留在工作区)。
