# W77 笔记 —— 讨论回合拒绝 `--test-gap` 的用例

## spec(tester)

在 `tests/conformance/test_v1_test_gap.py` 加 `TestDiscussTurn` 两条:讨论回合里轮到发言的 dev 带 `--test-gap` 交接被拒(提交数与 `state.json` 不变、仍在讨论阶段);
对照组同一场讨论不带旗标照常交接。登记变异点「缺口_拆掉讨论回合的那次调用」(把 `discuss_handoff` 里那行 `test_gap_refusal(DISCUSS, …)` 换成 `refusal = None`)。

## 行为来源

读了 `pair.py` 的 `discuss_handoff`:回合归属判完之后、提案改动检查之前调 `test_gap_refusal(DISCUSS, None, …)`;阶段不是 review-impl 就返回拒绝文案,`die` 退出,
所以什么都不提交。讨论回合的交接不经过 `cmd_handoff` 里那次判定(`cmd_handoff` 一进来就把讨论阶段转给 `discuss_handoff`),拆掉这一次调用,
`--test-gap` 在讨论里就被 argparse 收下、没人看 —— 交接照常成功。跑了两条用例,对现有实现都绿;变异之后被拒那条变红。

## 我冻结了哪些可疑行为

没有,逐条对过契约。契约「review-impl 的测试缺口」写"其他阶段带它 → 拒绝",讨论阶段是其他阶段;用例不断言文案措辞(契约没给这一种的措辞),
只断言被拒、提交数与状态不变、阶段仍是讨论。讨论由 tester 在 spec 回合开场、停在 dev 的讨论回合,与 W71、W72 的讨论用例同一写法。

## review-test(dev)

通过。被拒那条与对照组只差旗标,去掉讨论回合的那次调用就会放行;轮到的是 dev、提案是追加的,别的拒绝替不了它。不断言措辞是对的。
