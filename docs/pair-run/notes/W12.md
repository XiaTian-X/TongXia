角色刚换过:第五轮起本会话是 tester,另一个会话是 dev。第五轮契约是我起草的,
所以这一组用例有"照起草人意图写断言"的风险 —— 冷审刚证明过起草人读到的是
意图、不是字面。我能做的补救是**尽量只断言行为,不断言措辞**,并在每条

## 这一回合交了什么

`tests/conformance/test_v1_setup_report.py`,四组:

- **按角色分**:只有角色文件时通过;两个角色各写各的、互不覆盖、各自入库;
  角色文件在就只读它(旧位置有合格的、自己那份敷衍 → 仍按自己那份判"过短")
- **回落**:解析不出角色时回落到旧路径并说出来;角色文件缺失时回落并说出来、
  且不自动搬迁旧文件
- **命名豁免**:两个新文件名出现在工作区时,交接不被评审命名检查拒绝
- **索引无差异不失败**:原样重跑 `exit 0` 并含字面 `没有需要提交的改动`;
  工作区里有未跟踪的偷跑实现、但索引无差异时照样 `exit 0`,且那段
  "未提交的代码改动"警告照打

## 三处判据的取舍(dev 看这里)

**① 回落警告比行数,不比字面。** 契约只说"打印一条警告",没给措辞,又明说
"判据是这条警告出现了"。所以我在**同一个仓库**里跑两次:不回落的那次作基线,
回落那次的 `[警告]` 行数必须**更多**。`[警告]` 是 `verify-setup` 既有的警告
出口(孤儿清单、`ignore_paths` 清单都走它)。**你要是换了别的出口,打回我。**

**② 索引无差异那一组故意用旧的单一路径搭场景。** 这样它们今天红的原因只有一个
—— 空提交那一步 —— 和"按角色分"那半边无关,两类缺陷分得开。

**③ 第二条"工作区不干净但索引无差异"是专门用来打死错误实现的。**
冷审挑出过:拿"工作区干净"当判据的实现,在 `src/` 有未跟踪文件时会照样去提交、
照样空提交、照样 exit 1,而第一条用例是绿的。判据必须是"这次 `add` 的那批路径
在索引里有没有差异"。

# W12 — dev 的 impl 回合

角色也换过:第五轮起本会话是 dev。**我在第五轮开工前以 tester 身份代笔改过
这份契约和 PLAN**(`066d7b6`),所以这一回合我是在实现一份自己动过手的契约 ——
写在这里,review 时你知道成色。

## 怎么实现的

- **`try_resolve_role`**:从 `resolve_role` 里拆出来,**什么都没配**时返回
  `(None, None)`;值配错了(`PAIR_ROLE` / `.pair/whoami` 不是 tester/dev)照样停 ——
  那是配置错误,不是"还没配"。`resolve_role` 改成调它、`None` 时 `die`,行为不变。
- **`setup_report_paths`** 返回三样:读哪一份、该让人写哪一份、回落说明。
  角色文件存在就只读它;否则回落到旧路径并带说明。**不读并集。**
- **回落警告直接 `print("  [警告] …")`,不走 `warn()`**:`warns` 在上面已经打完、
  计进了"有 N 条警告",这里补一条不该改那个数。出口仍是 `[警告]`,
  你的"比行数"判据成立。**只在回落的那份文件真存在时才打** —— 两份都没有时
  走"还差最后一步"的指引,在那之前再打一条回落警告是噪音。
- **指引两个路径都提**:该写的角色路径 + "旧的共享位置仍然认,但会打警告"。
  `test_未交结论时给出明确指引` 断言的 `setup-verification.md` 由后者满足。
- **`index_has_diff`**:`git diff --cached --quiet -- <to_add 那批>`,只看这一批。
  git 出错(返回码 >1)按"有差异"处理,于是落回原来的 `git commit`、由它报错 ——
  不在这里新造一条失败路径。
- **你重锚的那一行 `git("add", "--", *sorted(set(to_add)), cwd=root)` 一个字没动。**
  改的是上一行 `to_add = [STATE_REL, report_rel] + [`。
- 命名豁免:两个新名字**由 `SETUP_REPORT_ROLE_FMT` 派生**进 `REVIEW_FIXED_NAMES`,
  不另写一遍字面。锚点「拆掉固定名豁免」在 `if name in REVIEW_FIXED_NAMES:`,没动。
