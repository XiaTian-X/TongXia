## 带声明改的契约(开工前审查 ⑳)

"重叠" = 有一个文件会同时命中两边(两边各取代表路径互相匹配)。理由见 W66 决策。

## 用例 `test_v1_proposals.py` 26 条,今天红 20 条;`test_docs_consistency.py` 加 1 条(绿)

类默认 `proposal_paths: ["docs/proposals"]`。
- 四个阶段都可写并交接(spec tester、impl dev、review-impl tester、review-test dev 完成),提案进提交;spec 那条另查正文有 `提案: <路径>`。
- 只能追加:tester 提交的提案,dev 在 impl 改一行被拒、删除被拒、追加放行。
- 四处不认它,用**最强的形状**试:提案名与小节都照异议文件写(`docs/proposals/W1-dispute.md` + `DISPUTE_DOC`)→ impl 的 `changes` 被拒(对照:同一份写在评审目录放行);
  提案里有真实的 `src/W1:1`、打回理由没有位置 → 被拒、文案含"位置";提案名不对应工作项 → 评审交接放行;只写提案不要求 `--doc-reason`。
- `scope` 豁免;只写提案门禁不重跑(仓库外计数);`inbox` 摆出提案原文;默认 `[]` 时写那个目录越界;`init` 写出 `["docs/proposals"]`。
- `verify-setup` 五种重叠各判失败、点名键:与角色(前缀,用 `plans/` —— `docs` 下会被别的检查先拒)、评审目录、冻结路径(单个文件)、记忆层(`notes_dir`)、`ignore_paths`(glob);
  三条对照:不重叠通过、`*` 不跨目录不算、前缀那份配置把 `plans` 换成 `plans-old` 就通过。
- ⑧(我的):`symbol_ref_scope` 再减去 `proposal_paths`;`TestScopeExcludesProposals` 在临时仓库里配出来看 —— 提案与评审都不在范围、普通文档在。去掉那一项 → 红(实测)。
