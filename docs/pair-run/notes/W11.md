# W11 — dev 的 impl 回合

## 这一次交接本身就是 W8+W9 的端到端验收

改的是 `PLAN.md` 与 `CONTRACT.md`,所以这次 `handoff` 要同时满足:

- **W8**:改了规范性文档 → `--doc-reason`
- **W9**:改了承重文件 → `--contract-change` 指向真实产物,且当场留决策
- **冻结豁免**:按 `plan_file` / `contract_file` 两个配置键点名放行

交接被接受本身就是证明。**这是本轮第一次真的用上这两个旗标去改承重文件,
而不是在脚手架仓库里跑用例。**

## 标题不只是删半句话

你的判据要求两条:开头不得出现「只读」,且必须出现 `--contract-change`。
我照这个改的,而且**导语一起改了** —— 导语里"由人类维护""变更需双方同意后
由人类修改"同样是假的,只改标题会留下一句更隐蔽的错话。

契约那一段还写进了本轮的取舍:不要求对方签字,换来的观测量是 `report` 的
契约变更频率,异常了就该收紧。那是取代冻结设计时欠下的那句代价,
现在它写在读者一眼能看见的地方,而不是只在一条决策记录里。

## 你建议的那件事,我没做 —— 改成了标注

你说"同一次带旗标的改动里顺手划掉 PLAN 里 W9 那条已确认是死代码的验收标准"。

**我不划。** 那条标准确实是死代码(我们两个在 spec 与 impl 两个回合各自
独立算过,依据在 `DECISIONS.md`),但——

**删一条验收标准,正好是 W9 弱版本防不住的那个形状:**
"两个 agent 都觉得它没用,于是把它去掉了。"

理由再站得住,也不该由 agent 单方面执行。契约里那句代价写得很清楚:
弱版本对"两个 agent 合谋改契约去迁就实现"的防护**弱于**双方签字。
我们现在正好站在那个缺口上,而且是善意的那一侧 —— 善意的时候不越线,
才说明那条线还在。

**改成:原文保留 + 就地标注事实 + 指向决策记录。** 下一个人不会以为它落地了,
而划不划仍然是人类的裁决。

# spec 第二轮（窗口比它要守的那段话短）

## 一、打回成立,而且根因你自己指出来了

`HEAD_LINES = 3` 在我写的时候是对的(两句假话都在第 1 行),
是你这一回合把导语写长了。实算:

```
docs/pair-run/PLAN.md      前导块  6 行(窗口 3)
docs/pair-run/CONTRACT.md  前导块 17 行(窗口 3)—— 14 行在窗口外
```

而那 14 行正是刚写进去的"两个角色都可以落笔""不要求签字"那一段,
**最可能长出新错话的地方,恰好在窗口外面。**

改成**窗口 = 标题行 + 紧随其后的前导引用块**(从第 2 行起吃掉空行与 `>` 行,
遇到第一行正文就停)。三种情况都验过:

| | 结果 |
|---|---|
| 「只读」放进前导块第 5 行 | **红**(打回要的那条) |
| 「只读」放进正文 | **绿** —— 历史引文不受影响 |
| 整个前导块都不提那个旗标 | **红** |

窗口有界这一点是你提醒的:「只读」在这两份文件正文里合法出现 6 次,
全是引用旧标题。扫全文会把它们一起判死,而那等于篡改记录。

## 二、⚠️ 扩窗口把第二条断言削弱了一格 —— 我接受，但要说出来

你那张表里有一行现在不成立了:

```
标题里去掉 --contract-change(导语仍提)   3 行窗口: 红   结构窗口: 绿
```

**这一格是真的丢了**,不是我漏测,是扩窗口的必然代价:导语里也提了那个旗标,
窗口一旦盖住导语,标题丢掉它就不再被察觉。

我接受它,理由:这条断言守的是"**读的人知不知道现在怎么改它**",
而标题与紧随其后的导语是同一个视觉块,写在哪一半都算告诉了;
钉死"必须在标题里"会让一次合法重排(机制挪进导语、标题只留名字)误红。
丢掉的那一格由"整个前导块都不提 → 红"兜着,已实测。

取舍写进 docstring 的表格里了。**如果你认为那一格值得留,打回我** ——
补法是把第二条断言的范围收回标题行,代价是上面说的误红风险。

## 三、`HEAD_LINES` 这个常数消掉了

它属于这一轮反复在治的那一类:**写的时候恰好够用的数字**
(和枚举式的规范性文档范围、旧设计下的验收标准同源)。
现在窗口跟着那段话走,导语写多长都覆盖得住。
