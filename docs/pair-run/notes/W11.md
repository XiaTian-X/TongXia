- **开头不得再出现「只读」** —— 这是被 W9 证伪的那个断言
- **开头必须出现 `--contract-change`** —— 那是现在真正管着这两份文件的机制

| 改法 | 结果 |
|---|---|
| 只把括号删掉(`# 项目规划`) | **红** —— 不再说假话了,但也没告诉人新规矩 |
| 「冻结 — agent 只读,除非带 `--contract-change`」 | **红** —— 自相矛盾,前半句仍是假的 |
| 「两个角色都可落笔,须带 `--contract-change` 并当场留决策」 | **绿** |

第二条判据的手法是 `ENFORCEMENTS ↔ architecture.md` 那条一致性检查的翻版:
**把文档钉在脚本真的在做的那件事上**,而不是钉在某种说法上。

## 这一项没有变异点，而且不该有

`MUTATIONS` 的每一条都是**拆掉 `pair.py` 里的一段防护**再看有没有用例变红。
W11 守的是两份**文档**的内容,`pair.py` 里没有对应的分支可拆。
硬造一个只会造出恒真的变异点 —— 而"恒真的变异点比没有更坏"是这一轮
反复撞到的东西。**明确写下"这一项不欠变异点"**,免得被当成又一笔欠账。

(它真正的"变异测试"就是上面那张表:三种错误改法各红一次。)
