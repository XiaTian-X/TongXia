# 接口契约（冻结 — agent 只读，变更需双方同意后由人类修改）

> **这是整套机制的承重墙。**
>
> 两个 agent 从不交谈,只通过这份契约对齐。契约含糊 → tester 测 `login() -> token`,
> dev 写 `authenticate() -> Session`,两边各自都"对",合起来是废的。
>
> 规则:**没写进这份文件的东西,tester 不许断言。**

## status 简报落盘

- 依据: 人类定稿

把 `status` 每回合注入给 agent 的东西同时落盘,让人类事后能看到
"这一回合它到底看到了什么"。现在这些内容只存在于那一次终端输出里,
agent 说"我没看到那条决策"时无从对质。

### `.pair/.last-brief.md`

**行为** `status` 在**轮到当前角色时**,把它打印的阶段简报与记忆注入
写入 `.pair/.last-brief.md`。**覆盖式** —— 只保留最近一次,不追加、不留历史。

**内容** 至少包含以下五项,缺一不可:

| 项 | 取自 |
|---|---|
| 当前角色 | `resolve_role` |
| 当前工作项 ID 与类型 | `state["item"]` / `state["item_type"]` |
| 当前阶段 | `state["phase"]` |
| 红绿状态 | `run_tests` 的结果 |
| 记忆注入原文 | `memory_brief` 的返回值(笔记全文 + 相干决策) |

工作项为 `None`(idle)时,前两项写"无"。`memory_brief` 返回空串时,该段落省略。

**不是自己回合时** 不写,**也不清空** —— 上一次的简报要留着给人类看。

**边界** 这个文件落在 `.pair/` 下,而 `.pair` 在 `frozen_paths` 里。
它必须同时:

1. 进 `PROTOCOL_LOGS`,从 `handoff` 的写权限边界检查中豁免
2. 进 `GITIGNORE_LINES`,让 `init` 为新项目写进 `.gitignore`

**不做这两件事,写出来的第一份简报会让下一次 `handoff` 判越界,而且 agent
删不干净(下一次 `status` 又会生成)。** 同类的坑在 `.pair/.last-full-test.log`
上真实发生过一次。

**错误** 写文件失败(权限、磁盘满、目录不存在)**不得**让 `status` 失败,
也不得改变它的退出码。它是可观测性,不是门禁。失败时在 stdout 打一行以
`[简报]` 开头的警告。

**不做**

- 不改变 `status` 的退出码
- 不改变 `status` 已有的任何标准输出
- 不参与任何协议判定 —— 没有哪条检查可以读这个文件
