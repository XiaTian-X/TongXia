# 接口契约（冻结 — agent 只读，变更需双方同意后由人类修改）

> **这是整套机制的承重墙。**
>
> 两个 agent 从不交谈,只通过这份契约对齐。契约含糊 → tester 测 `login() -> token`,
> dev 写 `authenticate() -> Session`,两边各自都"对",合起来是废的。
>
> 规则:**没写进这份文件的东西,tester 不许断言。**
> 反过来也成立:**这份文件只描述从外面看得见的东西**,不规定怎么实现。

## status 简报落盘

- 依据: 人类定稿

把 `status` 每回合给 agent 看的东西同时落盘,让人类事后能查
"这一回合它到底看到了什么"。现在这些内容只存在于那一次终端输出里,
agent 说"我没看到那条决策"时无从对质。

### 什么时候写

`status` 在**轮到当前角色时**写 `.pair/.last-brief.md`,**覆盖式**,
只保留最近一次。

"轮到当前角色"以 `status` 自己的判定为准,包含这两种容易漏掉的情形:

- **`idle` 阶段**:归 tester。tester 在 idle 跑 `status` 要写。
- **PLAN 里工作项已全部完成**:只要轮到自己就写,与 `status` 后面还打不打印
  阶段简报无关。

**不是自己回合时**:不写,**也不清空** —— 上一次的简报要留着给人类看。

### 写什么

一份独立的、字段化的产物。**它不是终端输出的副本。**

下面是一份**逐字节精确**的完整示例。**简报的结构必须与它完全一致 ——
包括标题行、字段顺序、半角冒号加一个空格、空行位置、以及文件末尾的换行 ——
只有字段值和记忆内容随状态变化。**

```
# 回合简报

- 角色: tester
- 工作项: W1 [feature]
- 阶段: spec
- 测试: GREEN

--- 本工作项笔记 (docs/pair-run/notes/W1.md) ---
这一项试过直接改 X,不行,因为 Y。
--- 相关决策 (docs/pair-run/DECISIONS.md) ---
## W1 — 某条结论
- 理由: ……
- 已否决: ……
- 影响路径: `a.py`
```

逐条说明:

| 位置 | 规定 |
|---|---|
| 第 1 行 | 固定为 `# 回合简报` |
| 第 2 行 | 空行 |
| 第 3–6 行 | 四个字段,顺序固定,形态是 `- <字段>: <值>`(**半角冒号 + 一个空格**) |
| 第 7 行 | 空行。**仅当下面有记忆段落时存在** |
| 第 8 行起 | 记忆段落 |
| 文件末尾 | 以一个换行符结束 |

四个字段的取值:

| 字段 | 取值 |
|---|---|
| `角色` | `tester` 或 `dev` |
| `工作项` | `<ID> [<类型>]`;没有进行中的工作项时写 `(无)` |
| `阶段` | `idle` / `spec` / `impl` / `review-impl` / `review-test` |
| `测试` | `GREEN` 或 `RED`,没有第三种 |

**记忆段落**:与 `status` 注入的记忆内容逐字一致,**但只要内容本身**——
终端上包着它的两条 `=` 分隔线和「你不在场时留下的东西」标题**不写进简报**。

**没有记忆内容时,记忆段落连同它前面那个空行一起省略**,文件就是四行头部
加一个末尾换行,像这样(idle 时):

```
# 回合简报

- 角色: tester
- 工作项: (无)
- 阶段: idle
- 测试: GREEN
```

### 写不成的时候

写入抛 `OSError` 时:

- `status` 打印**一行**以 `[简报]` 开头的警告到标准输出
- **退出码不变**
- `status` 的其余输出**完全不受影响**

它是可观测性,不是门禁。任何情况下都不许让 `status` 失败。

### 不许影响别的东西

- **不得让后续交接判越界。** 写过简报之后,下一次 `handoff` 不得因为
  `.pair/.last-brief.md` 的存在或改动而拒绝提交。
- **新项目接入后要被忽略。** 在一个全新项目上跑完 `init`,
  该项目的 `.gitignore` 里要有这个文件。
- **不参与任何协议判定。** 没有哪条检查可以读它的内容。
- **不改变 `status` 已有的标准输出和退出码。**

> 前两条不是可有可无的:这个文件落在 `.pair/` 下,而 `.pair` 是冻结路径。
> 不处理的话,写出来的第一份简报会让下一次 `handoff` 判越界,而且 agent
> 删不干净——下一次 `status` 又会生成。同类的坑在 `.pair/.last-full-test.log`
> 上真实发生过一次。**怎么解决是实现的事,契约只要求结果。**
