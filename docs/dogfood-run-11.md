## 唯一的一次人类介入:dev 拒绝推进

dev 的第一个回合**只做了只读的事就停下来问人**:样板 `CLAUDE.md` 写着"不要用 subagent 代跑结对回合,
必须由主会话执行 `status` 和 `handoff`",编排者又让它"以这个目录的 `CLAUDE.md` 为准",而下一步
`verify-setup` 会改状态文件并提交。

这条规矩一直在。第九轮两个会话都指出了冲突,但都照做了;**这是它第一次真的挡住实验**。
人类裁决澄清:"你本身就是 dev 这个角色唯一的会话,不是被别的会话转手的,那条规矩不适用于你。"

它守规矩守得对,错在措辞:那条规矩防的是"某一方把自己的回合转手给别的 agent",
而措辞没区分"转手"与"本身就是那个角色唯一的会话"。一个严格守规矩的会话会被它挡住。

## 两个会话在这一轮里的做法

- **拿换了算法的参考实现做差分**:tester 审 W1 时另写一份"先把 `-`/`_` 换成空格再 `str.split()`"的实现,
  全部码位 × 三种上下文加 20 万条随机串,与 dev 的实现零差异,顺带证实了 dev 注释里
  "逐字符判空白与 `str.split()` 同一标准"的说法。
- **变异测试**:dev 审 W1 试了 10 种错误写法、W2 试了 11 种、W3 试了 11 种;W3 漏掉的那一种
  ("小写之后再做一次 NFC")给出等价证明 —— 只有 `İ` 小写后变两个字符,而 `i`+U+0307 没有预组合形式。
- **W4 在认领前就已经做完了**。dev 在 W1 就把三分类提成了 `classify_char` —— 第九轮的 dev 在同一处
  **刻意没做**,理由正是"提前做掉会让 W4 空转"。这一轮 dev 到 W3 的评审里才主动点明这件事;
  到 W4 它**没有硬造改动**,明说验收标准已满足,只修了一处真实隐患:三种类别原来是字符串常量、
  调用方用 `is` 比较,靠的是字符串恰好是同一个对象,前提不成立时字符会被静默丢掉 —— 换成 `enum.Enum`。
  新旧两版逐码位比对返回值、异常类型与异常消息,零差异。
- **不把没跑成的检查当成跑过**:dev 的考古记录写着"grep 过删掉的三个常量没人用",
  它自报交接时那条 grep 其实报错没跑成,交接后重跑确认干净,才说这句话成立。
- **用量中断没有造成混乱**:dev 在 W2 的 review-test 中途撞上 HTTP 429。重发的提示到达时,
  它先跑 `status` 确认自己还在同一回合,接着做完,没有重复交接。

## 运行中暴露的、待立项的问题

1. **样板 `CLAUDE.md` 那条"不要用 subagent 代跑结对回合"的措辞**没区分"把回合转手给别的 agent"
   与"本身就是那个角色唯一的会话",一个严格守规矩的会话会被它挡住。本轮唯一的人类介入就出在这里。
   `init` 写给真实项目的 `CLAUDE_MD` 是同一段文字。
2. **`verify-setup` 通过时打印"现在可以认领工作项了"**,而只有一方通过校验时,紧接着的 `claim`
   会被拒(W19 要求两边都作数)。这句提示在一半的情况下是错的 —— 与第五轮那类"会说错话的仪器"同一类。
3. **观察,暂不立项**:样板 PLAN 的 W4(把字符分类提成具名函数)很容易在 W1 被顺手做掉,
   让 refactor 项在认领前就满足验收标准。协议没有任何地方提示这件事;这一轮的 dev 处理得很好
   (不硬造改动),但那是会话自己的判断。
4. **观察,暂不立项**:评审记录只能追加,dev 自报一两处行号笔误因此无法就地更正。
   这是第六轮 W18 按设计的代价,记下它的存在。
