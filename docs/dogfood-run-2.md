# 第二次真实运行:收尾 P1-4 的 W2/W3

> 2026-09。工作项是 [improvements.md](improvements.md) 的 P1-4 剩下的两块 ——
> 第一次运行只做完三块里的第一块。**这一轮要量的不是打回率,是交付吞吐:
> 两个 agent 靠这套协议把 PLAN 走完要几个回合。**

## 结论先说

**PLAN 走完了**,两个工作项双向通过,门禁套件全绿,一次都没撞死锁闸。
打回率 31%,落在健康区间里,而且双向都发生过。

但**20 次交接里有 8 次没有推进交付** —— 它们消耗在协议自己的机制上。
这一轮最值钱的产出不是那两个功能,是把这 8 次的成因查清楚了:
**四条发现指向同一个根因,而它不是"文档只许人类改"。**

## 数字

| 指标 | 值 | 说明 |
|---|---|---|
| 完成工作项 | 2 / 2 | W2 记忆段落、W3 降级与忽略 |
| 交接提交 | 20(不含 claim 与 verify-setup) | 每项 10 次 |
| **净推进交付的回合** | **12 / 20** | 见下面的拆分 |
| 打回率 | **31%(4/13)** | `ok`。双向:各打回对方 2 次 |
| 死锁 | 0%(0/3) | 一次都没撞 |
| 决策条目 / 完成项 | **11 / 2** | 与"产出主要是结论"一致 |
| `--no-decision` | 0%(0/2) | 两次晋升 gate 都真的晋升了 |

### 那 8 次去哪了

| 类型 | 次数 | 说明 |
|---|---|---|
| 跨边界常量挡住 impl | 6 | 每个工作项 3 次:dev 异议 → tester 改常量 → dev 重新交接 |
| 空转的 impl 回合 | 4 | 打回理由纯粹是覆盖不足时,序列强制绕经 dev 一趟,而它无事可做 |

(两类有重叠,去重后是 8 次。)

**`report` 把「每工作项回合数 10.0」判成"偏高"并提示"工作项切太大"——
判错了。** 工作项切得没问题,10 里有 4 次是协议机制的开销。
这个指标分不出这两者,和第一次运行记下的观察是同一条,而那条观察
**至今没有进过路线图**。

## 四条发现,同一个根因

| 发现 | 谁找到的 |
|---|---|
| 行号绊线跨越角色边界:`CITED_LINE_COUNTS` 锚着 `pair.py` 的行数,而它在 tester 的独占路径 | dev(W2 异议) |
| **33 个孤儿路径 vs 6 个冻结路径**;本轮三次卡顿全出自孤儿 | **tester 实算** |
| 协议强制 dev 跑的验证命令,产出落在 tester 的独占路径 | dev(交接时撞到) |
| 验证命令的副作用落在谁的路径是随机的,两个方向都会卡住对方 | tester |

**第二条把前一条的诊断纠正了。** dev 把它归成"角色边界太严",提的修法都
对着绊线本身。tester 按 `.pair/config.json` 的 roles 对 `git ls-files`
实算了一遍:刻意冻结的只有 6 个(PLAN、CONTRACT、`.pair/*`、`.claude`),
而**不属于任何角色、也没被冻结的"孤儿"有 33 个** —— `README.md`、
`INSTALL.md`、`pyproject.toml`、`cli/`、整个 `examples/`。

本轮三次卡顿(`INSTALL.md` 行号、`examples/.gitignore`、`improvements.md`
行号)**全部出自孤儿,一次都不出自冻结**。

**症结不是"文档只许人类改",是 roles 配置压根没覆盖全仓,而缺口只在第 N 个
回合突然发作。** 修法完全不同:改绊线治不了 `examples/`,补 roles 才治得了。

## 两次打回都不是红绿发现的（第二次验证）

第一次运行最值钱的结论是"两次打回都不是红绿发现的"。这一轮**又是如此**,
而且两次都是同一种手法:**把实现改坏,看有没有测试会红**。

- **dev → tester(W2)**:契约「`status` 提前收尾时简报同样没有记忆段落」
  零测试。拿掉 `all_done` 守卫,**279 条全绿**。
- **dev → tester(W3)**:契约点名警告落在**标准输出**,而两条用例用的是
  `Result.text`(= `out + err`,`harness.py:189`)。把 `print` 换成
  `sys.stderr.write`,**284 条全绿**。

第二条的根因值得单独记:**脚手架的默认取值抹掉了契约要区分的维度。**
`.text` 用起来最顺手,于是所有人默认用它,而任何"这句话打到哪条流"的契约
条款都会自动失去防护。

这是 [ADR-018](design-decisions.md#adr-018-评审证据优先于用例级红绿第一次真实运行的实测结论)
的第三、第四个样本 —— 用例级红绿(P0-1)对"契约条款没有测试守着"这一类
**天然失明**,而它是两轮真实运行里全部四次打回的共同形状。

## 定性观察

脚本强制不出来、但真实发生了的:

- **tester 两次做了超出打回要求的事,两次都是对的。** W2 里 dev 只要求
  "拿掉守卫得有测试变红",它按五步纪律自己补了变异点;W3 里 dev 只要求
  `.text` → `.out`,它自己加了 `bad.err == ok.err` —— 而**后者才是第二种
  流错误("两条流都写")的唯一抓手**,dev 打回时没想到。
- **双方都拒绝过"为了过检查而凑数"。** dev 一度想拿
  `"=" * 52` 是实现常量当第二条打回理由,自己验完发现"分隔线变宽不影响
  (52 是 60 的子串)",判定边际风险、不拿它凑数,只记进 `--uncovered`。
- **dev 提出的修法被 tester 判定超出范围、写进「已否决」,dev 接受。**
  两次都是同一句:范围要不要扩大是人类的决定。
- **最后一刻的抢救。** W3 终审时 dev 发现"截断路径零测试"这条 W2 遗留
  **既不在决策记录、也不在 improvements**,只活在两份马上要作废的笔记和
  一次聊天报告里 —— 而协议下一步就停转。它用完成时的晋升 gate 把这条
  写进了决策记录。**报告不落文件就活不过这一轮**,这是记忆层设计的现场验证。
- **协议拦过自己人一次。** dev 交异议时被自己几天前加的「异议必含三小节」
  拒了一次:`## 哪条用例` 后面紧跟 `###` 子标题,正文是空的,不满足每节
  40 字。

## 还欠着什么

**仍然是一次两边都独立的运行。** 这一轮 dev 是协议起草者本人 ——
它起草了本轮的 PLAN 与 CONTRACT,也写了本轮用到的 `--drafter`、定位绊线、
文档形状检查。第一次运行作废的理由(dev 是起草者)**这一轮同样成立**。

"两个都没参与设计的 agent 会以什么频率互相打回" —— **两轮下来,零样本。**
它仍然是这个项目最大的未知。

## 这一轮之后该做什么

按发现的成本排:

1. **补 roles 配置的覆盖面。** 33 个孤儿是本轮 8 次损耗里 6 次的直接成因,
   而且它每个 impl 回合都会重演。四条决策记录都指向它。
2. **`report` 要能分开"推进交付的回合"与"协议开销的回合"。**
   现在「每工作项回合数」把两者混在一个分母里,还会因此给出错误的诊断
   ("工作项切太大")。第一次运行就记过这条观察,一直没进路线图。
3. **P1-6(空转的 impl 回合)现在有 5 个样本了**,第一次运行时只有 1 个,
   当时的判断是"加判定的代价是确定的,收益是猜的,等它再出现两次再说"。
   条件已经满足。
