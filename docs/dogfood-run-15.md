## 人类介入:`.DS_Store` 挡住了 tester 的第一次交接

生成项目之后、tester 提交开工前校验之前,有人用 Finder 浏览了这个目录,macOS 在根目录与 `docs/` 下写了两个 `.DS_Store`。
它们没纳入 git、不属于任何角色,tester 在 W1 的第一次 `handoff` 被写权限边界拒绝;拒绝文案让它问人类、不要删,
而能挡住它们的 `.gitignore` 是冻结路径。它照规矩停下。

**这是协议的真缺陷**:本仓库自己的 `.gitignore` 忽略 `.DS_Store`,但 `init` 写给新项目的 `GITIGNORE_LINES`
与样板的 `.gitignore` 都没有这一行。在 macOS 上,只要有人用 Finder 看过项目目录,第一次交接就可能这样被卡住,
而拒绝文案只让人去找人类,新用户不知道这个文件是什么。人类裁决以人类身份在 run15 的 `.gitignore` 加一行并提交,
tester 用原来那条命令重新交接,一次通过。

## 第十四轮修复带出的两处连带问题

两处都出在第十四轮写进样板契约的组合符规则,也都被两个会话自己接住了,没有要人类介入:

- **W4 的措辞与新规则有张力**。样板 PLAN 的 W4 写"每个字符归为保留 / 分隔 / 丢弃的判定提成一个具名函数",
  而新规则里组合符留不留要看前一个字符,只看单个字符判断不了。dev 在开工前校验里第一个点出,W1 完成时写进决策记录;
  tester 认领 W4 时从决策记录读到,提前说明评审要看什么;dev 在 W4 把"前一个字符是否保留"作为参数传入,
  三类的说法照样成立。**决策记录跨了三个工作项被接住。** 但这是我改契约时没同步检查 PLAN 措辞留下的。
- **契约自带的例子测不出"结果不再做一次 NFC"**。这条是我写进去的,只给了 U+0958 一个例子,
  而它的结果恰好是 NFC 不动点。tester 照着写 W3 的测试,dev 用"算完再 NFC 一次"的错误版本打,31 条 slugify 用例 0 条红 ——
  **这一轮唯一的打回**。能区分的输入很窄:dev 找到 10 个大写希腊字母带变音的例子;tester 修的时候扩到 6 个变音符号,
  找到 21 个,其中有纯拉丁的 `T` + 分音符。新用例每个例子自带两条前提断言(输入已是 NFC、期望值再 NFC 会变),
  换了 Unicode 版本、例子不再成立时会变红,而不是悄悄恒绿。

## 两个会话的做法

- **W1 留下的缺口在 W3 被补上**:dev 审 W1 测试时写明"整串一次性小写、不做 NFC、组合符一律保留"三个错误版本抓不住、要 W3 补;
  tester 的 W3 测试抓住了这三个。
- **评审刻意用对方没用过的输入**:tester 审 W4 时特意换了上下文与随机串的构成(三个连续组合符、私用区、未分配码位),
  不重复 dev 的比对。W4 前后两版在约 780 万个输入上零差异。
- **测试文件 0 个非 ASCII 字符**:W3 的测试连中文注释都没有,特殊字符全部 `chr(0x...)`,对 NFC 是不动点。

## 运行中暴露的、待立项的问题

1. **`GITIGNORE_LINES` 与样板 `.gitignore` 不忽略 `.DS_Store` 这类系统垃圾文件**,macOS 用户的第一次交接可能被卡住。
   同类的还有 `Thumbs.db`、`desktop.ini`。另外写权限边界拒绝这类文件时,文案只说"问人类",可以直接点名"这是操作系统写的,
   加进 `.gitignore`"。
2. **样板契约与 PLAN 跟新组合符规则没对齐**:W4 的措辞"每个字符归为……"要改成允许带上前一个字符的状态;
   "结果不再做一次 NFC"要换成真能区分的例子(`T` + U+0308)。两处都是第十四轮我改契约时留下的。
3. **`mutation_check` 不核对抓手与变异是否相关**(第十四轮 W30 的评审里记下的,本轮报告一并登记)。
