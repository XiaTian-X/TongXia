**主题:文档改动的授权与留痕。** 五个工作项(W10 裁判副本同步、W7 补第三轮的
测试欠账、W8 `--doc-reason`、W9 承重文件带声明才放行、W11 标题改写),
**40 次交接、6 次打回、347 条全绿收尾**。

和前三轮一样,`dev` 由本会话扮演,`tester` 是另一个会话,共用一个工作目录,

## 一句话:六次打回,没有一次是红绿发现的

| 怎么发现的 | 次数 |
|---|---|
| **变异**(把实现改坏,看有没有测试会红) | 4 |
| **读代码**(对照同一份文件里的既有写法) | 2 |
| 红绿 | **0** |

四轮累计:13 次打回,红绿贡献 1 次。

**红绿在这个项目里的角色已经很清楚了:它是回合调度的信号,不是发现问题的
手段。** 发现问题的是变异,而这一轮把这句话推得更远 ——
**六次打回里有五次,被打回的东西本身是绿的。**

## 这一轮的形状:判据比它声称守的性质更窄或更宽

同一个失效模式在五个不同的地方出现,每次表面都不一样:

| 哪里 | 判据 | 为什么不成立 |
|---|---|---|
| W10 重钉记录 | `sha[:7] in body` | sha 未 strip 时正文断成两行,而 sha 仍完整 |
| W10 我提的改法 | "一行里同时含路径与完整 sha" | **同样恒真** —— 被挤到下一行的是右括号 |
| W8 文档理由 | `--doc-reason ""` 被拒 | 一个空格就绕过去 |
| W9 契约变更频率 | "那一行前后不同" | 分母是完成项数,跑第二个工作项本身就让它变 |
| W11 标题检查 | `HEAD_LINES = 3` | 导语写长之后,18 行里 15 行在窗口外 |

**第二行是这一轮最值得记的一条。** 我打回 tester 的判据太松,给了一个
"更结构化"的改法 —— 而 tester 实测之后告诉我:**我给的改法同样恒真**。
真正咬得住的是它自己想出来的"正文里不该有只剩标点的残行"。

我以为"从措辞判据换成结构判据"就够了。**结构也分强弱,而分强弱的办法
仍然只有变异。** 这一条我和 tester 各犯了一次。

## 裁判已经漂了一整轮，而没有任何东西会红

开工前 tester 实测:`.pair/enforcer.py` 与 `pair.py` **差 122 行**。
第三轮 W4 交付的整节孤儿清单**在裁判里根本不存在** ——
也就是说,那一整轮的每一次 `handoff` 都不在它以为的规则下运行。

**没人发现,因为少一条警告不会让任何东西变红。**

更硬的一档也已经就位:W8/W9 要给 `handoff` 加旗标,而旧裁判对
`--contract-change` 直接 `unrecognized arguments` —— 两条验收标准
无人能执行。

**注册表比对挡不住它。** 实算:漂移那一刻 `ENFORCEMENTS` 与
`HANDOFF_INVARIANTS` 两边**差集都是空的**,而文件差 122 行。
拿它当护栏是恒真的 —— 它长得像检测器。

W10 因此把不变量定成**逐字节相等**,例外窗口是一个工作项:`claim` 校验、
`DONE` 且全绿时自动重钉。而它的第一次真实端到端验证来自计划没预料到的
一条路径:人类在工作项进行中就手工重钉过一次,于是 W10 自己的 `DONE`
走的是自动路径。

**一个连带的实证:** 人类 `cp` 之后没有提交,改过的冻结路径留在工作区,
下一个回合 tester 被自己的冻结判定拦住,而拒绝文案让它"撤销这些改动"——
撤销就把重钉撤掉。**契约里写下的那个"没有出路"场景,第一次真的发生了**,
只是发生在手工那条路上。

## 一个流程结构问题:tester 补测试的机会完全由 dev 决定

实算 `feature` 流程:tester **唯一可写的阶段是 `spec`**(`review-impl` 是
只读评审)。而回到 `spec` 的边只有两条 —— `('impl', 'changes')` 与
`('review-test', 'changes')` —— **两条都由 dev 发起**。tester 自己那次打回
去的是 `impl`,是 dev 的回合。

这和五步纪律的第 3 步(补变异点)撞在一起:变异锚点是 `pair.py` 的字面源码,
实现没落地时任何锚点都失配,**而实现落地后 tester 已经没有可写回合了**。

W8 那一轮它之所以补上了,是因为 dev 为**别的两条缺口**打了回。
**那是运气,不是机制。**

**tester 想出了第三条路,而且比原来两条都好:** 在 `spec` 回合就把锚点按
"实现应该长什么样"写下来,让 `test_变异点仍能匹配到源码` 红着交给 dev,
并写明"要换写法就打回我、并给出你实际用的片段"。
**把一个时序死结变成了一次普通的规格协商。**

前提是那个片段本身有依据 —— W8 那次用的是同一份文件里既有的判空写法,
逐字一致。分支形状自由度大时用它就是越界,W9 因此改回了原来两条。

## 「只认本回合新追加」：三次实测发作，最后一次挡着整轮收尾

`contract-change-note` 与笔记晋升闸都用 `new_decision_entries`
(按偏移量算"这一次交接里新写的")。于是:

1. W9 的 spec 回合留了决策,走到 `DONE` 又被拦
2. W9 的 `approve`,笔记已在上一个 impl 回合沉淀,晋升闸照样拦
3. **W11 的 `approve`,`contract-change-note` 再次拦下 —— 而这次它挡着
   第四轮收尾**

第三次的性质变了:它不只是噪音,**它能让一轮结不了尾**,除非有人写一条
"为了过闸"的条目。而决策记录是每次 `status` 都注入给两个 agent 的长期资产,
掺水的代价由此后每一个回合承担。

两条强制要问的都是"**本工作项有没有被沉淀过**",实际问的却是
"这一回合有没有新写"。

## 净回合:40 次交接里 4 次是空转的 impl

| | 次数 |
|---|---|
| 交接回合 | 40(spec 10 / impl 10 / review 20) |
| 其中打回 | 6(占评审回合 30%) |
| **空转的 impl 回合** | **4 / 10** |

四次全是同一个形状:**打回只动了测试,修完之后实现无事可做**,
但协议仍然要求 dev 走一个完整的 impl 回合才能进评审。

P1-6(空转的 impl 回合)的样本累计到 **11 个**,分布在四轮里。

**但"空转"这个词要小心:** 那四次里有三次最后并不空 —— 迁移把文档写陈旧了、
契约里的数字过期了、我上一回合声称写了却没写的决策记录。
真正的判据只能是"这一回合有没有东西要写",不是"打回动了哪一侧"。

## 我这一轮犯的两个错，都被 tester 抓到

**① 我三次声称"已进决策记录",而 `DECISIONS.md` 里一条都没有。**
tester 把出现位置逐处数出来给我看,并且**没有替我搬过去** ——
理由是"那三条是你的判断"。

难看的地方在于:**"写下『已经登记了』比不写更坏,读的人会以为有人在跟进"
这句话是我自己在开工前审查里写下的**,当时挑的正是契约里一句假的
"已登记进路线图"。同一个错,隔了几个工作项自己犯了一遍。

之后我改了做法:**写下"已在 DECISIONS.md"之前先跑一次 `grep` 逐条核实。**

**② 我把阶段读成了 review-test,按评审写了文件还跑了 `approve`。**
协议当场拦下("approve 只用于评审阶段,当前是 impl 阶段")。
这一轮它拦我三次,三次都是我自己没注意到的错位。

## 四轮下来仍然欠着的

**一次两边都独立的运行。**

这一轮 `dev` 仍然是本会话,而本会话起草了第四轮的 PLAN 与契约、
在人类授权下修订过三次、还代笔定稿了开工前审查挖出的那九处歧义。
第一轮作废的理由这一轮同样成立。

四轮下来**零样本**。

不过这一轮出现了三轮以来最接近独立的证据:**tester 有三次推翻了我的提议
而且推翻得对** —— 我给的判据同样恒真(W10)、我建议的变异锚点实测不红(W9)、
我要求它别做的那条它照做了并把理由写进 docstring(W8)。
反过来我也否掉了它一次(W11 建议我顺手划掉一条死代码验收标准 —— 那正好是
W9 弱版本防不住的形状:"两个 agent 都觉得它没用,于是把它去掉了")。

**双向的、带证据的、被对方接受的推翻,这一轮有四次。** 那不是独立运行,
但它是四轮以来"两个 agent 真的在互相约束"最硬的证据。
