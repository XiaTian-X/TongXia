## slugify

- 依据: 人类定稿

### `slugify(text: str) -> str`

**导入** `from src import slugify`(公开函数从 `src` 包顶层导出)。

**行为** 把任意文本转成适合放进 URL 的 slug。

**参数约束**

| 参数 | 类型 | 约束 |
|---|---|---|
| `text` | `str` | 至少含一个字母或数字(本契约里"字母或数字"一律按 `str.isalnum()` 判定) |

**返回** 由字母、数字(按 Python 的 `str.isalnum()` 判定)、保留下来的组合符和 `-` 组成的字符串;字母按 `str.lower()` 小写化。
**组合符**(`unicodedata.category` 以 `M` 开头的字符,`isalnum()` 为假):NFC 之后**紧跟在一个保留字符后面**的一起保留,
连续几个都保留;不跟在保留字符后面的(在开头、在分隔符或被丢弃的字符之后)丢弃。小写化带出的组合字符(`"İ"`)同样保留。
**输入全是 ASCII 时,结果只含 `a-z`、`0-9` 和 `-`。** 不以 `-` 开头或结尾;不含连续的 `-`。

**错误**

| 条件 | 抛出 |
|---|---|
| `text` 不是 `str` | `TypeError` |
| 丢掉标点与符号之后没有任何 `str.isalnum()` 为真的字符(空串、纯空白、`"!!!"`)—— slug 不能为空 | `ValueError` |

**边界情况**
- **处理之前先做 Unicode NFC 规范化**:重音分开写(`"Cafe\u0301"`)与合在一起写(`"Caf\u00e9"`)得到同一个 slug `"café"`。
  只做 NFC,不做 NFKC —— `"x²"`、全角字母、`½` 原样保留
- **`½` 算数字**:`'½'.isdigit()` 为假,但 `'½'.isalnum()` 为真,本契约只认后者 ——
  `slugify("½")` 是 `"½"`,不抛 `ValueError`
- 空白按 Python 的 `str.split()` 判定(含不换行空格等 Unicode 空白);连续空白折叠成单个 `-`
- `-` 与 `_` 视同空白,作分隔符:`"hello-world"`、`"hello_world"` → `"hello-world"`;`"a - b"` → `"a-b"`
- 其余非字母数字字符(标点、符号,包括 Unicode 里的各种连字符)直接丢弃,不转成 `-`;组合符按「返回」里那条规则
- **NFC 拆出来的组合符跟着它的字母走**:U+0958(天城文 qa)是 NFC 的组合排除字符,NFC 把它拆成 U+0915 加 nukta(U+093C),
  `slugify("\u0958")` 是 `"\u0915\u093c"`(例子里的码位一律写成转义:这个字符在任何会做规范化的编辑器里都会被悄悄拆开)。没有预组合形式的也一样:`slugify("q\u0301")` 是 `"q\u0301"`。
  不跟在保留字符后面的组合符丢弃:`slugify("\u0301a")` 是 `"a"`,`slugify("a-\u0301b")` 是 `"a-b"`。
  理由:按"其余一律丢弃",U+0958 会变成另一个字母 U+0915 —— 那不是少了装饰,是改了字
- **结果不再做一次 NFC**:NFC 只在处理之前做一次,组合符规则与小写化都作用在它之后,算完就是结果。
  看得出区别的只有一窄类 —— 大写字母加一个变音,大写没有合成形式、小写有:
  `slugify("T\u0308")` 是 `"t\u0308"`(再做一次 NFC 会变成 U+1E97),
  `slugify("\u03aa\u0301")` 是 `"\u03ca\u0301"`(会变成 U+0390)。
  上面 U+0958 那个例子的结果本身就是 NFC,说明不了这一条
- 非 ASCII 的字母与数字原样保留并按 `str.lower()` 小写化:`"Café"` → `"café"`。
- **小写化逐个字符做,不对整串调用 `str.lower()`**:希腊词尾 Σ 因此得到 `σ` 而不是 `ς`,
  `slugify("ΟΔΟΣ")` 是 `"οδοσ"`。每个字符的结果只取决于它自己,不取决于它前后有什么
- **顺序:先按原字符判定保留还是丢弃,再小写化。** 所以小写化带出的组合字符照样保留:
  `"İ"` 的小写是 `i` 加 U+0307,`slugify("İ")` 是 `"i\u0307"`。先小写再过滤的实现会把 U+0307 丢掉,不符合本契约

## truncate

- 依据: 人类定稿

### `truncate(text: str, n: int) -> str`

**导入** `from src import truncate`。

**行为** 若 `text` 长度超过 `n`,截断并以 `…`(U+2026)结尾。

**参数约束**

| 参数 | 类型 | 约束 |
|---|---|---|
| `text` | `str` | 可为空串 |
| `n` | `int` | `>= 1`;`bool` 是 `int` 的子类,照 `int` 接受(`True` 即 1) |

**返回** 长度不超过 `n` 的字符串。省略号**计入**长度:需要截断时,结果是**正好前 `n-1` 个**原文字符
(按 Python 的 `len()` 计)加一个 `…`,不退到单词边界、不去掉末尾空白。`n=5` 时是 4 个原文字符加 `…`。

**错误**

| 条件 | 抛出 |
|---|---|
| `text` 不是 `str` 或 `n` 不是 `int` | `TypeError` |
| `n < 1` | `ValueError` |

**先查类型,再查取值**:`truncate(123, 0)` 抛 `TypeError`,`truncate("", 0)` 抛 `ValueError`。

**边界情况**
- `len(text) == n` 时原样返回,不加省略号
- 空串原样返回
